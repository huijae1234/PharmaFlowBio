## 2. 장별 핵심 한 문장과 발표 메모
각 장의 "현재 작성·근거·부족·교체·채우는 작업"은 [checklist.md](checklist.md) 3절에도 있다. 말은 계획이고 실제 대본이 아니다.

**s00 표지 (10초)** — 우리는 가상 백신 제조사의 QA 관리자를 돕는 앱을 만들었다. 모든 자료는 교육용 가상 자료다.

**s01 서비스 소개와 문제 (55초)** — *핵심: QA 관리자는 출하 서명 직전에 흩어진 기록을 맞추느라 시간을 쓰고, 열린 건을 늦게 안다.* 누가·언제·손해·지금의 대안을 한 장씩. 손해 숫자(15분~3~4시간, 연 1~3회)는 AI 페르소나 설정값이라 "가정"이라고 반드시 말한다.

**s02 인터뷰 (60초)** — *핵심: 두 명 이상이 반복한 불편만 문제 정의에 썼다.* 인용 3개를 그대로 읽는다. AI 역할극 인터뷰이며 실제 현업 인터뷰가 아니라고 먼저 말한다.

**s03 리서치와 변화 (45초)** — *핵심: 인터뷰가 우리 가설을 고쳤다.* 출처·날짜 있는 숫자 두 개, "30분 → 15분~3~4시간", "이탈 전달 누락은 근거 없음".

**s04 업무 흐름 (50초)** — *핵심: 요청(시험값 저장)에 앱이 반응(이슈·보류·알림)하고 사람이 승인해야 닫힌다.* 여섯 단계를 왼쪽에서 오른쪽으로. 모든 단계는 업무 이력에 자동으로 남고 고칠 수 없다. 직접 입력 데이터와 가상 자료 종류를 한 줄로. 쌓인 건수는 캡처 전에는 말하지 않는다.

**s05 API (55초)** — *핵심: 공개 자료는 서버 함수가 받아 출처·시각과 함께 보여 준다.* 네 개. 네 개 모두 실제 키로 확인했다(허가·회수·GMP는 배포 화면까지). 국가출하승인은 배포에서 한 번 실패해 "마지막 정상 조회"가 나온 기록이 있다고 그대로 말한다.

**s06 세 가지 상태 (50초)** — *핵심: "없음"과 "못 읽음"을 구분해야 거짓 안심을 막는다.* "읽음" 캡처는 실제 공공데이터(지씨플루주, 출처·조회 시각), 나머지 두 칸은 캡처 자리. 시험 모드 성공은 실제 API 성공이 아니다.

**s07 결합 규칙과 Claude (55초)** — *핵심: 숫자와 기준 비교는 코드, 정리는 Claude, 승인은 사람.* 판정·출하 막기는 규칙이고, Claude 칸(AI 도우미·아침 브리핑·출하 검토 요약·이슈 조사 준비)은 main에 들어왔다. 캡처의 검증 줄을 가리키며 "숫자·인용은 코드가 다시 검사하고, 판정은 하지 않는다"고 말한다. 022~024 AI 칸도 실제 호출로 확인했고, 그때 답이 길면 통째로 버리던 문제를 찾아 고쳤다고 말한다.

**s08 근거와 한계 (45초)** — *핵심: 한계를 먼저 말하는 것이 신뢰를 만든다.* "규격 80~125 · 관리기준 90~115 · v2" 예를 보여 주고, 알 수 없는 것을 읽는다.

**s09 정상 업무 시연 (150초)** — *핵심: 한 건이 처음부터 끝까지 가는 것을 직접 본다.*
| 순서 | 계정(역할) | 할 일 | 초 |
|---|---|---|---|
| 1 로그인 | QA 관리자 | 구글 로그인, 홈 "지금 할 일" | 20 |
| 2 조회 | QA 관리자 | 로트 목록 → 열린 이슈가 있는 로트 상세 | 25 |
| 3 신청 | QC | 조치 요청 등록(예: 재시험) | 35 |
| 4 승인 | QA 관리자 | 승인 대기에서 승인·담당자 배정 | 30 |
| 5 완료 | 배정된 담당자 → QA 관리자 | 결과 입력 → 이슈 종결 → 내부 출하 검토 | 40 |
이슈를 닫으려면 승인된 품질 영향 평가가 필요하므로 시연 로트는 평가 승인을 미리 해 둔다.
시연 자료는 `QA-1029-`로 시작하는 가상 로트만 쓴다(`qa-list` 브랜치의 docs/qa.md 4절, 이 브랜치에는 아직 없음). **주의:** 승인·배정 때 실제 슬랙 개인 메시지가 나갈 수 있다. 시연 전에 알림 대상을 확인한다. 배포 사이트가 main 최신인지 아직 확인하지 못했다.

**s10 위험·망가진·권한 (105초)** — *핵심: 막히는 것을 직접 보여 줘야 안전하다고 말할 수 있다.*
| 순서 | 시연 | 기대 | 초 |
|---|---|---|---|
| ① 위험 | 보관 온도 9.2℃ 입력(로트 QA-1029-B) | 규격 이탈 → 이슈 생성 → 로트 보류 | 35 |
| ② 망가진 | 로컬 시험 모드에서 깨진 공공데이터 응답 | "못 읽음" + 다시 시도(0건으로 보이지 않음) | 35 |
| ③ 권한 | 관리자 아닌 계정으로 관리 주소 직접 입력 | 막힘 | 35 |
②는 배포 사이트가 늘 실제 API를 쓰기 때문에 로컬 시험 모드(`PUBLIC_DATA_MODE=fixtures`)에서 한다. 현재 확인된 것은 로그인 없이 막히는 것까지이고 비관리자 계정으로 막히는 것은 확인하지 못했다.

**s11 데이터 구조와 권한 (40초)** — *핵심: 누가 무엇을 쓰는지 DB가 정한다.* 관계 그림, 가입 흐름, 역할 표. 17개 표 전체 구조도는 부록 A1.

**s12 확인한 것 (45초)** — *핵심: 확인한 것과 못 한 것을 같이 말한다.* 자동 시험 536/536, DB 시험 019·025·026 통과 기록, Claude QA 22·0·6(오후 실행, 28건), 팀 직접 QA 25/25(아침 브리핑 자동 발송은 10/30 08:01에 확인). 고친 오류 기록 9건 중 한 건(DN-01). 모의 응답 시험은 실제 API 시험이 아니다.
