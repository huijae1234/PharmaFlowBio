# PharmaFlow QA (docs/specs/NNN-기능/qa.md)

```
plan 승인 ─▶ A: QA 목록 등록 ─▶ [단계 끝마다] B: Claude QA + 기록 ─▶ [기능 끝] C: 전체 회귀 + 사람 QA 목록 ─▶ D: 사람 결과 기록
```
- **C 항목**: Claude가 직접 확인한다(함수 시험, DB 시험, 미리보기 화면, 코드 점검, 실제 호출).
- **H 항목**: 사람만 판단할 것 두 종류 — 판단(보기 좋은가, 현장 말과 맞나)과 핵심 여정 한 바퀴.

## 규칙
1. **증거 없이 통과로 적지 않는다.** 증거 = 시험 이름과 통과 개수, 명령 결과, DB 시험 문구, 확인한 화면 상태·캡처 파일.
2. 못 한 것은 `확인 못 함`과 이유. 실패를 고친 뒤에는 `실패 → 통과 (재확인 날짜)`로 쌓고 "실패와 조치" 표에 한 줄.
3. 모든 SC는 C나 H에 한 번 이상. spec 3절 경계·예외는 C 항목으로.
4. 표 줄은 머리 줄과 칸 수가 같다(C·H 모두 9칸). **글 안에 `|`를 쓸 때는 `\|`로.** 표를 스크립트로 고친 뒤에는 아래 점검을 반드시 돌린다.
5. 사람이 실패로 알린 것이 새 요구면 고치기 전에 spec을 고칠지 묻는다(`pharmaflow-spec`).

## 확인 방법 (PharmaFlow)
| 무엇 | 어떻게 | 증거로 적을 것 |
|---|---|---|
| 함수 시험 | `node --test "tests/*.test.js"` | 통과/전체 개수. 새 규칙은 시험을 먼저 써서 실패를 본 뒤 구현 |
| DB 시험 | `supabase/tests/NNN_rules.sql`을 Supabase SQL로 실행(끝에서 일부러 오류를 내 되돌림) | "PF_TEST 통과 N/N". 마이그레이션이 아직 적용 전이면 마이그레이션 + 시험을 한 번에 돌려 되돌린다. 실제 DB 적용은 승인 뒤 |
| 화면 | `.claude/launch.json`의 `pharmaflow` 미리보기(포트 5173). 고친 JS·CSS는 `fetch(파일, {cache: "reload"})`로 새로 받는다. `api/` 파일을 고쳤으면 서버를 다시 켠다 | 확인한 화면·문구, 375px·Tab 키, 필요하면 캡처 |
| 시험 모드 | 공공데이터 `PUBLIC_DATA_MODE=fixtures`, AI `AI_MODE=fixtures`, 브리핑 `BRIEFING_MODE=fixtures`(로컬만, Vercel에서는 꺼짐) | "시험 자료 성공은 실제 API 성공이 아님"을 함께 적는다 |
| 실제 Claude 호출 | 실제 키로 확인. **10번을 넘기면 먼저 비용 승인** | 모델 이름, 검증 결과(경고 수), 실패면 원문 |
| 코드 점검 | 단계 끝 `ponytail-review`(보고만), 커밋 전 `pharmaflow-review` | 지적 사항과 처리 |

사람 QA(H)는 역할별 계정으로 한다: QA 관리자 유○○, 생산 담당자 김희재, QC 시험 담당자 윤○○. Claude는 다른 역할로 로그인할 수 없으니 그 역할 화면은 `확인 못 함`으로 남기고 사람 QA로 넘긴다.

## 절차
- **A (plan 승인 직후)**: 아래 틀로 qa.md. C마다 확인할 plan 단계를 정하고, H는 초안. plan 4절 추적 표의 QA 번호 칸을 채운다.
- **B (단계 끝)**: 그 단계의 C를 확인하고 앞 단계도 회귀(함수 시험은 전체). 결과·증거·날짜를 적고 머리말 "요약: C 통과/전체"를 맞춘다. 사용자에게 통과/실패/확인 못 함 개수를 보고하고 다음 단계 승인을 받는다.
- **C (기능 끝)**: 모든 C 재확인, H를 실제 화면에 맞게 다듬어(준비·할 일·보고 판단할 것) 채팅으로 준다.
- **D (사람 결과)**: 사람이 말한 결과를 바꾸지 않고 적는다. 모두 통과면 상태 `완료`, Intent·README·CLAUDE.md의 시험 개수와 기능 범위를 같이 맞춘다. 직접 수행한 QA는 `docs/qa.md`와 QA List 시트에도.

## 점검
```bash
py -X utf8 .claude/skills/pharmaflow-qa/scripts/check_qa.py docs/specs/NNN-기능
```
- 문제(실패): 표 머리와 칸 수가 다른 줄, 증거 없이 통과로 적은 줄, qa.md에 없는 SC.
- 경고: 머리말 요약 숫자와 표가 다를 때.

- 요약: C {통과}/{전체} (확인 못 함 {n}), H {통과}/{전체}

## 1. Claude QA
| ID | 근거 | 단계 | 방법 | 할 일 | 기대 결과 | 결과 | 증거 | 확인일 |
|---|---|---|---|---|---|---|---|---|

## 2. 사람 QA
| ID | 종류 | 근거 | 준비 | 할 일 | 보고 판단할 것 | 결과 | 메모 | 확인일 |

## 3. 실패와 조치

|---|---|

## 이 스킬을 만든 이유 (원본과 바꾼 것)
- 원본: 개인 하네스 스킬 `harness-qa`(유○○ `~/.claude/skills`). 저장소에 없어서 팀원의 Claude는 같은 방식으로 QA를 적지 않았다(spec 021~024의 qa.md는 4칸 표).
- 이 프로젝트에서 되풀이된 것을 넣었다: 시험·DB 시험(PF_TEST)·미리보기 캐시·서버 다시 켜기·시험 모드·실제 AI 호출 비용, 역할별 계정.
- 표 점검 스크립트를 새로 만들었다. 2026-10-29에 표를 고치는 스크립트가 "기대 결과" 칸을 지운 일(qa 025 실패와 조치 7)과, 글 안의 `|` 때문에 표가 깨진 줄 5개(qa 005·009·010·011·018, 이 스킬을 처음 써서 찾아 고침)가 있었다.
