1. 한눈에 보기

백신 공장에서는 만든 묶음(로트)마다 품질 시험을 합니다. 시험 결과가 기준을 벗어나면 원인을 조사하고, 품질에 어떤 영향이 있는지 평가하고, 재시험 같은 조치를 하고, 품질 책임자(QA 관리자)가 검토·승인한 뒤에야 그 로트를 출하할지 정합니다.

PharmaFlow Bio는 이 과정을 한 곳에 모읍니다. 시험값을 넣는 순간 앱이 기준을 벗어났는지 판정하고, 벗어났으면 "품질 이슈"를 자동으로 엽니다. 그 이슈가 평가 → 검토 → 조치 → 종료 → 출하 검토까지 어디쯤 와 있는지, 누가 언제 무엇을 근거로 승인했는지 모두 기록되고 한 화면에서 보입니다.

목표: QA 관리자가 로트 하나의 상태를 확인하고 내부 출하 검토를 하는 데 걸리는 시간을 약 30분(여러 기록과 메일을 뒤짐)에서 1분 안으로 줄이는 것. (30분은 검증할 가설)
회사·로트·시험값·시험 규격·관리기준은 모두 교육용 가상 자료입니다. 식약처 허가정보와 회수·판매중지 정보만 실제 공개 자료를 불러와 씁니다. 이 앱의 판단은 회사 내부 검토이며 국가출하승인이 아닙니다.

2. 왜 만들었나

가상 백신 제조사를 가정하고, 품질 이탈이 생겼을 때 지금 어떻게 일하는지(As-Is)를 그려 보면 이렇습니다.

단계지금 방식 (As-Is)앱을 쓰면 (To-Be)
이탈 발견시험 담당자가 기록지에 적고 기준서와 눈으로 비교. 벗어나면 메일·전화로 QA에 알림 → 빠뜨리기 쉬움값을 넣는 순간 자동 판정, 품질 이슈 자동 생성, 규격 이탈이면 로트 자동 보류
영향 평가워드 양식에 측정값·기준을 옮겨 적고 메일로 첨부이슈 화면에서 작성. 로트·측정값·적용 기준은 자동으로 붙어 있음
승인메일함에서 요청서를 찾아 회신. 누가 언제 승인했는지 흩어짐"승인 대기" 한 화면에서 처리, 모든 결정이 이력으로 남음
출하 전 확인시험 기록·생산 기록·평가서·메일·엑셀을 따로 확인 (약 30분, 가장 불안한 순간)로트 상세 위쪽 요약만 보면 됨. 막히는 이유가 있으면 앱이 글로 알려 주고 출하를 막음

핵심 질문: "이탈 발생부터 출하 검토까지를 여러 기록을 뒤지지 않고 로트 하나 기준으로 추적하려면 어떻게 해야 하는가?"

3. 누가 쓰나

구글 계정으로 로그인합니다. 처음 들어온 사람은 열람자(읽기만 가능)가 되고, QA 관리자가 역할을 정해 줍니다. 역할마다 첫 화면과 할 수 있는 일이 다릅니다.

QA 관리자

첫 화면: 관리자 대시보드

핵심 사용자. 영향 평가와 조치 요청을 검토·승인하고, 시험 규격·관리기준을 정하고, 마지막에 로트의 내부 출하 검토(출하 가능 / 폐기)를 합니다. 사용자 역할 지정과 관리 메뉴도 이 역할만 씁니다.

QC 시험 담당자

첫 화면: 품질시험 홈

로트의 시험값(역가, 엔도톡신, pH 등)을 넣습니다. 이탈이 나면 영향 평가를 쓰고 조치를 요청하며, 배정받은 재시험의 결과를 넣습니다.

생산 담당자

첫 화면: 제조공정 홈

로트를 등록하고 공정 조건(배양 온도, 보관 온도, 설비 상태)을 넣습니다. 필요하면 사유를 적어 로트를 직접 보류합니다. 공정 이탈의 평가·조치도 씁니다.

열람자

첫 화면: 로트 목록

역할을 받기 전 상태. 모든 화면을 볼 수만 있고 버튼이 없습니다. 인허가·공급 담당자도 따로 역할을 만들지 않고 읽기 화면으로 정보를 봅니다.

4. 꼭 알아야 할 말

말뜻
로트같은 조건으로 한 번에 만든 제품 묶음. 품질 확인과 출하 결정의 단위. 예: VX-2610-002
시험 규격시험 항목마다 정해진 허용 범위. 벗어나면 그대로는 쓸 수 없음. 예: 역가 80~125%
사내 관리기준규격보다 좁게 잡은 회사 내부 경보 범위. 벗어나도 규격 안이지만 원인을 확인해야 함. 예: 역가 90~115%. 항목에 따라 없을 수도 있음
판정측정값을 기준과 비교한 결과. 정상 관리기준 이탈 규격 이탈 세 단계
기준 버전기준을 고칠 때마다 1씩 오르는 번호(v1, v2…). 측정값마다 "그때 어떤 기준(몇 번째 버전)으로 판정했는지"를 함께 남겨, 기준이 바뀌어도 예전 판정의 근거를 설명할 수 있음
품질 이슈이탈이 생기면 자동으로 열리는 처리 건. 종류는 규격 이탈 / 관리기준 이탈. 처리가 끝나면 닫힘
품질 영향 평가담당자가 이슈에 대해 이탈 내용·추정 원인·품질 영향·제안 후속 조치·근거를 적어 QA 검토를 받는 기록. 이슈 하나에 하나. 평가 승인은 "평가 내용을 받아들인다"는 뜻이지 사용·출하 승인이 아님
보완 요청 / 반려QA 관리자가 평가나 요청을 사유와 함께 되돌리는 것. 요청자가 고쳐 다시 제출할 수 있음
조치 요청이슈를 해결하려고 하는 일. 재시험, 설비 점검, 원료 확인, 로트 폐기 건의. QA가 승인하며 담당자를 배정
보류로트를 더 진행하지 못하게 멈춘 상태. 규격 이탈이면 자동, 또는 사유를 적어 직접
내부 출하 검토QA 관리자가 로트를 "출하 가능" 또는 "폐기"로 정하는 회사 내부 결정
국가출하승인백신을 시장에 내기 전 국가기관이 하는 별도 승인. 이 앱은 하지 않으며 흉내 내지도 않음
업무 이력누가 언제 무엇을 했는지(값을 넣음, 승인함 등) 자동으로 남는 기록. 화면에서도, 데이터베이스에서도 고치거나 지울 수 없음

5. 로트 하나의 이야기

가상 백신 A의 로트 VX-2610-002로 처음부터 끝까지 따라가 봅니다. 기준은 역가 시험 규격 80~125%, 사내 관리기준 90~115%라고 합시다.

  1. QC 시험 담당자 · 품질시험 홈 → 로트 상세 → 시험값 입력

    역가 항목을 고르면 입력 칸 아래에 "규격 80~125 % · 관리기준 90~115 % · v1 · 교육용 가상 기준"이 보입니다. 85%를 넣고 저장합니다.

  2. 앱이 자동으로

    85는 규격 안이지만 관리기준 밖이므로 관리기준 이탈로 판정합니다. 품질 이슈(종류: 관리기준 이탈)를 열고, 로트는 보류하지 않습니다. 만약 79%였다면 규격 이탈 → 이슈를 열고 로트를 자동 보류합니다. 어느 쪽이든 판정에 쓴 기준과 버전이 측정값과 함께 저장됩니다.

  3. QC 시험 담당자 · 품질 이슈 상세 → 품질 영향 평가 작성

    창 위쪽에 로트·발생 시각·측정값·적용 기준이 이미 채워져 있습니다. 이탈 내용, 추정 원인(예: 시료 보관 온도 편차), 품질 영향, 제안 후속 조치(예: 재시험), 근거(문서 번호)를 적어 검토 요청합니다.

  4. QA 관리자 · 관리자 대시보드 "승인 대기" → 품질 영향 평가 검토

    내용을 보고 승인, 반려, 보완 요청 중 하나를 고릅니다(반려·보완 요청은 사유 필수). 보완 요청을 하면 요청자의 첫 화면에 사유와 함께 뜨고, 요청자가 고쳐 다시 제출합니다. 승인 창에는 "사용·출하 승인이 아닙니다"가 늘 보입니다.

  5. 담당자 → QA 관리자 → 배정된 담당자

    필요하면 조치 요청(재시험)을 등록 → QA 관리자가 승인하며 담당자 배정 → 배정된 담당자가 재시험 결과를 넣습니다. 재시험도 세 단계로 판정되고, 또 이탈이어도 새 이슈를 만들지 않고 같은 이슈에 붙습니다. 관리기준 이탈이던 이슈가 재시험에서 규격 이탈로 나빠지면 이슈 종류가 규격 이탈로 바뀌고 로트가 보류됩니다.

  6. 배정됐던 담당자 또는 QA 관리자 · 이슈 닫기

    조건을 채우면 닫힙니다. 관리기준 이탈: 승인된 영향 평가. 규격 이탈: 승인된 영향 평가 + 완료된 조치. 못 닫으면 이유가 글로 보입니다. 마지막 규격 이탈 이슈가 닫히면 로트는 보류 → 시험 중으로 돌아갑니다.

  7. QA 관리자 · 로트 상세 → 내부 출하 검토

    위쪽 요약에서 열린 이슈 수, 평가 상태, 다음에 할 일, 최근 이력을 확인하고 "출하 가능" 또는 "폐기"를 정합니다. 열린 이슈가 하나라도 있거나 아직 시험이 끝나지 않은 항목이 있으면 "출하 가능"은 잠기고 이유가 표시됩니다. 창에는 "회사 내부 검토이며 국가출하승인이 아닙니다"가 보입니다.

이 모든 단계가 업무 이력에 자동으로 남아, 나중에 "누가 언제 무엇을 근거로 결정했는지"를 그대로 되짚을 수 있습니다.

6. 화면 안내

왼쪽 메뉴(휴대폰에서는 위쪽 "메뉴" 버튼)로 이동합니다. 관리 메뉴는 QA 관리자에게만 보입니다.

첫 화면

화면보이는 것
관리자 대시보드승인 대기(조치 요청 + 품질 영향 평가, 오래된 순), 되돌아온 내 요청, 내부 출하 검토 대기 로트(시험 중이고 열린 이슈 없음), 품질 지표(열린 이슈 수·이번 주 규격 이탈 수·평균 처리 일수), 로트 상태별 개수, 보류 로트, 최근 회수 공지(실제 공공데이터)
품질시험 홈나에게 배정된 조치, 보완 요청·반려된 내 요청, 시험값을 기다리는 로트, 최근 이탈(시험)
제조공정 홈나에게 배정된 조치, 보완 요청·반려된 내 요청, 생산 중 로트, 최근 이탈(공정)

로트

  • 로트 목록: 로트번호·제품·상태(생산 중 / 시험 중 / 보류 / 출하 가능 / 폐기). 상태로 거르기, 로트 등록.
  • 로트 상세: 위쪽 요약(열린 이슈 수를 종류별로, 영향 평가 상태, 조치 요청 상태, 다음에 할 일과 담당, 최근 이력 3줄). 버튼: 시험값 입력, 공정 조건 입력, 로트 보류, 내부 출하 검토. 탭: 공정 조건 / 시험 결과(측정값·판정·그때 기준과 버전) / 품질 이슈 / 업무 이력.

품질 이슈

  • 품질 이슈 목록: 로트번호, 발생 구분(시험·공정), 종류(규격 이탈·관리기준 이탈), 이탈 항목, 열림/닫힘. 상태·구분·종류로 거르기.
  • 품질 이슈 상세: 맨 위 단계 표시줄(이탈 → 영향 평가 → 조치 → 이슈 종료 → 내부 출하 검토, 지금 단계에 "지금" 표시)과 다음에 할 일. 아래로 이탈 내용(측정값과 그때 기준) → 품질 영향 평가(작성·검토·다시 제출) → 조치 요청(등록·승인·반려·결과 입력) → 이슈 닫기 → 재시험 결과 → 업무 이력.

제품

  • 제품 목록·등록: 식약처 허가정보를 품목명으로 검색해 골라 등록합니다(직접 입력 없음). "백신만" 거르기 추가 중.
  • 제품 상세 → 기준 탭: 시험 항목·공정 조건 항목마다 시험 규격, 사내 관리기준, 버전. QA 관리자만 수정. "교육용 가상 기준" 표시.
  • 제품 상세 → 허가정보·회수 이력 탭: 허가정보로 등록한 제품만. 허가일·업체·주성분·취소 여부, 같은 품목의 회수·판매중지 공지.

관리 (QA 관리자만)

  • 승인 대기: 조치 요청(승인·반려)과 품질 영향 평가 검토 대기.
  • 사용자·역할: 새로 들어온 사람에게 역할 지정.
  • 전체 업무 이력: 모든 로트의 이력을 사람·로트번호·기간으로 거르기.
  • 사용 기록: 로그인·화면 이동·검색·공공데이터 호출(성공 여부, 걸린 시간). 이메일 대신 사용자 ID만.
  • 예시 자료 되돌리기: 시연 전 자료를 가상 백신 예시 처음 상태로. "되돌리기"를 직접 입력해야 실행되고, 사용자·업무 이력은 지우지 않습니다.

MSDS: 원료·시약 안전정보는 산업안전보건공단 사이트로 연결합니다.

규칙내용
자동 보류규격 이탈만 로트를 보류. 관리기준 이탈은 이슈만 열고 보류하지 않음(불필요하게 출하를 막지 않도록)

기준 수정값을 바꿀 때만 버전 +1. 이미 넣은 측정값의 판정과 그때 기준은 바뀌지 않음

8. 실제 공공데이터 연결

식약처 공공데이터포털의 두 가지 실제 자료를 불러옵니다.

  • 의약품 제품 허가정보: 품목명으로 검색해 제품을 등록하고, 제품 상세에서 허가일·업체·주성분·취소 여부를 봅니다. 백신은 품목 구분이 "백신류"라 "백신만" 골라 찾을 수 있습니다.
  • 의약품 회수·판매중지: 등록 제품과 같은 품목의 회수 공지, 대시보드의 최근 회수 공지 5건.

공공데이터는 응답이 0.3초~15초 넘게 들쭉날쭉합니다. 그래서 칸마다 따로 불러오고, 실패하면 그 칸에만 안내와 "다시 시도" 버튼을 보여 줍니다(나머지 화면은 정상). 추가 중인 기능으로, 칸마다 "출처: 식약처 공공데이터 · 조회 시각"을 붙이고, 실패하면 이 기기에서 마지막으로 정상 조회한 결과와 그 시각을 함께 보여 줍니다.

공공데이터는 데이터베이스에 복사해 두지 않고, 허가정보를 로트 시험 규격이나 국가출하승인 정보로 쓰지 않습니다.

9. 어떻게 동작하나

화면 (브라우저)

HTML·CSS·JavaScript. 설치 없이 웹 주소로 엽니다. 휴대폰 폭에서도 씁니다.

데이터베이스·로그인 (Supabase)

로트·측정값·이슈·평가·이력을 저장. 구글 로그인. 판정·보류·닫기·출하 규칙과 권한을 여기서 강제합니다.

중간 함수 (Vercel, 서울)

식약처 API를 대신 부르는 작은 서버 함수. 인증키는 여기에만 있고 화면에는 나가지 않습니다.

식약처 공공데이터

허가정보, 회수·판매중지. 실시간 조회, 하루 10,000건 무료.

  • 중요한 규칙(판정, 자동 보류, 닫기 조건, 출하 막기, 권한)은 화면이 아니라 데이터베이스가 지킵니다. 화면을 우회해도 같은 규칙이 적용됩니다.
  • 모든 자료 변경은 데이터베이스가 자동으로 업무 이력에 남기고, 그 이력은 고칠 수 없습니다.
  • 비밀 값(인증키 등)은 코드나 저장소에 넣지 않습니다.

10. 하지 않는 것

  • 실제 회사·로트 자료 사용, 가상 기준을 실제 법정 규격처럼 보이게 하기
  • 규격 미달 로트를 버튼 하나로 특채 사용·출하 승인하기
  • 국가출하승인 판단, 공급사 자동 부적격 처리
  • 메일·메신저·푸시 알림, 결재 시스템 연동, 전자서명
  • 아이디·비밀번호 회원가입(구글 로그인만), 공공데이터 대량 복사
