## 1. 해결하려는 문제
**지금 방식:** 제품의 허가정보와 회수·판매중지 공지는 식약처 사이트를, 원료·시약의 안전정보는 산업안전보건공단 사이트를 따로 찾아본다. 취급 점검 내용은 종이나 엑셀에 남고, 누가 앱을 어떻게 썼는지는 남지 않는다. [문제정의 정한 범위 "공개 정보", "기록"] [PRD §2]
**막히는 지점:**
- 제품을 등록할 때 품목명·주성분·제조원을 손으로 옮겨 적어 틀리기 쉽다. [PRD FR-18]
- 우리 제품이 회수·판매중지 대상인지 출하 판단 전에 따로 확인해야 한다. [PRD FR-19]
- 공공데이터가 느리거나 실패하면 화면 전체가 멈출까 걱정된다. 실제로 응답이 0.5초에서 15초 넘게까지 들쭉날쭉하다. [UJ E4] [Intent Q14]
- 발표 시연 중에 자료가 섞이면 처음 상태로 되돌릴 방법이 없다. [PRD FR-24] [문제정의 정한 범위 "배포"]

## 2. 주요 사용자
- QA 관리자(제품 등록, 회수 확인, 사용 기록, 되돌리기), 모든 역할(물질 검색), QC 시험 담당자·생산 담당자(취급점검 기록). [IA 역할별로 쓸 수 있는 화면] [PRD §4]

### 이야기 1 — 허가정보로 제품을 등록하고 회수 이력을 본다 (P1)
QA 관리자가 품목명으로 허가정보를 검색해 고르면 품목명·주성분·제조원이 채워진 채 제품이 등록되고, 제품 상세에서 그 품목의 허가정보와 회수·판매중지 이력을 바로 본다. [PRD FR-18, FR-19] [IA PD_010100_MD, PD_010202_TB]
- 왜 P1: 청중이 실제 공공데이터를 눈으로 보는 발표의 핵심 장면이다. [Intent §2 발표 시연]
- 확인 방법: "타이레놀"로 검색 → 하나 골라 등록 → 제품 상세 허가정보·회수 이력 탭에 실제 값이 보인다.

### 이야기 2 — 공공데이터가 실패해도 일은 끝까지 된다 (P1)
공공데이터가 늦거나 실패해도 그 칸만 안내와 다시 시도 버튼을 보이고, 기준값·품질 이슈 같은 나머지 화면은 그대로 쓴다. [PRD FR-20] [UJ E4]
- 왜 P1: 응답이 들쭉날쭉해(Intent Q14) 발표 중에도 일어날 수 있다.
- 확인 방법: 인증키를 비운 서버로 제품 상세를 열면 허가정보 칸에만 안내가 뜨고 기준값 표는 보인다.

### 이야기 3 — 원료·시약을 찾아 취급점검을 기록한다 (P2)
담당자가 물질을 국문명이나 CAS 번호로 찾아 물질 상세를 열고, 공단 MSDS 상세로 넘어가 확인한 뒤, 점검 내용과 보호조치를 기록한다. [PRD FR-21, FR-22] [IA MS_010000_PG, MS_010100_PG, MS_010101_MD, MS_010102_LK]
- 확인 방법: "벤젠" 검색 → 물질 상세 → 취급점검 기록 작성 → 목록에 보인다.

### 이야기 4 — QA 관리자가 사용 기록을 본다 (P2)
QA 관리자가 누가 언제 로그인하고 어떤 화면을 열고 무엇을 검색했는지, 공공데이터 호출이 성공했는지와 걸린 시간을 본다. [PRD FR-23] [IA AD_040000_PG]

### 이야기 5 — 시연 전에 예시 자료로 되돌린다 (P2)
QA 관리자가 한 번 더 확인한 뒤 업무 자료를 처음 예시 상태로 되돌린다. 사용자·역할과 사용 기록은 그대로다. [PRD FR-24] [IA AD_050000_PU]

## 3. 핵심 기능과 요구사항
PRD 9절에 따라 Should는 FR 번호 순서로 만들고, 시간이 모자라면 뒤에서부터 뺀다. [PRD §9]

### FR-001 허가정보 검색으로 제품 등록 (P1, PD_010100_MD)
QA 관리자가 품목명으로 허가정보를 검색해 결과 하나를 고르면, 시스템은 품목명·주성분·제조원을 채워 제품을 등록해야 한다. [PRD FR-18]
- 수용 기준
  1. **전제** QA 관리자, 제품 목록 **행동** 제품 등록 → "타이레놀" 검색 **결과** 품목명·주성분·제조원이 보이는 결과 목록 (최대 10건)
  2. **전제** 결과 목록 **행동** 하나를 골라 등록 **결과** 제품 목록에 그 품목이 보이고, 업무 이력에 "제품 등록"이 남는다
  3. **전제** 검색 결과 0건 **행동** — **결과** "검색 결과가 없습니다. 품목명을 바꿔 다시 검색해 주세요."
  4. **전제** 이미 등록한 품목(같은 허가 품목) **행동** 다시 등록 **결과** 저장되지 않고 "이미 등록된 제품입니다."
  5. **전제** QA 관리자가 아닌 사람 **행동** — **결과** 제품 등록 버튼이 없고 저장 단계에서도 거부된다

### FR-002 제품 상세의 허가정보·회수 이력 (P1, PD_010202_TB)
시스템은 제품 상세에 그 품목의 허가정보와 회수·판매중지 이력을 공공데이터에서 바로 불러와 보여 줘야 한다. [PRD FR-19]
- 수용 기준
  1. **전제** 허가정보로 등록한 제품 **행동** 제품 상세 > 허가정보·회수 이력 탭 **결과** 허가일, 전문·일반 구분, 업체명, 취소 여부가 보인다
  2. **전제** 같은 품목의 회수·판매중지 공지가 있음 **행동** 같은 탭 **결과** 회수 사유, 회수 명령일, 제조번호가 최근순으로 보인다
  3. **전제** 공지가 없음 **행동** — **결과** "이 제품의 회수·판매중지 공지가 없습니다."
  4. **전제** 예시 제품처럼 허가정보로 등록하지 않은 제품 **행동** — **결과** "허가정보로 등록한 제품만 공공데이터를 볼 수 있습니다." (기준값 탭은 그대로)

### FR-003 관리자 대시보드의 최근 회수 공지 (P2, HM_010000_PG)
시스템은 관리자 대시보드에 최근 회수·판매중지 공지 5건을 보여 줘야 한다. [PRD FR-19] [IA HM_010000_PG "최근 회수 공지는 2차"]
- 수용 기준
  1. **전제** QA 관리자 **행동** 대시보드 **결과** 제품명, 업체명, 회수 사유, 회수 명령일 5건 (최근순)
  2. **전제** 불러오기 실패 **행동** — **결과** 그 칸에만 실패 안내 (FR-004), 승인 대기 등 나머지는 정상

### FR-004 공공데이터를 기다리고 실패를 견디기 (P1, PD_010100_MD, PD_010202_TB, MS_010000_PG, HM_010000_PG)
공공데이터를 부르는 칸마다, 시스템은 기다리는 동안 "불러오는 중"을 보이고, 실패하면 그 칸에만 안내와 다시 시도 버튼을 보이며, 인증키는 화면 코드와 응답 어디에도 드러내지 않아야 한다. [PRD FR-20] [UJ E4] [ADR 0001]
- 수용 기준
  1. **전제** 응답이 늦음 **행동** — **결과** 그 칸에 "허가정보를 불러오는 중…"이 보이고, 15초가 넘으면 실패로 본다 (Q14 가정)
  2. **전제** 실패(시간 초과·연결 실패·인증키 없음) **행동** — **결과** "허가정보를 불러오지 못했습니다. 잠시 뒤 다시 시도해 주세요."와 다시 시도 버튼. 같은 화면의 다른 칸은 정상
  3. **전제** 다시 시도 **행동** 버튼 **결과** 그 칸만 다시 부른다
  4. **전제** 아무 화면 **행동** 화면 코드·네트워크 응답을 본다 **결과** 공공데이터 인증키가 없다

### FR-005 물질 검색 (P2, MS_010000_PG) — **이번 범위에서 미룸 (Q24·D13, 2026-10-22)**
시스템은 모든 역할이 원료·시약을 국문명이나 CAS 번호로 검색해 물질명·CAS 번호 목록을 보게 해야 한다. [PRD FR-21] [확인 필요: Q24 MSDS API를 쓸 수 있는가]
- 수용 기준
  1. **전제** 물질 검색 **행동** "벤젠" 검색 **결과** 물질명·CAS 번호 목록, 줄마다 물질 상세로 이동
  2. **전제** 검색 기준 "CAS 번호" **행동** "71-43-2" **결과** 해당 물질
  3. **전제** 결과 0건 **행동** — **결과** "검색 결과가 없습니다. 물질명이나 CAS 번호를 확인해 주세요."
  4. **전제** 빈 검색어 **행동** 검색 **결과** 부르지 않고 "검색어를 입력해 주세요."

### FR-006 물질 상세와 공단 MSDS 링크 (P2, MS_010100_PG, MS_010102_LK) — **공단 MSDS 사이트 링크만 (Q24·D13)**. 물질 검색 화면에 "MSDS 조회는 산업안전보건공단 사이트에서 합니다" 안내와 새 창 링크를 둔다. 물질 상세는 미룸
시스템은 물질 상세에 물질명·CAS 번호와 그 물질의 취급점검 기록 목록을 보이고, 공단 MSDS 상세를 새 창으로 여는 링크를 줘야 한다. [PRD FR-21] [IA MS_010102_LK]
- 수용 기준
  1. **전제** 물질 상세 **행동** "공단 MSDS 상세 보기" **결과** 공단 페이지가 새 창으로 열린다 (유해·위험 문구, 보호구는 공단 페이지에서 본다, Q7 가정)
  2. **전제** 기록이 없음 **행동** — **결과** "아직 취급점검 기록이 없습니다."

### FR-007 취급점검 기록 (P2, MS_010101_MD) — **화면은 미룸 (Q24·D13)**. 데이터베이스 함수(`save_handling_check`)와 DB 시험은 1단계에서 완료
QC 시험 담당자·생산 담당자·QA 관리자가 점검 내용과 보호조치를 적으면, 시스템은 그 물질의 취급점검 기록으로 저장하고 최근순으로 보여 줘야 한다. [PRD FR-22] [ERD handling_check]
- 수용 기준
  1. **전제** 물질 상세 **행동** 취급점검 기록 작성 → 점검 내용·보호조치 입력 → 저장 **결과** 목록 맨 위에 작성자·시각과 함께 보인다
  2. **전제** 점검 내용이나 보호조치가 빔(공백만 포함) **행동** 저장 **결과** 저장되지 않고 "점검 내용을 입력해 주세요." 또는 "보호조치를 입력해 주세요."
  3. **전제** 열람자 **행동** — **결과** 작성 버튼이 없고 저장 단계에서도 거부된다

### FR-008 사용 기록 남기기 (P2, 모든 화면)
시스템은 로그인·로그아웃, 화면 이동, 검색어, 공공데이터 호출(무엇을, 성공 여부, 걸린 시간)을 사용자 ID로만 남겨야 한다. [PRD FR-23] [ERD usage_log]
- 수용 기준
  1. **전제** 로그인 → 배치 목록 → 제품 상세 **행동** — **결과** 로그인 1줄, 화면 이동 2줄(주소)
  2. **전제** 허가정보 검색 "타이레놀" **행동** — **결과** 검색 1줄(검색어)과 공공데이터 호출 1줄(허가정보, 성공, 걸린 시간 ms)
  3. **전제** 공공데이터 실패 **행동** — **결과** 호출 1줄이 "실패"로 남는다 (UJ E4 검증 방법)
  4. **전제** 사용 기록 **행동** 저장된 내용을 본다 **결과** 이메일이 없다
  5. **전제** 사용 기록을 남기지 못함 **행동** — **결과** 사용자의 화면 동작은 막히지 않는다

### FR-009 사용 기록 화면 (P2, AD_040000_PG)
시스템은 QA 관리자에게 사용 기록을 최근순 50개씩 보여 주고, 사람과 기록 종류로 거르게 해야 한다. [PRD FR-23] [IA AD_040000_PG]
- 수용 기준
  1. **전제** QA 관리자 **행동** 관리 > 사용 기록 **결과** 시각, 이름, 종류(로그인·로그아웃·검색·공공데이터 호출), 내용(검색어·호출 대상), 성공 여부, 걸린 시간. 화면 이동은 기록은 남기되 화면과 거르기 목록에는 보이지 않는다 (v0.4, 2026-10-27 사용자 결정 Q63)
  2. **전제** 종류 "공공데이터 호출" **행동** 거르기 **결과** 호출만, 실패는 글자로 "실패" 표시
  3. **전제** QA 관리자가 아닌 사람 **행동** 주소를 직접 연다 **결과** "이 화면은 QA 관리자만 볼 수 있습니다." 데이터도 읽히지 않는다

### FR-010 예시 자료 되돌리기 (P2, AD_050000_PU)
QA 관리자가 확인 창에서 한 번 더 확인하면, 시스템은 업무 자료를 처음 예시 상태로 되돌리고, 그 사실을 업무 이력에 남겨야 한다. [PRD FR-24] (Q27: 업무 이력은 지우지 않고 배치 연결만 비우며 배치번호를 글로 남긴다)
- 수용 기준
  1. **전제** QA 관리자, 관리 메뉴 **행동** 예시 자료 되돌리기 **결과** "배치·시험값·공정 기록·품질 이슈·조치 요청·취급점검 기록이 처음 예시 상태로 돌아갑니다. 사용자·역할과 사용 기록은 그대로입니다." 확인 창
  2. **전제** 확인 창 **행동** 확인 문구 "되돌리기"를 입력하고 실행 **결과** 예시 배치 PF-2610-001~005와 예시 제품 3개의 처음 기준값만 남고, 허가정보로 등록한 제품은 사라진다 (Q26)
  3. **전제** 실행 뒤 **행동** — **결과** 사용자·역할과 사용 기록은 그대로, 업무 이력에 "예시 자료 되돌리기" 1줄
  4. **전제** QA 관리자가 아닌 사람 **행동** — **결과** 메뉴가 없고 저장 단계에서도 거부된다

### 경계·예외 상황
- 허가정보 검색어 빈 값·공백만: 부르지 않고 "품목명을 입력해 주세요." (FR-001)
- 허가정보 검색어 1글자: 그대로 부른다 (결과가 많으면 앞 10건)
- 허가정보·회수 응답이 15초 넘음: 실패로 보고 다시 시도 (Q14)
- 공공데이터가 오류 코드를 돌려줌(인증키 오류, 한도 초과): 실패와 같게 안내하고 사용 기록에 실패로 남김
- 회수 공지 찾기: 품목명으로 찾은 뒤 같은 허가 품목(품목기준코드)만 남긴다. 이름이 비슷한 다른 품목은 보이지 않는다 (Q25 가정)
- 허가가 취소된 품목: 등록은 되고, 허가정보 탭에 "취소" 상태가 보인다
- 물질 검색어에 CAS 형식이 아닌 값(예: "71-43")으로 CAS 검색: 그대로 부르고 결과 0건 안내
- 취급점검 내용·보호조치 500자 넘음: 더 입력되지 않는다
- 되돌리기 확인 문구가 틀림: 실행 버튼이 잠겨 있다
- 되돌리기 중 다른 사람이 입력 중: 그 사람의 다음 저장은 "배치를 찾을 수 없습니다…" 류 안내로 실패한다 (발표용 1인 시연 전제)

### 핵심 자료
- **제품**: 품목명, 주성분, 제조원, 허가 품목기준코드(공공데이터에서 그 품목을 다시 찾는 값) [ERD product]
- **허가정보·회수 공지**: 저장하지 않고 열 때마다 부른다 [PRD §9 하지 않을 것 "대량 복사"] [Intent §4]
- **취급점검 기록**: 물질 식별값, 물질명·CAS 번호(작성 당시), 점검 내용, 보호조치, 작성자, 작성 시각 [ERD handling_check]
- **사용 기록**: 사용자 ID, 종류, 주소·검색어·호출 대상, 성공 여부, 걸린 시간, 시각. 이메일 없음 [ERD usage_log]
- **업무 이력**: 제품 등록, 취급점검 기록, 예시 자료 되돌리기가 더해진다 [ERD work_history.action]

## 4. 성공 기준

### 완료 확인
- **SC-001**: QA 관리자가 "타이레놀"을 검색해 하나를 등록하면 제품 목록에 보이고, 그 제품 상세에서 실제 허가정보와 회수·판매중지 이력(없으면 없다는 안내)이 보인다 (관련: FR-001, FR-002)
- **SC-002**: 공공데이터 인증키를 비운 서버에서 제품 상세·대시보드·물질 검색을 열면, 공공데이터 칸에만 실패 안내와 다시 시도 버튼이 뜨고 나머지는 정상이며, 사용 기록에 호출 실패가 남는다 (관련: FR-003, FR-004, FR-008)
- **SC-003**: 화면 코드와 모든 응답 어디에도 공공데이터 인증키가 없다 (관련: FR-004)
- **SC-004**: (v0.3) 물질 검색 화면에서 공단 MSDS 사이트가 새 창으로 열린다. 취급점검 기록의 권한(열람자 거부)은 DB 시험으로 확인한다 (관련: FR-006, FR-007)
- **SC-005**: 로그인·화면 이동·검색·공공데이터 호출이 사용 기록에 남고, QA 관리자만 볼 수 있으며 이메일이 없다 (관련: FR-008, FR-009)
- **SC-006**: 예시 자료 되돌리기 뒤 배치는 PF-2610-001~005 처음 상태이고, 사용자·역할과 사용 기록은 그대로이며, 업무 이력에 되돌린 사실이 남는다 (관련: FR-010)
