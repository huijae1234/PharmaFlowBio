## 1. 해결하려는 문제
**지금 방식:** QC 시험 담당자는 시험값 입력 창에서 시험 항목을 하나 고르고 값 하나를 넣어 저장한다. 항목이 4개면 창을 4번 연다. QA 관리자는 이탈이 생길 때만 알림을 받고, 모든 시험이 끝났는지는 로트 상세를 열어 봐야 안다. 내부 출하 검토에서 "출하 가능"이 나면 로트는 그 상태로 끝나고, 실제로 내보냈는지는 앱에 남지 않는다. [코드 시험값 입력 BT_010206_MD] [spec 009 알림 15가지] [ERD batch 로트 상태 규칙]
**막히는 지점:**
- 시험 항목마다 창을 다시 열어야 해서 입력이 느리고, 어느 항목을 빠뜨렸는지 창 안에서 한눈에 보이지 않는다. [사용자 요청 2026-10-28 "QC 입력창 한번에 입력 가능하도록"]
- QA 관리자는 시험이 끝난 로트를 앱을 뒤져서 찾아야 한다. 내부 출하 검토 대기를 늦게 안다. [사용자 요청 2026-10-28 "QC 시험 완료시 QA 알림"] [PRD 문제 1 "출하 검토 직전의 확인이 오래 걸리고 놓치기 쉽다"]
- 출하 가능 판정 뒤 생산이 실제로 로트를 내보냈는지, 누가 언제 했는지 기록이 없다. 출하 가능 로트와 이미 나간 로트가 같은 상태로 섞인다. [사용자 요청 2026-10-28 "출하가능 승인 났을 때 출하하는 버튼"]
- 측정값 표의 열 이름 "그때 기준"이 어색하다. [사용자 요청 2026-10-28 "그때 기준 → 기준"]

## 2. 주요 사용자
**사용자:** QC 시험 담당자(시험값 입력), QA 관리자(시험 완료 알림을 받고 내부 출하 검토, 출하 완료 알림을 받음), 생산 담당자(출하 완료 기록). 새 역할은 만들지 않는다. [IA 역할별 권한] [전환 D4]

### 이야기 1 — 시험값을 한 창에서 모두 넣는다 (P1)
- 장면: QC 시험 담당자 윤○○이 IFV-2610-002 시험을 끝내고 로트 상세에서 "시험값 입력"을 연다. 역가·엔도톡신·pH 칸이 한 창에 기준과 함께 보인다. 세 값을 넣고 한 번 저장하면 항목마다 판정이 나온다.
- 왜 P1: 사용자가 가장 자주 하는 입력이고, 시험 완료(이야기 2)도 이 입력으로 생긴다.
- 혼자 확인하는 방법: 시험값이 비어 있는 예시 로트에서 창을 열어 모든 칸을 채우고 저장 → 시험 결과 탭에 항목 수만큼 줄과 판정.

### 이야기 2 — 시험이 끝나면 QA가 알림을 받는다 (P1)
- 장면: 윤○○이 마지막 시험값을 저장하자, 유○○ 슬랙과 앱 알림 함에 "시험 완료 · IFV-2610-002 · 정상 2 · 이탈 1"이 온다. 유○○은 알림을 눌러 로트 상세에서 내부 출하 검토를 시작한다.
- 왜 P1: QA가 출하 검토 대기를 늦게 아는 문제를 바로 줄인다.
- 혼자 확인하는 방법: QC 계정으로 남은 시험값을 모두 넣고, QA 계정 알림 함에서 그 알림 한 건과 로트 이동을 본다.

### 이야기 3 — 출하 가능 로트를 출하 완료로 남긴다 (P1)
- 장면: 내부 출하 검토로 IFV-2610-004가 "출하 가능"이 되었다. 생산 담당자 김희재가 로트 상세에서 [출하 완료]를 눌러 출하 일시와 메모를 넣는다. 로트가 "출하 완료"로 바뀌고 QA 관리자에게 알림이 간다.
- 왜 P1: 출하 가능과 이미 나간 로트를 구분하는 최소 기록이다.
- 혼자 확인하는 방법: 예시 로트 IFV-2610-004(출하 가능)에서 생산 계정으로 출하 완료 → 상태 배지 "출하 완료", 업무 이력 한 줄, QA 알림 함 한 줄.

### 이야기 4 — "기준"이라는 말로 본다 (P2)
- 장면: 누구든 시험 결과 탭을 열면 측정값마다 판정에 쓴 기준이 "기준" 열에 보인다.
- 왜 P2: 뜻은 그대로이고 글자만 바뀐다.
- 혼자 확인하는 방법: 시험 결과 탭과 제품 상세 기준 등록 안내를 열어 "그때 기준"이 없는지 본다.

## 3. 핵심 기능과 요구사항

### FR-001 시험 완료 판단 (P1, BT_010200_PG)
로트에 시험값이 저장될 때, 시스템은 그 로트의 제품 시험 항목(내부 출하 검토가 확인하는 시험 항목과 같은 범위) 모두에 첫 측정값이 있는지 확인하고, 이번 저장으로 처음 모두 채워졌을 때만 "시험 완료"로 보아야 한다. [사용자 Q2 결정] [PRD FR-15]
- 수용 기준
  1. **전제** 시험 항목 3개 중 2개 입력됨 **행동** 마지막 1개 저장 **결과** 시험 완료로 보고 FR-002 알림이 한 번 간다
  2. **전제** 3개 중 1개 입력됨 **행동** 1개 저장 **결과** 시험 완료가 아니고 알림도 없다
  3. **전제** 이미 시험 완료된 로트 **행동** 재시험 조치 결과로 측정값 저장 **결과** 시험 완료 알림이 다시 가지 않는다(재시험은 세지 않는다)
  4. **전제** 남은 항목 2개 **행동** 한 번에 입력(FR-003)으로 2개를 같이 저장 **결과** 알림은 한 건만 간다

### FR-002 시험 완료 알림 (P1, 알림 함 · 사용 기록 AD_040000_PG)
FR-001의 시험 완료가 생길 때, 시스템은 QA 관리자 모두(저장한 사람 제외)에게 슬랙 개인 메시지와 앱 알림을 한 건씩 보내야 한다. 이탈이 있어도 보내며, 알림이 실패해도 시험값 저장은 막지 않는다. [사용자 Q2 결정] [spec 009 FR-001·004·007]
- 수용 기준
  1. **전제** 정상 2·관리기준 이탈 1로 시험 완료 **결과** QA 관리자 알림 함에 "시험 완료 · IFV-2610-002 · 정상 2 · 이탈 1", 누르면 그 로트 상세
  2. **전제** 모두 정상 **결과** "시험 완료 · IFV-2610-003 · 정상 3 · 이탈 0"
  3. **전제** 슬랙 설정 없음 **결과** 시험값은 저장되고 알림 기록에 "보내지 못함 · 슬랙 설정 없음"
  4. **결과** 이 알림도 spec 009 v0.7 확인 표시를 따른다: 로트 상세 집계 줄에 들어간다

### FR-003 시험값 한 번에 입력 (P1, BT_010206_MD)
QC 시험 담당자가 시험값 입력 창을 열 때, 시스템은 아직 첫 측정값이 없는 시험 항목을 모두 칸으로 보여 주고 칸마다 시험 규격·사내 관리기준·기준 버전을 옆에 보여 주어야 한다. [사용자 Q3 결정] [spec 004 FR-003 수용 기준 6]
- 수용 기준
  1. **전제** 시험 항목 3개 모두 미입력 **결과** 칸 3개, 칸마다 "규격 80~125 % · 관리기준 90~115 % · v1 · 교육용 가상 기준" 같은 기준 글자
  2. **전제** 1개 입력됨 **결과** 남은 2개만 칸으로 나오고, 이미 넣은 항목은 "입력됨"으로 칸 없이 보인다
  3. **전제** 모두 입력됨 **결과** 칸이 없고 "모든 시험 항목을 입력했습니다. 다시 재려면 재시험 조치를 요청해 주세요."가 보이며 저장 버튼이 눌리지 않는다
  4. **결과** 키보드 Tab으로 칸을 차례로 옮겨 다닐 수 있고, 칸마다 이름표(시험 항목 이름)가 있다

### FR-004 한 번에 저장하고 항목별 판정 보기 (P1, BT_010206_MD · BT_010202_TB)
여러 칸에 값을 넣고 저장할 때, 시스템은 넣은 값을 모두 같은 규칙(세 단계 판정, 이탈이면 항목마다 품질 이슈, 규격 이탈이면 자동 보류)으로 한꺼번에 저장하고, 저장 뒤 항목별 판정을 보여 주어야 한다. 넣은 값 중 하나라도 저장할 수 없으면 아무것도 저장하지 않아야 한다. [사용자 Q3 결정] [PRD FR-08] [ERD 로트 상태 규칙]
- 수용 기준
  1. **전제** 3칸 모두 값 **행동** 저장 **결과** 시험 결과 탭에 3줄, 저장 뒤 안내에 "역가 정상 · 엔도톡신 관리기준 이탈 · …"처럼 항목별 판정
  2. **전제** 2칸만 값, 1칸 빈칸 **행동** 저장 **결과** 2개만 저장되고 빈칸 항목은 다음에 다시 칸으로 나온다
  3. **전제** 한 칸에 "12a" **행동** 저장 **결과** 그 칸 옆에 숫자 오류 문구, 다른 칸 값도 저장되지 않고 창에 그대로 남는다
  4. **전제** 모든 칸이 빈칸 **행동** 저장 **결과** "시험값을 하나 이상 입력해 주세요."
  5. **전제** 두 항목이 규격 이탈 **결과** 품질 이슈 2건(항목마다 하나, 한 건씩 넣을 때와 같음), 로트 보류 한 번, 이탈 알림은 지금 규칙대로
  6. **전제** 창을 연 사이 다른 사람이 같은 항목을 먼저 저장 **결과** "이미 입력된 시험 항목이 있습니다. 창을 닫고 다시 열어 주세요." 아무것도 저장되지 않는다
  7. **전제** 생산 중 로트에 첫 시험값 저장 **결과** 로트가 "시험 중"이 되는 규칙은 지금과 같다

### FR-005 출하 완료 기록 (P1, BT_010200_PG, 새 모달)
"출하 가능" 로트에서 생산 담당자가 출하 완료를 기록할 때, 시스템은 출하 일시(기본값 지금)와 메모(선택)를 받아 로트 상태를 "출하 완료"로 바꾸고, 기록한 사람·일시를 남겨야 한다. [사용자 Q4 결정]
- 수용 기준
  1. **전제** 출하 가능 로트, 생산 담당자 **행동** [출하 완료] → 출하 일시 그대로, 메모 "1차 출고" → 저장 **결과** 상태 배지 "출하 완료", 로트 상세 위쪽에 "출하 완료 · 10/28 14:00 · 김희재"
  2. **결과** 창에 "회사 내부 출하 기록이며 국가출하승인이 아닙니다."가 보인다
  3. **전제** 출하 가능이 아닌 로트(생산 중·시험 중·보류·폐기·출하 완료) **결과** 버튼이 없고, 화면을 거치지 않고 불러도 "출하 가능 로트만 출하 완료로 기록할 수 있습니다."
  4. **전제** QA 관리자·QC 시험 담당자·열람자 **결과** 버튼이 없고, 직접 불러도 "이 작업을 할 권한이 없습니다"
  5. **전제** 두 사람이 거의 동시에 출하 완료 **결과** 한 건만 기록되고 다른 사람은 3번 문구

### FR-006 출하 완료 로트는 읽기만 (P1, BT_010200_PG · BT_010000_PG)
로트가 출하 완료일 때, 시스템은 지금 출하 가능·폐기 로트처럼 시험값·공정 조건 입력, 보류, 내부 출하 검토를 막고, 로트 목록 상태 거르기와 배지에 "출하 완료"를 보여 주어야 한다. 출하 완료는 되돌릴 수 없다. [ERD 로트 상태 규칙 Q11] [사용자 Q4 결정]
- 수용 기준
  1. **전제** 출하 완료 로트 **결과** 입력·보류·내부 출하 검토·출하 완료 버튼이 모두 없다
  2. **결과** 로트 목록 상태 거르기에 "출하 완료"가 있고 배지는 글자로 보인다(색만으로 구분하지 않음)
  3. **결과** 되돌리기 버튼은 없다
  4. **결과** 검체 기록(반납·반납 확인·보존 검체)은 로트 상태와 상관없이 지금처럼 된다 [가정 Q77]

### FR-007 출하 완료 업무 이력과 알림 (P1, BT_010204_TB · AD_030000_PG · 알림 함)
출하 완료를 기록할 때, 시스템은 업무 이력에 누가·언제·출하 일시·메모를 남기고(고치기·지우기 불가), QA 관리자 모두에게 슬랙 개인 메시지와 앱 알림을 한 건씩 보내야 한다. 알림 실패는 기록을 막지 않는다. [PRD FR-16] [사용자 Q4 결정] [spec 009]
- 수용 기준
  1. **결과** 로트 업무 이력 탭과 전체 업무 이력에 "출하 완료 · 출하 가능 → 출하 완료 · 출하 일시 10/28 14:00 · 김희재"
  2. **결과** QA 관리자 알림 함에 "출하 완료 · IFV-2610-004 · 김희재", 누르면 로트 상세

### FR-008 "그때 기준" → "기준" (P2, BT_010202_TB · PD_010201_MD)
시스템은 화면에 보이는 "그때 기준"을 "기준"으로 바꾸어야 한다. 제품 기준 등록 안내 문장은 "이미 넣은 측정값은 바꾸기 전 기준으로 남습니다."로 바꾼다. 측정값마다 판정에 쓴 기준을 저장해 두는 규칙은 바꾸지 않는다. [사용자 Q5 결정] [spec 004 FR-004]
- 수용 기준
  1. **결과** 시험 결과 탭 측정값 표의 열 이름이 "기준"
  2. **결과** 제품 상세 기준 등록 안내가 "…바꾸기 전 기준으로 남습니다."
  3. **결과** 앱 화면 어디에도 "그때 기준"이 보이지 않는다

### FR-009 예시 자료와 기존 동작 유지 (P2)
시스템은 예시 자료 되돌리기 뒤에도 지금 예시 로트 상태를 그대로 두고(출하 완료 예시는 새로 만들지 않음), 기존 기능(시험 결과 판정·품질 이슈·내부 출하 검토·검체·작업지시·공정 단계)이 예전과 같이 동작해야 한다. [CLAUDE.md 예시 자료] [가정 Q78]
- 수용 기준
  1. **전제** 되돌리기 직후 **결과** IFV-2610-004는 "출하 가능" 그대로라 출하 완료를 바로 시연할 수 있다
  2. **결과** 기존 함수 시험과 DB 시험이 모두 통과한다

### 경계·예외 상황
- 시험 항목이 하나도 없는 제품: 입력 창에 칸이 없고 "이 제품에 시험 항목이 없습니다. 제품 상세에서 기준을 먼저 등록해 주세요." 시험 완료 알림은 생기지 않는다
- 시험값 입력이 막힌 로트 상태(출하 가능·폐기·출하 완료): 지금처럼 입력 버튼이 없다
- 시험 완료 뒤 QA가 기준(새 시험 항목)을 더하면: 그 로트는 다시 미완료가 되지만 새 항목이 채워질 때 알림이 한 번 더 간다 [가정 Q79]
- 숫자 형식: 지금 시험값 입력과 같은 규칙(빈칸은 건너뜀, 숫자가 아니면 칸 옆 오류)
- 출하 일시: 빈칸 → "출하 일시를 입력해 주세요." 앞으로의 시각 → "출하 일시는 지금보다 뒤일 수 없습니다." 출하 가능이 된 시각보다 앞 → "출하 일시는 출하 가능 판정 뒤여야 합니다."
- 메모: 앞뒤 빈칸을 지우고 200자까지. 사람이 쓴 글은 글자 그대로 보인다
- 출하 수량·출하처: 받지 않는다(5절)
- 같은 로트에 출하 완료 두 번: FR-005 수용 기준 3·5

### 핵심 자료
- **로트**: 상태에 "출하 완료"가 더해진다. 출하 완료면 출하 일시, 출하 메모, 기록한 사람, 기록 일시를 갖는다.
- **측정값**: 지금 그대로. 한 번에 넣어도 항목마다 한 줄씩, 판정에 쓴 기준과 버전을 함께 갖는다.
- **알림**: 종류 둘이 더해진다(시험 완료, 출하 완료). 받는 사람·보내는 방식은 spec 009 그대로.

## 4. 성공 기준

### 완료 확인
- **SC-001**: QC 계정으로 시험값 입력 창을 열면 남은 시험 항목이 모두 칸으로 기준과 함께 보이고, 값을 넣어 한 번 저장하면 시험 결과 탭에 항목 수만큼 줄과 판정이 생긴다. 하나라도 형식이 틀리면 아무것도 저장되지 않는다 (관련: FR-003, FR-004)
- **SC-002**: 마지막 시험값을 저장하면 QA 관리자 알림 함과 슬랙에 "시험 완료 · 로트번호 · 정상 N · 이탈 N"이 한 번 오고, 누르면 그 로트 상세가 열린다. 재시험으로는 다시 오지 않는다 (관련: FR-001, FR-002)
- **SC-003**: 출하 가능 로트에서 생산 계정으로 출하 완료를 기록하면 상태가 "출하 완료"가 되고, 업무 이력과 QA 알림이 남으며, 그 로트에서 입력·검토 버튼이 사라진다 (관련: FR-005, FR-006, FR-007)
- **SC-004**: 생산 외 역할과 출하 가능이 아닌 로트에는 출하 완료 버튼이 없고, 화면을 거치지 않고 불러도 막힌다 (관련: FR-005)
- **SC-005**: 앱 화면에 "그때 기준"이 없고 "기준"으로 보인다 (관련: FR-008)
- **SC-006**: 예시 자료 되돌리기 뒤 기존 기능이 예전과 같이 동작하고 모든 시험이 통과한다 (관련: FR-009, FR-004 수용 기준 5·7)

## 5. 제외 범위
| 무엇 | 왜 뺐나 | 언제 다시 보나 |
|---|---|---|
| 출하 수량·출하처·운송 정보 | 사용자 결정 Q4(일시·메모만). 재고·물류는 이 앱의 범위가 아니다 | 필요해지면 |
| 출하 완료 되돌리기 | 출하는 되돌릴 일이 아니다. 잘못 누른 경우는 메모와 업무 이력으로 설명 | 영영 안 함 |
| 국가출하승인 신청·결과 기록 | PRD §9 하지 않을 것 "국가출하승인 결정·보증" | 영영 안 함 |
| QA 관리자의 출하 완료 기록 | 사용자 결정 Q4(생산 담당자만) | 요청 시 |
| 시험값을 엑셀·파일에서 붙여 넣기 | 이번 요청은 한 창에서 입력. 붙여 넣기는 형식 검사가 따로 필요 | 2차 |
| 재시험 측정값 한 번에 입력 | 재시험은 조치 결과 창에서 항목 하나씩(spec 002) 그대로 | 요청 시 |
| 제조공정 홈 "출하할 로트" 칸 | 출하 검토 결과 알림(spec 009)과 로트 목록 거르기로 찾을 수 있다 | 2차 |
| 출하 완료 예시 로트 | 시연에서 직접 눌러 보이는 편이 낫다(Q78) | 요청 시 |
