## 1. 해결하려는 문제
**지금 방식:** 시험값·공정값 판정과 공공데이터 화면을 확인할 때 그때그때 값을 지어 넣거나 실제 공공데이터 사이트를 부른다. 위험 값·틀린 값·실패 응답이 한곳에 정리돼 있지 않고, 공공데이터 실패 화면은 실제 사이트가 실패할 때만 볼 수 있다. [코드 api/permit.js·recall.js] [spec 006 FR-003] [사용자 요청 2026-10-28]
**막히는 지점:**
- 같은 확인을 다시 할 때 어떤 값으로 무엇을 봤는지 남아 있지 않아 결과를 비교할 수 없다. [사용자 요청 2026-10-28 "자료마다 확인할 것과 기대 결과"]
- 공공데이터 오류·시간 초과·깨진 응답을 일부러 만들 수 없어 실패 안내와 마지막 정상 조회 화면을 시연·확인하기 어렵다. [spec 006 FR-003] [UJ E4]
- 실제 사이트를 부르면 하루 호출 한도를 쓰고 결과가 날마다 달라진다. [ADR 0001] [plan 003 §1]

## 2. 주요 사용자
**사용자:** 개발·확인하는 사람(Claude 포함), 시연하는 QA 관리자. 앱을 쓰는 업무 사용자는 이 기능을 보지 않는다(배포에서는 늘 실제 자료). [사용자 요청 2026-10-28] [Q3 결정]

### 이야기 1 — 시험용 자료로 판정·저장·권한을 다시 확인한다 (P1)
- 장면: 개발자가 판정 규칙을 고친 뒤 `fixtures/`의 정상·위험·틀린 값을 그대로 다시 넣어 기대 결과와 같은지 본다.
- 왜 P1인가: 사용자가 요청한 1·3·4번의 바탕이다.
- 혼자 확인하는 방법: 시험 명령과 되돌리는 DB 시험을 돌려 docs/test-data.md의 기대 결과와 실제 결과가 같은지 본다.

### 이야기 2 — 시험 모드로 공공데이터 화면을 확인한다 (P1)
- 장면: 로컬에서 시험 모드를 켜고 제품 등록 검색에 "실패"를 넣어 실패 안내를, "없음"을 넣어 0건 안내를 본다. 칸마다 "시험 자료" 표시가 있어 실제 자료와 헷갈리지 않는다.
- 왜 P1인가: 사용자가 요청한 2번. 실제 사이트 없이 실패 화면을 볼 수 있는 유일한 방법이다.
- 혼자 확인하는 방법: 시험 모드로 서버를 켜고 제품 등록 검색 → "시험 자료" 표시와 검색어별 결과.

## 3. 핵심 기능과 요구사항

### FR-001 시험용 자료 폴더 (P1)
시스템은 `fixtures/`에 정상 값과 위험 값(관리기준 이탈·규격 이탈)을, `fixtures/broken/`에 일부러 틀린 값(빈 값, 단위가 붙은 값, 중복, 음수, 경계값, 공공데이터 실패 응답)을 가져야 한다. 모든 자료는 가상이다. [사용자 요청 1] [Q1 결정] [CLAUDE.md 하지 않을 것 "실제 회사 자료"]
- 수용 기준
  1. **결과** 시험값·공정값 자료는 예시 제품(인플루엔자 4가 백신 프리필드주 (가상))의 기준으로 판정할 값이고, 자료마다 번호·넣을 값·기대 판정이 있다
  2. **결과** 공공데이터 자료는 허가정보·회수 응답 모양 그대로(정상, 0건, 오류 코드, XML, 깨진 글, 중복, 칸 빠짐)이고 품목명·업체명에 "(시험 자료)"가 붙어 있다
  3. **결과** 이 폴더는 로컬 서버도 내보내지 않고 배포에도 올라가지 않는다

### FR-002 공공데이터 시험 모드 (P1, PD_010100_MD·제품 상세·관리자 대시보드 공공데이터 칸)
로컬 서버에서 시험 모드를 켰을 때, 시스템은 공공데이터 서버 함수가 실제 사이트 대신 시험용 자료를 돌려주게 해야 하고, 켜지 않았거나 배포 환경이면 지금처럼 실제 사이트를 불러야 한다. [사용자 요청 2] [Q2·Q3 결정]
- 수용 기준
  1. **전제** 시험 모드 켬(로컬) **행동** 허가정보 검색 "인플루엔자" **결과** 시험 자료 정상 응답, 실제 사이트 호출 없음
  2. **행동** 검색어 "없음" / "실패" / "XML" / "깨짐" / "시간초과" / "중복" / "빈칸" **결과** 0건 / 오류 / 오류 / 오류 / 시간 초과 / 같은 품목 두 줄 / 빈 칸은 빈칸으로 (Q4 결정)
  3. **전제** 시험 모드 끔, 또는 배포 환경에서 켬 **결과** 실제 사이트를 부른다
  4. **결과** 로그인 확인·검색어 검사·실패 안내는 지금과 같다

### FR-003 "시험 자료" 표시 (P1)
시험 자료로 응답했을 때, 시스템은 그 공공데이터 칸에 "시험 자료" 표시를 하고 출처 줄을 "출처: 시험 자료(fixtures)"로 보여야 하며, 그 결과를 마지막 정상 조회로 보관하지 않아야 한다. [사용자 요청 2] [spec 006 FR-002·003]
- 수용 기준
  1. **결과** 칸 위쪽 "시험 자료" 글자(색만으로 구분하지 않음), 출처 줄 "출처: 시험 자료(fixtures) · 조회 …"
  2. **결과** 시험 자료 결과는 이 기기에 보관하지 않는다(실제 결과의 마지막 정상 조회를 덮지 않음)

### FR-004 시험 자료 문서 (P1)
시스템 문서는 `docs/test-data.md`에 자료마다 확인할 것·기대 결과·실제 결과·확인일을 두어야 하고, 돌리지 못한 것은 "미검증"과 이유를 적어야 한다. [사용자 요청 3·4]
- 수용 기준
  1. **결과** 정상, 경계값, 데이터 오류, 저장, 권한, 공공데이터 시험 모드 다섯 묶음 이상, 자료 번호가 fixtures 파일과 같다
  2. **결과** 실제 결과 칸이 비어 있는 줄이 없다(결과 또는 "미검증: 이유")

### FR-005 자료로 직접 돌리기 (P1)
시스템은 시험용 자료를 함수 시험과 되돌리는 DB 시험으로 돌릴 수 있어야 하고, 실제 DB에는 아무것도 남기지 않아야 한다. [사용자 요청 4] [Q5 결정]
- 수용 기준
  1. **결과** 입력 검사(빈 값·단위·음수·경계값)는 함수 시험이 fixtures 파일을 읽어 기대 결과와 비교한다
  2. **결과** 판정·저장(보류·이슈)·중복·권한은 DB 시험이 같은 값으로 되돌리는 거래 안에서 확인한다
  3. **결과** 시험 뒤 실제 DB의 로트·측정값 수가 그대로다

### FR-006 기존 동작 유지 (P1)
시스템은 시험 모드를 켜지 않았을 때 공공데이터 화면·호출·사용 기록과 판정·저장·권한을 지금처럼 유지해야 한다. [Intent 4절]
- 수용 기준
  1. **결과** 기존 함수 시험·DB 시험이 모두 통과한다

### 경계·예외 상황
- 시험 모드 값이 "fixtures"가 아니면(빈 값, 오타, 대소문자 다름) 실제 사이트를 부른다
- 배포 환경이면 값이 있어도 실제 사이트를 부른다
- 시험 모드인데 인증키가 없어도 시험 자료로 응답한다(실제 키를 쓰지 않음)
- 시험 자료 파일이 없거나 읽지 못하면 "연결 실패"와 같은 실패 안내
- 검색어가 비면 지금처럼 "품목명을 입력해 주세요."(시험 자료를 부르지 않음)
- 경계값: 규격·관리기준 최솟값·최댓값과 딱 같은 값은 그 범위 안으로 본다(지금 판정 규칙)
- 음수: 숫자로 받아 판정한다(엔도톡신 -1은 규격 이탈)
- 단위가 붙은 값("1.5 EU/mL"), 쉼표 소수("1,5"), 빈 값, 공백은 저장하지 않고 "숫자로 입력해 주세요."
- 중복: 한 번에 저장에 같은 항목이 두 번이면 아무것도 저장하지 않는다(spec 017)

### 핵심 자료
- **시험값·공정값 자료**: 번호, 묶음(정상·위험·경계·오류), 항목, 넣을 글자, 기대 결과(판정 또는 오류 문구)
- **공공데이터 자료**: 종류(허가정보·회수), 검색어, 응답 모양, 기대 화면
- **시험 자료 문서**: 번호, 확인할 것, 기대 결과, 실제 결과, 확인일

## 4. 성공 기준

### 완료 확인
- **SC-001**: `fixtures/`와 `fixtures/broken/`에 정상·위험·틀린 값 자료가 있고 docs/test-data.md의 번호와 같다 (관련: FR-001, FR-004)
- **SC-002**: 로컬에서 시험 모드를 켜고 제품 등록 검색을 하면 "시험 자료" 표시와 시험 자료가 보이고, "실패"는 실패 안내가 보인다 (관련: FR-002, FR-003)
- **SC-003**: 시험 모드를 끄면 같은 화면이 실제 자료와 "출처: 식약처 공공데이터"를 보이고, 배포 환경 값이 있으면 시험 모드가 켜지지 않는다(함수 시험) (관련: FR-002, FR-006)
- **SC-004**: 함수 시험과 DB 시험이 시험용 자료를 그대로 읽어 기대 결과와 같고, docs/test-data.md 실제 결과 칸이 모두 채워져 있다 (관련: FR-004, FR-005)
- **SC-005**: 기존 시험이 모두 통과한다 (관련: FR-006)
