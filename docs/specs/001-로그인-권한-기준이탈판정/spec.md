## 1. 해결하려는 문제
**지금 방식:** QC 시험 담당자가 시험값을 기록지에 적고 기준서와 눈으로 비교한다. 이탈이면 메일·전화로 QA에 알린다. 생산 담당자는 공정 이상을 보고서로 전달한다. [UJ CUJ-01 1·2단계 As-Is] [UJ CUJ-02 3단계]
**막히는 지점:**
- 기준 이탈이 사람 손으로 전달되어 누락·지연이 생기고, 문제 배치가 멈추지 않은 채 출하 판정 대상에 섞일 수 있다. [PRD §2-2] [Intent 1절]
- 누가 언제 무엇을 기록했는지 한곳에 남지 않는다. [PRD §2-3] [Intent 1절]
- 모든 사람이 같은 자료를 보되 역할마다 할 수 있는 일을 막아야 하는데, 지금은 그런 장치가 없다. [문제정의 정한 범위-사용자와 권한] [ADR 0002]
- 문제의 크기(이탈 전달에 걸리는 시간)는 가설이다. [Intent Q9]

## 2. 주요 사용자
**사용자:** QC 시험 담당자, 생산 담당자, QA 관리자, 열람자 [GLOSSARY 사람] [PRD §4]

### 이야기 1 — 시험값을 넣으면 기준 이탈이 바로 잡힌다 (P1)
- 장면: QC 시험 담당자가 구글로 로그인해 품질시험 홈에서 시험을 기다리는 배치를 열고, 순도 측정값을 입력한다. [UJ CUJ-01 1·2단계] [IA HM_020000_PG, BT_010206_MD]
- 왜 P1인가: CUJ-01의 첫 번째 결정적 순간(기준 이탈 감지)이다. 이것이 없으면 이후의 조치·승인·출하 판정이 시작되지 않는다. [UJ CUJ-01 MOT]
- 혼자 확인하는 방법: QC 시험 담당자 계정으로 예시 배치에 기준 밖 값을 넣으면 "기준 이탈"과 배치 "보류"가 보이고, 업무 이력 탭에 기록이 남는다.

### 이야기 2 — 처음 온 사람이 역할을 받아 자기 화면으로 들어간다 (P1)
- 장면: 처음 로그인한 사람이 열람자로 들어와 안내를 보고, QA 관리자가 사용자·역할 화면에서 역할을 지정한다. [UJ CUJ-03] [IA MB_000000_PG, AD_020000_PG]
- 왜 P1인가: 역할이 없으면 아무도 시험값을 넣을 수 없다. 발표 때 청중 전원이 거치는 흐름이다. [PRD CUJ-03]
- 혼자 확인하는 방법: 구글 계정 두 개로, 한 계정이 다른 계정에 역할을 주고 그 계정의 첫 화면이 바뀌는지 본다.

### 이야기 3 — 공정 조건이 기준을 벗어나면 배치가 멈춘다 (P2)
- 장면: 생산 담당자가 제조공정 홈에서 생산 중 배치를 열고 생산량·공정 온도·설비 상태를 입력한다. 이상이 보이면 사유를 적어 직접 보류하기도 한다. [UJ CUJ-02] [IA HM_030000_PG, BT_010205_MD, BT_010207_MD]
- 왜 P2인가: CUJ-02의 결정적 순간이지만, 이야기 1과 같은 판정 방식을 공정 쪽으로 넓히는 것이라 이야기 1 다음에 만든다.
- 혼자 확인하는 방법: 생산 담당자 계정으로 기준 밖 공정 온도와 설비 상태 "이상"을 함께 넣으면 품질 이슈가 1개만 생기고 배치가 보류된다.

### 이야기 4 — QA 관리자가 제품별 기준값을 관리한다 (P2)
- 장면: QA 관리자가 제품 상세에서 시험 항목과 공정 조건 항목의 기준 범위를 등록·수정한다. [IA PD_010200_PG, PD_010201_MD]
- 왜 P2인가: 예시 제품 3개에는 기준값이 미리 들어 있어 이야기 1은 이것 없이도 된다. [PRD FR-06]
- 혼자 확인하는 방법: 기준값을 바꾼 뒤 새로 넣은 시험값이 바뀐 기준으로 판정되고, 이미 넣은 측정값의 판정은 그대로인지 본다.

## 3. 핵심 기능과 요구사항

### FR-001 구글 로그인 (P1, MB_000000_PG)
시스템은 구글 계정으로 로그인·로그아웃할 수 있게 해야 한다. [PRD FR-01] [ADR 0002]
- 수용 기준
  1. **전제** 로그인하지 않은 상태 **행동** "구글로 로그인"을 누르고 구글 계정을 고른다 **결과** 그 사람의 역할별 첫 화면이 열린다
  2. **전제** 구글 로그인 창 **행동** 창을 닫거나 실패한다 **결과** 로그인 화면에 "로그인하지 못했습니다. 다시 시도해 주세요."가 보인다 [UJ CUJ-03 명세]
  3. **전제** 로그인한 상태 **행동** 로그아웃을 누른다 **결과** 로그인 화면으로 간다

### FR-002 로그인하지 않은 접근 막기 (P1, MB_000000_PG)
로그인하지 않은 사람이 로그인 화면이 아닌 주소로 들어오면, 시스템은 로그인 화면으로 보내야 한다. [PRD FR-01]
- 수용 기준
  1. **전제** 로그인하지 않은 상태 **행동** 배치 상세 주소를 직접 연다 **결과** 로그인 화면이 열리고 배치 정보는 보이지 않는다

### FR-003 처음 로그인하면 열람자 (P1, BT_010000_PG)
처음 로그인한 사람에게, 시스템은 열람자 역할을 주고 모든 화면 위에 읽기 전용 이유와 할 일을 보여 줘야 한다. [PRD FR-02] [UJ CUJ-03 MOT]
- 수용 기준
  1. **전제** 한 번도 로그인한 적 없는 구글 계정 **행동** 로그인한다 **결과** 배치 목록이 열리고 "역할을 받기 전에는 읽기만 할 수 있습니다. QA 관리자에게 역할을 요청해 주세요."가 보이며, 입력 버튼이 하나도 없다

### FR-004 QA 관리자의 역할 지정 (P1, AD_020000_PG)
QA 관리자가 사용자·역할 화면에서 역할을 고르면, 시스템은 그 사용자의 역할을 바꾸고 다음 화면 이동부터 적용해야 한다. [PRD FR-03] [UJ CUJ-03 3·4단계]
- 수용 기준
  1. **전제** QA 관리자로 로그인 **행동** 사용자·역할 화면을 연다 **결과** 이름, 이메일, 역할, 처음 로그인한 시각이 보이고 최근에 처음 로그인한 사람이 맨 위에 있다
  2. **전제** 열람자 A가 배치 목록을 보고 있음 **행동** QA 관리자가 A를 QC 시험 담당자로 바꾸고, A가 다른 화면으로 이동한다 **결과** A가 다시 로그인하지 않아도 품질시험 홈이 열리고 시험값 입력 버튼이 보인다
  3. **전제** QA 관리자로 로그인 **행동** 자기 역할을 다른 역할로 바꾸려 한다 **결과** 바뀌지 않고 "QA 관리자는 자기 역할을 바꿀 수 없습니다."가 보인다 [UJ README 정한 사항]
  4. **전제** QA 관리자가 아닌 사람 **행동** 사용자·역할 주소를 직접 연다 **결과** "이 화면은 QA 관리자만 볼 수 있습니다."가 보이고 이메일이 보이지 않는다

### FR-005 역할별 첫 화면 (P1, HM_010000_PG, HM_020000_PG, HM_030000_PG, BT_010000_PG)
로그인하면, 시스템은 역할에 맞는 첫 화면을 열어야 한다. [PRD FR-04] [IA 확인된 사항-첫 화면]
- 수용 기준
  1. **전제** QA 관리자 **행동** 로그인 **결과** 관리자 대시보드가 열리고 보류 배치 목록과 배치 상태별 개수가 보인다
  2. **전제** QC 시험 담당자 **행동** 로그인 **결과** 품질시험 홈이 열리고 시험값을 기다리는 배치(생산 중·시험 중)와 최근 기준 이탈(시험)이 보인다
  3. **전제** 생산 담당자 **행동** 로그인 **결과** 제조공정 홈이 열리고 생산 중 배치와 최근 기준 이탈(공정)이 보인다
  4. **전제** 열람자 **행동** 로그인 **결과** 배치 목록이 열린다
  5. **전제** 보여 줄 배치가 없음 **행동** 첫 화면을 연다 **결과** "아직 ~ 배치가 없습니다."가 보인다
  - 승인 대기, 출하 판정 대기, 나에게 배정된 재시험·설비 점검 칸은 기능 002에서 채운다(5절).

### FR-006 역할 권한을 화면과 저장 단계 모두에서 지키기 (P1, 전체)
시스템은 IA "역할별로 쓸 수 있는 화면" 표대로 입력 버튼을 보이거나 숨기고, 권한 없는 저장 시도는 저장 단계에서 거부해야 한다. [PRD FR-05] [IA 역할별로 쓸 수 있는 화면] [ERD 권한 요약] [UJ 에러 E2]
- 수용 기준
  1. **전제** 생산 담당자 **행동** 배치 상세를 연다 **결과** 시험값 입력 버튼이 없고 공정 조건 입력·배치 보류 버튼이 있다
  2. **전제** 생산 담당자 계정 **행동** 화면을 거치지 않고 시험값 저장을 직접 시도한다 **결과** 저장되지 않는다
  3. **전제** 권한 없는 저장이 거부됨 **행동** — **결과** 화면에 "이 작업은 ~만 할 수 있습니다."가 보이고 자료는 바뀌지 않는다

### FR-007 제품과 기준값 (P2, PD_010000_PG, PD_010200_PG, PD_010201_MD)
시스템은 제품 목록·상세에서 시험 항목과 공정 조건 항목의 기준값을 보여 주고, QA 관리자만 기준값을 등록·수정할 수 있게 해야 한다. [PRD FR-06] [ERD specification]
- 수용 기준
  1. **전제** 처음 설치한 상태 **행동** 제품 목록을 연다 **결과** 예시 제품 3개가 보이고, 각 제품 상세에 시험 항목과 공정 조건 항목의 기준 범위(단위 포함)가 보인다
  2. **전제** QA 관리자 **행동** 기준값 등록에서 최솟값 102, 최댓값 98을 넣는다 **결과** 저장되지 않고 "최솟값이 최댓값보다 클 수 없습니다."가 칸 옆에 보인다
  3. **전제** 순도 측정값 97.5(당시 기준 98.0~102.0, 기준 이탈)가 있음 **행동** QA 관리자가 기준을 97.0~102.0으로 바꾼다 **결과** 이미 있는 측정값의 판정은 "기준 이탈" 그대로이고, 새로 넣는 값부터 바뀐 기준으로 판정된다 [ERD measurement.result]

### FR-008 배치 등록·목록·상세 (P1, BT_010000_PG, BT_010100_MD, BT_010200_PG, BT_010201_TB, BT_010202_TB, BT_010204_TB)
시스템은 배치를 등록하고, 배치 상태로 거른 목록과 탭이 있는 상세를 보여 줘야 한다. [PRD FR-07] [ERD batch]
- 수용 기준
  1. **전제** 생산 담당자 또는 QA 관리자 **행동** 배치번호와 제품을 넣어 등록한다 **결과** 배치 목록에 "생산 중"으로 나타난다
  2. **전제** 배치번호 A-001이 이미 있음 **행동** A-001로 또 등록한다 **결과** 저장되지 않고 "이미 있는 배치번호입니다."가 보인다
  3. **전제** 배치 목록 **행동** 상태 "보류"로 거른다 **결과** 보류 배치만 보인다. 상태는 글자와 색으로 함께 표시된다
  4. **전제** 배치 상세 **행동** 주소 끝을 `?tab=tests`처럼 바꿔 연다 **결과** 그 탭이 바로 열린다
  5. **전제** 배치 상세 **행동** 연다 **결과** 화면 위쪽에 배치번호, 제품, 배치 상태, 열린 품질 이슈 수가 보인다 [IA 배치 상세 콘텐츠 우선순위]

### FR-009 시험값 자동 판정 (P1, BT_010206_MD, BT_010202_TB)
QC 시험 담당자가 시험값을 저장하면, 시스템은 기준값과 비교해 적합·기준 이탈을 판정하고, 기준 이탈이면 품질 이슈(발생 구분: 시험) 1개를 열고 배치를 보류해야 한다. [PRD FR-08] [UJ CUJ-01 MOT] [ERD measurement, quality_issue]
- 수용 기준
  1. **전제** 시험값 입력 창 **행동** 시험 항목을 고른다 **결과** 그 항목의 기준 범위와 단위가 입력 칸 옆에 보인다
  2. **전제** 순도 기준 98.0~102.0 **행동** 97.2 저장 **결과** 시험 결과 탭에 "기준 이탈"이 글자와 색으로 보이고, 품질 이슈가 1개 열리고, 배치 상태가 "보류"가 된다
  3. **전제** 같은 기준 **행동** 99.6 저장 **결과** "적합"이 보이고 품질 이슈가 생기지 않는다
  4. **전제** 저장 중 **행동** 저장 버튼을 다시 누른다 **결과** 같은 값이 두 번 저장되지 않는다 [UJ CUJ-01 1단계 성공 기준]

### FR-010 첫 시험값이 들어오면 시험 중 (P1, BT_010200_PG)
"생산 중"인 배치에 첫 시험값이 저장되면, 시스템은 배치 상태를 "시험 중"으로 바꿔야 한다. 그 시험값이 기준 이탈이면 "보류"가 된다. [ERD batch 배치 상태 규칙 (Q1 확정)]
- 수용 기준
  1. **전제** 생산 중 배치 **행동** 적합한 시험값 저장 **결과** 배치 상태가 "시험 중"
  2. **전제** 생산 중 배치 **행동** 기준 이탈 시험값 저장 **결과** 배치 상태가 "보류"

### FR-011 공정 조건 자동 판정 (P2, BT_010205_MD, BT_010201_TB)
생산 담당자가 공정 조건을 저장하면, 시스템은 기준이 있는 항목마다 판정하고, 하나라도 기준 이탈이거나 설비 상태가 "이상"이면 품질 이슈(발생 구분: 공정) 1개를 열고 배치를 보류해야 한다. [PRD FR-09] [UJ CUJ-02 MOT] [ERD process_record]
- 수용 기준
  1. **전제** 공정 온도 기준 20~25℃ **행동** 공정 온도 27, 설비 상태 "이상"을 함께 저장 **결과** 품질 이슈가 1개만 열리고, 그 이슈에 공정 온도와 설비 상태 두 가지가 이탈 항목으로 보이며, 배치가 "보류"가 된다
  2. **전제** 같은 기준 **행동** 공정 온도 22, 설비 상태 "정상" **결과** 품질 이슈가 생기지 않는다
  3. **전제** 공정 조건 입력 창 **행동** 생산량을 넣는다 **결과** 기준 없이 기록만 된다 [ERD Q4 확정]

### FR-012 직접 보류 (P2, BT_010207_MD)
생산 담당자나 QA 관리자가 사유를 적어 보류하면, 시스템은 배치 상태를 "보류"로 바꾸고 사유를 배치 상세에 보여 줘야 한다. [PRD FR-10] [ERD batch.hold_reason]
- 수용 기준
  1. **전제** 배치 보류 창 **행동** 사유를 비운 채 저장 **결과** 저장되지 않고 "보류 사유를 입력해 주세요."가 보인다
  2. **전제** 시험 중 배치 **행동** 사유 "포장 라인 점검"으로 보류 **결과** 배치 상태가 "보류"이고 상세 위쪽에 사유가 보인다

### FR-013 업무 이력 자동 기록 (P1, BT_010204_TB)
자료가 만들어지거나 바뀔 때마다, 시스템은 누가(이름·역할), 언제, 무엇을, 바뀌기 전·후를 업무 이력으로 남기고, 아무도 고치거나 지울 수 없게 해야 한다. [PRD FR-16] [ERD work_history]
- 수용 기준
  1. **전제** 기준 이탈 시험값 저장 **행동** 배치 상세의 업무 이력 탭을 연다 **결과** 측정값 입력, 품질 이슈 생성, 배치 상태 변경(→ 보류)이 최근순으로 보이고 각각 이름·역할·시각이 있다
  2. **전제** QA 관리자 계정 **행동** 업무 이력 한 줄을 고치거나 지우려 한다 **결과** 바뀌지 않는다
  3. **전제** QA 관리자가 역할을 지정함 **행동** — **결과** 역할 지정도 업무 이력에 남는다

### FR-014 저장 실패 복구 (P1, 모든 입력 창)
저장에 실패하면, 시스템은 입력 창과 입력값을 그대로 두고 다시 저장할 수 있게 해야 하며, 측정값·품질 이슈·배치 상태·업무 이력 중 일부만 바뀐 상태를 남기지 않아야 한다. [PRD FR-17] [UJ 에러 E1]
- 수용 기준
  1. **전제** 인터넷 연결 끊김 **행동** 시험값 저장 **결과** "저장하지 못했습니다. 인터넷 연결을 확인한 뒤 다시 저장해 주세요."가 보이고 입력값이 남아 있다
  2. **전제** 위 상태에서 연결 복구 **행동** 다시 저장 **결과** 측정값·품질 이슈·배치 상태·업무 이력이 한 번씩만 생긴다

### FR-015 예시 자료 (P1, BT_010000_PG, PD_010000_PG)
처음 설치했을 때, 시스템은 가상 예시 제품 3개(기준값 포함)와 여러 상태의 가상 예시 배치를 갖고 있어야 한다. [PRD FR-06] [문제정의 머리말-가상 자료] [PRD FR-24]
- 수용 기준
  1. **전제** 처음 설치 **행동** 배치 목록을 연다 **결과** 생산 중, 시험 중, 보류 배치가 각각 1개 이상 보인다
  2. **전제** 예시 자료 **행동** 제품·배치 이름을 본다 **결과** 실제 회사·제품 이름이 아니다

### 경계·예외 상황
- 시험값이 기준 최솟값·최댓값과 정확히 같음 (예: 98.0, 102.0): 적합 [PRD FR-08]
- 시험값이 비어 있거나 숫자가 아님 ("9 8", "abc"): 저장하지 않고 칸 옆에 "숫자로 입력해 주세요." [PRD FR-08]
- 음수, 소수 여러 자리: 숫자면 받아서 그대로 판정한다 (기준이 음수일 수 있는 공정 온도 대비) [ERD measurement.value]
- 기준값 최솟값 > 최댓값: 저장하지 않음 [PRD FR-06]
- 같은 제품·같은 구분에 같은 이름의 기준 항목: 저장하지 않고 "이미 있는 항목입니다." [ERD specification.item_name]
- 배치번호 중복: 저장하지 않음 [PRD FR-07]
- 공정 조건 여러 항목 동시 이탈: 품질 이슈 1개, 이탈 항목 모두 기록 [PRD FR-09]
- 설비 상태만 "이상"이고 숫자 항목은 모두 적합: 기준 이탈로 보고 품질 이슈 1개 [PRD FR-09]
- 같은 배치의 다른 시험 항목에서 또 기준 이탈: 새 품질 이슈 1개 더 (이슈는 기준 이탈 하나 단위) [GLOSSARY 품질 이슈]
- 같은 배치·같은 시험 항목에 이미 측정값이 있는데 또 입력: 못 넣는다. 입력 목록에서 "입력됨"으로 표시하고, 다시 재는 것은 기능 002의 재시험 조치로만 (Q10 확정)
- 출하 가능·폐기 배치에 시험값·공정 조건 입력이나 보류: 못 한다. 읽기만 (Q11 확정)
- 열람자가 입력 창 주소로 직접 들어옴: 입력 창이 열리지 않고 권한 안내 [UJ 에러 E2]
- QA 관리자가 한 명뿐일 때 자기 역할 변경: 막음 [UJ README 정한 사항]
- 저장 중 같은 버튼 두 번 누름: 한 번만 저장 [UJ CUJ-01 1단계]

### 핵심 자료
- **사용자**: 로그인한 사람. 갖는 정보: 이름, 이메일, 역할, 처음 로그인한 시각 [ERD profile]
- **제품**: 예시 제품. 갖는 정보: 품목명, 주성분, 제조원 [ERD product]
- **기준값**: 제품별 시험 항목·공정 조건 항목의 허용 범위. 갖는 정보: 구분(시험·공정), 항목 이름, 단위, 최솟값, 최댓값 [ERD specification]
- **배치**: 갖는 정보: 배치번호, 제품, 배치 상태, 직접 보류 사유, 등록한 사람 [ERD batch]
- **공정 기록**: 공정 조건 입력 한 번. 갖는 정보: 생산량, 설비 상태, 기록한 사람·시각 [ERD process_record]
- **측정값**: 갖는 정보: 기준 항목, 값, 판정, 연결된 품질 이슈, 잰 사람·시각 [ERD measurement]
- **품질 이슈**: 이 기능에서는 자동으로 여는 것까지만. 갖는 정보: 배치, 발생 구분, 열림/닫힘, 연 시각 [ERD quality_issue]
- **업무 이력**: 갖는 정보: 누가(이름·역할), 언제, 무엇을, 대상, 관련 배치, 바뀌기 전·후 [ERD work_history]

## 4. 성공 기준

### 완료 확인
- **SC-001**: QC 시험 담당자로 로그인 → 품질시험 홈 → 예시 배치 열기 → 시험값 입력에서 순도 97.2 저장 → 같은 화면에서 "기준 이탈"과 배치 "보류"가 보이고, 업무 이력 탭에 3줄(측정값 입력, 품질 이슈 생성, 상태 변경)이 보인다 (관련: FR-001, FR-005, FR-008, FR-009, FR-013)
- **SC-002**: 같은 흐름에서 99.6을 저장하면 "적합"이고 품질 이슈가 생기지 않는다. 98.0과 102.0도 "적합"이다 (관련: FR-009, FR-010)
- **SC-003**: 처음 쓰는 구글 계정으로 로그인하면 읽기 전용 안내가 있는 배치 목록이 열리고, QA 관리자가 역할을 QC 시험 담당자로 바꾸면 그 계정이 다음 화면 이동에서 품질시험 홈으로 간다 (관련: FR-002, FR-003, FR-004, FR-005)
- **SC-004**: 생산 담당자 계정으로 시험값 저장을 화면 밖에서 직접 시도하면 거부되고, 열람자 계정에는 입력 버튼이 하나도 없다 (관련: FR-006)
- **SC-005**: 생산 담당자로 공정 온도 27(기준 20~25)과 설비 상태 "이상"을 함께 저장하면 품질 이슈가 1개만 생기고 배치가 "보류"가 된다. 사유를 적어 직접 보류하면 상세에 사유가 보인다 (관련: FR-011, FR-012)
- **SC-006**: QA 관리자가 기준값을 바꿔도 이미 있는 측정값의 판정은 그대로이고, 최솟값 > 최댓값은 저장되지 않는다 (관련: FR-007)
- **SC-007**: 인터넷을 끊고 시험값을 저장하면 안내와 함께 입력값이 남고, 다시 연결해 저장하면 기록이 한 번씩만 생긴다 (관련: FR-014)
- **SC-008**: 처음 설치한 상태에서 예시 제품 3개와 생산 중·시험 중·보류 예시 배치가 보이고, 휴대폰 폭(375px)에서 가로 스크롤 없이 위 흐름을 할 수 있다 (관련: FR-008, FR-015)
