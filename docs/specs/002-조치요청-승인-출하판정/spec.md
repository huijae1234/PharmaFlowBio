## 1. 해결하려는 문제
**지금 방식:** 기능 001까지는 기준 이탈이 나면 품질 이슈가 열리고 배치가 보류되는 데서 멈춘다. 그 뒤의 조치·승인·출하 판정은 앱 밖(메일·엑셀)에서 해야 한다. [spec 001 §5 제외 범위] [UJ CUJ-01 4~6단계 As-Is]
**막히는 지점:**
- 승인 대기 건이 메일에 묻히고, 누가 언제 승인·반려했는지 한곳에서 볼 수 없다. [PRD §2-3] [UJ CUJ-01 4단계]
- 출하 판정 직전에 "끝나지 않은 이슈가 있는가"를 여러 기록에서 확인해야 해 약 30분이 걸리고 놓치기 쉽다(가설). [PRD §2-1] [문제정의 확인할 것 하나] [Intent Q9]
- 열린 이슈가 남은 배치를 실수로 출하해도 막을 장치가 없다. [UJ CUJ-01 MOT "출하 판정"]

## 2. 주요 사용자
**사용자:** QA 관리자(핵심), QC 시험 담당자, 생산 담당자 [PRD §4] [GLOSSARY 사람]

### 이야기 1 — 이슈를 닫고 1분 안에 출하 판정한다 (P1)
- 장면: 기준 이탈로 보류된 배치에 재시험 조치를 요청하고, QA 관리자가 승인·배정하고, 배정된 QC 시험 담당자가 재시험 결과를 넣어 이슈를 닫은 뒤, QA 관리자가 배치 상세에서 출하 판정을 한다. [UJ CUJ-01 3~6단계] [IA QI_010101_MD, QI_010102_MD, QI_010104_MD, BT_010208_MD]
- 왜 P1인가: CUJ-01의 두 번째 결정적 순간(출하 판정)이자 문제정의의 "확인할 것 하나"다. 이것이 없으면 기능 001의 이슈가 끝나지 않는다. [문제정의 확인할 것 하나]
- 혼자 확인하는 방법: 기능 001에서 보류된 배치(예: PF-2610-001)로 조치 요청 → 승인 → 재시험 99.6 → 이슈 닫기 → 출하 가능까지 진행하고, 업무 이력에 모든 단계가 남는지 본다.

### 이야기 2 — 반려된 요청을 고쳐 다시 낸다 (P1)
- 장면: QA 관리자가 사유를 적어 조치 요청을 반려하면, 요청자가 자기 첫 화면에서 반려 사유를 보고 고쳐 다시 제출한다. [UJ E3] [IA QI_010103_MD]
- 왜 P1인가: 승인 흐름의 실패 경로다. 해피 패스만 만들지 않는다. [PRD FR-13]
- 혼자 확인하는 방법: 조치 요청을 반려하고, 요청자 계정 첫 화면에 "반려됨 — 사유"가 보이는지, 다시 제출하면 승인 대기로 돌아오는지 본다.

### 이야기 3 — QA 관리자가 한눈에 할 일을 본다 (P1)
- 장면: QA 관리자가 로그인하면 관리자 대시보드에 승인 대기, 출하 판정 대기, 보류 배치, KPI 숫자가 보이고, 관리 메뉴에서 승인 대기 목록과 전체 업무 이력을 본다. [IA HM_010000_PG, AD_010000_PG, AD_030000_PG] [PRD FR-04, FR-16]
- 왜 P1인가: "승인 대기 건이 메일에 묻힘"(문제 2)을 직접 푼다.
- 혼자 확인하는 방법: 조치 요청 1건을 만든 뒤 관리자 대시보드와 승인 대기 화면에 그 건이 보이는지 본다.

### 이야기 4 — 담당자가 자기에게 배정된 일을 본다 (P2)
- 장면: QC 시험 담당자는 품질시험 홈에서 "나에게 배정된 재시험"을, 생산 담당자는 제조공정 홈에서 "나에게 배정된 설비 점검"을 보고 바로 조치 결과를 넣는다. [IA HM_020000_PG, HM_030000_PG] [PRD FR-04, FR-13 "배정된 담당자의 첫 화면에 그 일이 보인다"]
- 왜 P2인가: 품질 이슈 목록에서도 찾을 수 있어 이야기 1은 이것 없이 된다.
- 혼자 확인하는 방법: 재시험을 QC 시험 담당자 계정에 배정하고 그 계정 첫 화면에 보이는지 본다.

## 3. 핵심 기능과 요구사항

### FR-001 품질 이슈 목록 (P1, QI_010000_PG)
시스템은 품질 이슈를 최근순으로 보여 주고, 열림/닫힘과 발생 구분(시험·공정)으로 거를 수 있게 해야 한다. [PRD FR-11] [IA QI_010000_PG]
- 수용 기준
  1. **전제** 로그인한 사람 **행동** 품질 이슈 메뉴를 연다 **결과** 이슈마다 배치번호, 발생 구분, 이탈 항목, 상태(글자+색), 연 시각, 열린 조치 요청 수가 보인다
  2. **전제** 목록 **행동** "열림"과 "시험"으로 거른다 **결과** 열린 시험 이슈만 보이고 주소에 거르기가 남는다
  3. **전제** 이슈가 없음 **행동** 연다 **결과** "아직 품질 이슈가 없습니다."

### FR-002 품질 이슈 상세 (P1, QI_010100_PG)
시스템은 품질 이슈 상세에 기준 이탈 내용(측정값·당시 기준·판정, 공정 이탈이면 공정 기록과 설비 상태), 조치 요청 목록과 상태, 조치 결과(재시험 측정값 포함), 이 이슈의 업무 이력을 보여 줘야 한다. [PRD FR-11] [IA QI_010100_PG] [ERD quality_issue.process_record_id]
- 수용 기준
  1. **전제** 순도 97.2로 열린 시험 이슈 **행동** 상세를 연다 **결과** "순도 97.2% (기준 98.0~102.0%) 기준 이탈", 배치번호 링크, 상태 "열림"이 보인다
  2. **전제** 설비 상태만 "이상"으로 열린 공정 이슈 **행동** 상세를 연다 **결과** 그 공정 기록(시각, 설비 상태 "이상", 공정 항목 값)이 보인다
  3. **전제** 반려된 조치 요청 **행동** 상세를 연다 **결과** "반려됨 — 사유: …"가 보인다 [UJ E3]

### FR-003 조치 요청 등록 (P1, QI_010101_MD)
열린 품질 이슈에서 QC 시험 담당자·생산 담당자·QA 관리자가 조치 종류를 고르고 내용을 적어 제출하면, 시스템은 조치 요청을 "승인 대기"로 만들어야 한다. [PRD FR-12] [ERD action_request]
- 수용 기준
  1. **전제** 열린 이슈 상세 **행동** 조치 요청 등록을 연다 **결과** 이슈 정보(배치, 이탈 항목, 측정값)가 자동으로 채워져 있고 조치 종류 4가지(재시험·설비 점검·원료 확인·배치 폐기)를 고를 수 있다
  2. **전제** 조치 종류를 고르지 않음 **행동** 제출 **결과** 저장되지 않고 "조치 종류를 골라 주세요."
  3. **전제** 제출 **행동** — **결과** 상태 "승인 대기", 업무 이력 "조치 요청 등록"
  4. **전제** 닫힌 이슈 또는 열람자 **행동** — **결과** 조치 요청 등록 버튼이 없고, 저장 단계에서도 거부된다

### FR-004 조치 요청 승인과 담당자 배정 (P1, QI_010102_MD, AD_010000_PG)
QA 관리자가 승인 대기인 조치 요청을 승인하면, 시스템은 담당자를 반드시 배정하게 하고 상태를 "승인됨"으로 바꿔야 한다. [PRD FR-13] [UJ CUJ-01 4단계]
- 수용 기준
  1. **전제** 승인 대기 요청 **행동** 담당자를 고르지 않고 승인 **결과** 저장되지 않고 "담당자를 골라 주세요."
  2. **전제** 재시험 요청 **행동** 담당자 고르기 **결과** 조치 종류에 맞는 역할의 사람만 고를 수 있다 (Q18 가정: 재시험 → QC 시험 담당자·QA 관리자, 설비 점검 → 생산 담당자·QA 관리자, 원료 확인 → QC·생산 담당자·QA 관리자, 배치 폐기 → QA 관리자)
  3. **전제** 승인 **행동** — **결과** 상태 "승인됨", 배정된 담당자 이름이 보이고 업무 이력 "조치 요청 승인"
  4. **전제** QA 관리자가 아닌 사람 **행동** 승인을 시도 **결과** 버튼이 없고 저장 단계에서도 거부된다

### FR-005 조치 요청 반려와 다시 제출 (P1, QI_010103_MD)
QA 관리자가 사유를 적어 반려하면, 시스템은 요청을 "반려됨"으로 바꾸고 요청자가 내용을 고쳐 다시 제출할 수 있게 해야 한다. [PRD FR-13] [UJ E3]
- 수용 기준
  1. **전제** 반려 창 **행동** 사유를 비운 채 반려 **결과** 저장되지 않고 "반려 사유를 입력해 주세요."
  2. **전제** 반려됨 **행동** 요청자가 첫 화면을 연다 **결과** "반려됨 — 사유: …"와 다시 제출 버튼이 보인다
  3. **전제** 반려됨 **행동** 요청자가 조치 종류·내용을 고쳐 다시 제출 **결과** 상태 "승인 대기", 업무 이력에 반려와 재제출이 모두 남는다
  4. **전제** 반려됨 **행동** 요청자가 아닌 사람이 다시 제출을 시도 **결과** 거부된다

### FR-006 동시 처리 막기 (P2, QI_010102_MD, QI_010103_MD)
두 사람이 같은 조치 요청을 거의 동시에 승인·반려하면, 시스템은 먼저 처리된 것만 남기고 나중 사람에게 알려야 한다. [PRD FR-25] [UJ E5]
- 수용 기준
  1. **전제** 같은 승인 대기 요청을 두 화면에서 엶 **행동** 한 화면에서 승인한 뒤 다른 화면에서 반려 **결과** 반려되지 않고 "다른 사람이 먼저 처리했습니다. 화면을 새로 고칩니다."가 보이며 최신 상태가 뜬다

### FR-007 조치 결과 입력 (P1, QI_010104_MD)
배정된 담당자나 QA 관리자가 승인된 조치 요청에 결과를 넣으면, 시스템은 요청을 "완료"로 바꿔야 한다. 재시험이면 측정값을 받아 다시 판정해야 한다. [PRD FR-14] [UJ CUJ-01 5단계] [GLOSSARY 조치 결과]
- 수용 기준
  1. **전제** 순도 이탈 이슈의 재시험 요청(승인됨, 나에게 배정) **행동** 조치 결과 입력 **결과** 시험 항목 "순도"와 기준 범위가 미리 정해져 있고 측정값을 넣는다
  2. **전제** 같은 창 **행동** 99.6 저장 **결과** 판정 "적합", 요청 "완료", 측정값이 같은 이슈에 "재시험"으로 붙는다
  3. **전제** 같은 창 **행동** 97.5 저장 **결과** 판정 "기준 이탈", 새 품질 이슈가 생기지 않고 같은 이슈에 붙으며 이슈는 열린 채로 "다른 조치 요청" 안내가 보인다
  4. **전제** 설비 점검·원료 확인·배치 폐기 요청 **행동** 결과 내용을 비운 채 저장 **결과** 저장되지 않고 "조치 결과를 입력해 주세요."
  5. **전제** 배정되지 않은 QC·생산 담당자 **행동** 결과 입력을 시도 **결과** 버튼이 없고 저장 단계에서도 거부된다

### FR-008 품질 이슈 닫기 (P1, QI_010100_PG)
배정된 담당자나 QA 관리자가 이슈를 닫으면, 시스템은 열린 조치 요청(승인 대기·승인됨)이 없을 때만 닫고, 그 배치의 열린 이슈가 0이 되면 배치 상태 규칙에 따라 보류를 풀어야 한다. [PRD FR-14] [ERD batch 배치 상태 규칙 (Q2)]
- 수용 기준
  1. **전제** 승인됨 상태의 조치 요청이 남은 이슈 **행동** 이슈 닫기 **결과** 닫히지 않고 "끝나지 않은 조치 요청이 있어 닫을 수 없습니다."
  2. **전제** 조치 요청이 모두 완료·반려된 이슈 **행동** 이슈 닫기 **결과** 상태 "닫힘", 닫은 사람·시각, 업무 이력 "품질 이슈 닫기"
  3. **전제** 그 배치의 마지막 열린 이슈이고 직접 보류 사유가 없음 **행동** 이슈 닫기 **결과** 배치 상태가 "보류"에서 "시험 중"으로 바뀐다
  4. **전제** 직접 보류 사유가 있는 배치 **행동** 마지막 이슈를 닫음 **결과** 배치는 "보류"로 남는다 (QA 관리자가 출하 판정에서 정한다)
  5. **전제** 그 이슈의 조치 요청에 배정된 적 없는 QC·생산 담당자 **행동** 이슈 닫기를 시도 **결과** 버튼이 없고 저장 단계에서도 거부된다. 완료된 조치 요청이 하나도 없으면 QA 관리자도 닫을 수 없다 (Q19 확정)

### FR-009 출하 판정 (P1, BT_010200_PG, BT_010208_MD)
QA 관리자가 배치 상세에서 출하 판정을 하면, 시스템은 "출하 가능" 또는 "폐기"로 배치 상태를 바꾸고, 열린 품질 이슈가 있으면 "출하 가능"을 막아야 한다. [PRD FR-15] [UJ CUJ-01 MOT "출하 판정"]
- 수용 기준
  1. **전제** 배치 상세 **행동** 연다 **결과** 탭을 누르지 않아도 화면 위쪽에 열린 품질 이슈 수, 조치 요청 상태 요약(승인 대기 N·승인됨 N), 최근 업무 이력 3줄이 보인다
  2. **전제** 열린 이슈 1건 이상 **행동** 출하 판정 창 **결과** "출하 가능"을 고를 수 없고 "열린 품질 이슈가 N건 있어 출하할 수 없습니다."가 보인다. "폐기"는 고를 수 있다
  3. **전제** 출하 가능 조건 충족 **행동** "출하 가능" **결과** 배치 상태 "출하 가능", 업무 이력 "출하 판정", 이후 모든 입력 버튼이 사라진다 (spec 001 Q11)
  4. **전제** 열린 이슈는 0건이지만 시험 항목 하나가 측정값이 없거나 마지막 값이 기준 이탈 **행동** 출하 판정 창 **결과** "출하 가능"을 고를 수 없고 "시험이 끝나지 않은 항목이 있습니다: 용출률"처럼 이유가 보인다 (Q17 확정)
  5. **전제** QA 관리자가 아닌 사람 **행동** — **결과** 출하 판정 버튼이 없고 저장 단계에서도 거부된다

### FR-010 관리자 대시보드 보강 (P1, HM_010000_PG)
시스템은 관리자 대시보드에 승인 대기 조치 요청, 출하 판정 대기 배치, KPI 숫자(열린 품질 이슈 수, 이번 주 기준 이탈 수, 평균 처리 일수)를 더해야 한다. [PRD FR-04] [IA 관리자 대시보드 콘텐츠 우선순위]
- 수용 기준
  1. **전제** 승인 대기 2건 **행동** 대시보드를 연다 **결과** "승인 대기 2"와 목록(배치번호, 조치 종류, 요청자, 요청 시각)이 맨 위에 보인다
  2. **전제** 시험 중이고 열린 이슈가 없는 배치 **행동** — **결과** "출하 판정 대기" 목록에 보인다
  3. **전제** — **행동** — **결과** KPI 숫자 3개가 보인다. 평균 처리 일수 = 닫힌 이슈의 (닫은 시각 − 연 시각) 평균, 소수 첫째 자리

### FR-011 승인 대기 화면 (P1, AD_010000_PG)
시스템은 QA 관리자에게 승인 대기 조치 요청 전체를 오래된 순으로 보여 주고, 각 줄에서 승인·반려 창을 열 수 있게 해야 한다. [PRD FR-13] [IA AD_010000_PG]
- 수용 기준
  1. **전제** QA 관리자 **행동** 관리 > 승인 대기 **결과** 배치번호, 이탈 항목, 조치 종류, 내용, 요청자, 요청 시각과 승인·반려 버튼
  2. **전제** QA 관리자가 아닌 사람 **행동** 주소를 직접 연다 **결과** "이 화면은 QA 관리자만 볼 수 있습니다."

### FR-012 첫 화면의 내 일 (P2, HM_020000_PG, HM_030000_PG)
시스템은 QC 시험 담당자·생산 담당자의 첫 화면에 나에게 배정된 승인된 조치 요청과 내가 낸 요청 중 반려된 것을 보여 줘야 한다. [PRD FR-04, FR-13] [UJ E3]
- 수용 기준
  1. **전제** 재시험이 나에게 배정됨 **행동** 품질시험 홈 **결과** "나에게 배정된 재시험"에 그 건과 "조치 결과 입력" 링크가 보인다
  2. **전제** 설비 점검이 나에게 배정됨 **행동** 제조공정 홈 **결과** "나에게 배정된 설비 점검"에 보인다
  3. **전제** 내가 낸 요청이 반려됨 **행동** 첫 화면 **결과** "반려된 내 요청"에 사유와 함께 보인다

### FR-013 전체 업무 이력 (P2, AD_030000_PG)
시스템은 QA 관리자에게 모든 업무 이력을 최근순으로 보여 주고, 사람·배치번호·기간으로 거를 수 있게 해야 한다. [PRD FR-16] [IA AD_030000_PG]
- 수용 기준
  1. **전제** QA 관리자 **행동** 관리 > 전체 업무 이력 **결과** 시각, 이름(역할), 행동, 배치번호가 최근순 50개씩
  2. **전제** 같은 화면 **행동** 사람 "윤○○", 기간 오늘로 거른다 **결과** 그 조건의 이력만
  3. **전제** 역할 지정처럼 배치가 없는 이력 **행동** — **결과** 배치번호 칸이 비어 있고 행동은 보인다

### FR-014 측정 당시 기준 보여 주기 (P1, BT_010202_TB, QI_010100_PG)
시스템은 측정값마다 그 측정을 판정할 때 쓴 기준 범위를 함께 저장하고 보여 줘야 한다. 나중에 기준값이 바뀌어도 그 측정값 옆에는 당시 기준이 보여야 한다. [Intent Q16] [spec 001 실패와 조치 14] [ERD v0.5 measurement.applied_min_value]
- 수용 기준
  1. **전제** 함량 94.9(당시 기준 95~105, 기준 이탈) **행동** QA 관리자가 기준을 94~105로 바꾼 뒤 시험 결과 탭을 연다 **결과** 그 줄에 "기준 95~105%", 판정 "기준 이탈"이 보인다

### 경계·예외 상황
- 열린 조치 요청이 남은 이슈 닫기: 막음 (FR-008)
- 반려된 요청만 남은 이슈 닫기: 반려됨은 끝난 요청으로 보고 닫을 수 있다 (Q19 가정)
- 재시험 결과가 또 기준 이탈: 같은 이슈에 붙고 이슈는 열린 채 (PRD FR-14)
- 재시험 요청을 공정 이슈에 등록: 막음 (가정, Q20)
- 승인과 반려가 동시에: 먼저 것만 (FR-006)
- 같은 이슈에 승인 대기 요청이 여러 개: 허용 (예: 재시험과 원료 확인을 동시에)
- 출하 판정이 끝난 배치의 이슈에 조치 요청: 막음 (spec 001 Q11과 같은 규칙)
- 배정된 담당자가 그 뒤 열람자로 바뀜: 그 사람은 결과를 넣을 수 없고, QA 관리자가 넣을 수 있다 (가정)
- 반려 사유·조치 결과 내용이 공백만: 빈 값으로 봄
- 배치 폐기 조치 요청이 완료돼도 배치 상태는 바뀌지 않음 (ERD Q5)

### 핵심 자료
- **조치 요청**: 품질 이슈 하나에 여러 개. 갖는 정보: 조치 종류, 내용, 상태(승인 대기·승인됨·반려됨·완료), 요청자·요청 시각, 담당자, 검토자·검토 시각, 반려 사유, 조치 결과 내용·완료 시각 [ERD action_request]
- **재시험 측정값**: 조치 결과로 넣은 측정값. 이슈와 조치 요청에 연결 [ERD measurement.action_request_id]
- **품질 이슈**: 열림/닫힘, 닫은 사람·시각 [ERD quality_issue]
- **배치**: 출하 판정으로 출하 가능·폐기 [ERD batch]
- **측정 당시 기준**: 측정값마다 판정에 쓴 최솟값·최댓값 (Q16)

## 4. 성공 기준

### 완료 확인
- **SC-001**: 보류된 배치에서 조치 요청(재시험) → QA 관리자 승인(QC 시험 담당자 배정) → 재시험 99.6 → 이슈 닫기 → 배치 "시험 중" → 출하 판정 "출하 가능"까지 끊김 없이 되고, 배치 상세 업무 이력에 모든 단계가 순서대로 남는다 (관련: FR-002, FR-003, FR-004, FR-007, FR-008, FR-009)
- **SC-002**: 열린 이슈가 1건이라도 있으면 "출하 가능"을 고를 수 없고 이유가 글로 보이며, 데이터베이스에 직접 시도해도 거부된다 (관련: FR-009)
- **SC-003**: 반려 사유를 적어 반려하면 요청자 첫 화면에 사유가 보이고, 고쳐 다시 내면 승인 대기로 돌아오며 반려·재제출이 업무 이력에 남는다 (관련: FR-005, FR-012)
- **SC-004**: 재시험 결과가 또 기준 이탈이면 새 이슈 없이 같은 이슈에 붙고, 열린 조치 요청이 있으면 이슈를 닫을 수 없다 (관련: FR-007, FR-008)
- **SC-005**: QA 관리자 대시보드에 승인 대기·출하 판정 대기·KPI가 보이고, 배정된 담당자의 첫 화면에 자기 일이 보인다 (관련: FR-010, FR-011, FR-012)
- **SC-006**: QA 관리자가 아닌 사람은 승인·반려·출하 판정을, 배정되지 않은 사람은 조치 결과 입력을 화면과 저장 단계 모두에서 할 수 없다 (관련: FR-004, FR-005, FR-007, FR-009)
- **SC-007**: 같은 요청을 두 화면에서 동시에 처리하면 나중 쪽에 안내가 뜨고 상태는 하나만 남는다 (관련: FR-006)
- **SC-008**: 전체 업무 이력을 사람·배치·기간으로 거를 수 있고, 기준값을 바꿔도 측정값 옆에 당시 기준이 보인다 (관련: FR-013, FR-014)

## 5. 제외 범위
| 무엇 | 왜 뺐나 | 언제 다시 보나 |
|---|---|---|
| 메일·푸시 알림 (승인 요청, 반려 알림) | PRD 하지 않을 것. 첫 화면 목록으로 대신 | 영영 안 함 |
| 전자서명, 결재 시스템 연동 | PRD 하지 않을 것 | 영영 안 함 |

| 조치 요청 삭제, 품질 이슈 다시 열기 | 문서에 없는 동작. 이력이 끊긴다 | 필요하면 따로 묻기 |
| KPI 차트 | PRD 여유 있으면 (Won't 아님, 이후 범위) | 발표 뒤 |
| 사용 기록, 공공데이터, MSDS, 예시 자료 되돌리기 | 기능 003 | 기능 003 |
| 실험 조건별 결과 비교 | PRD FR-26 Won't | 이번엔 안 함 |
