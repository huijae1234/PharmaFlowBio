> 바뀌는 기존 동작은 하나다: 제품 상세에 "공개 규제 현황" 탭이 하나 늘어난다(허가정보·회수 이력 탭 옆). 판정 규칙, 저장 규칙, 권한, 기존 허가정보·회수 칸은 바꾸지 않는다.
> 이 앱은 국가출하승인이나 GMP 적합 여부를 결정하거나 보증하지 않는다. 식약처가 공개한 정보를 그대로 보여 줄 뿐이다 (PRD 하지 않을 것).

## 1. 해결하려는 문제
**지금 방식:** QA 담당자는 백신 제품의 국가출하승인 이력과 제조사의 GMP 적합판정 유효기간을 식약처 사이트 두 곳에서 따로 찾아본다. [QC 현직 친구 대화: 나라마다 GMP가 달라 QA와 확인] [docs/research.md 6절]
**막히는 지점:**
- 두 정보가 따로 있어, "승인 이력이 있는 제조사의 GMP가 곧 끝나는가"를 한눈에 알 수 없다.
- 이 앱의 제품 상세에는 허가정보와 회수 이력만 있고 규제 정보가 이어져 있지 않다.
- 두 API 모두 이 앱에서 아직 호출한 적이 없다 (조사만 했다).

## 2. 주요 사용자
**사용자:** QA 관리자, QC 시험 담당자 (제품 상세를 읽는 모든 로그인 사용자). [PRD FR-35]

### 이야기 1 — 제품의 공개 규제 현황을 한 카드로 본다 (P1)
- 장면: 허가정보로 등록한 백신 제품의 상세 → "공개 규제 현황" 탭을 연다. 승인 로트 3건(결과일 최근순)과 제조사 GMP 유효기간, 남은 일수가 보이고 출처·조회 시각이 붙는다.
- 왜 P1인가: 사용자가 요청한 핵심("두 API를 합친 인사이트").
- 혼자 확인하는 방법: 시험 모드(spec 019)로 서버를 켜고 시험 자료 제품의 칸을 본다.

### 이야기 2 — GMP가 곧 끝나는 제조사를 놓치지 않는다 (P1)
- 장면: 제조사의 GMP 유효기간이 180일 안이거나 끝났고 승인 이력이 있으면 칸 위에 "QA 확인 필요"가 뜬다. 글자·아이콘·색을 같이 쓴다.
- 왜 P1인가: 사용자가 요청한 인사이트. 숫자(남은 일수)가 판단 근거로 같이 보인다.
- 혼자 확인하는 방법: 시험 자료 5가지(여유·임박·만료·없음·다른 회사)로 배지가 맞게 뜨는지 본다.

### 이야기 3 — "QA 확인 필요"를 QA에게 올린다 (P2)
- 장면: 배지 옆 버튼 "QA에 확인 요청"을 누르면 QA 관리자에게 슬랙·앱 알림이 간다.
- 왜 P2인가: 새 DB 함수와 마이그레이션이 필요하다(클라우드 DB 변경은 별도 승인). 카드만으로도 P1 가치가 있다.
- 혼자 확인하는 방법: 버튼 → 알림 함에 한 줄이 생기는지.

## 3. 핵심 기능과 요구사항

### FR-001 GMP 적합판정서 조회 (P1)
시스템은 제품의 업체명으로 식약처 GMP 적합판정서 발급현황을 서버 함수로 조회해, 업체명·완제/원료 구분·제형군(제조방법)·유효기간을 보여야 한다. [공공데이터 15097207]
- 수용 기준
  1. **전제** 허가정보로 등록한 제품 **행동** 상세의 공개 규제 현황 탭 열기 **결과** 업체명으로 부른 GMP 결과 중 유효기간이 가장 늦은 한 줄과 남은 일수가 보인다
  2. **결과** 제형군(제조방법) 글자를 그대로 보이고, "백신"이 없으면 "백신 제형이 포함되는지 확인 필요"를 같이 보인다 [Q8]
  3. **결과** 0건이면 "이 업체명으로 찾은 GMP 적합판정서가 없습니다. 업체명이 다르게 등록됐을 수 있습니다."
  4. **결과** 로그인 확인·15초 제한·인증키 비노출·실패 안내(불러오는 중·실패·다시 시도·마지막 정상 조회)는 기존 공공데이터 칸과 같다 (spec 006)

### FR-002 국가출하승인 조회 (P1)
시스템은 백신류 제품에 대해 국가출하승인정보를 서버 함수로 조회해 제품명·제조번호·결과일시·유효기간 중 최근 3건을 보여야 한다. [공공데이터 15084883]
- 수용 기준
  1. **전제** 백신류 제품 **결과** 이 API는 제품명으로 거를 수 없어(접수번호만 지원), 자료가 접수 순서로 쌓여 최신이 마지막 쪽에 있으므로(2026-10-29 실제 호출로 확인) 서버가 전체 건수를 먼저 알고 끝 4쪽을 받아 제품명으로 거른다. 칸에 "최근 N건(YYYY-MM-DD 이후 판정, 전체 M건 중) 안에서 찾음, 그보다 오래된 이력은 보지 않음"을 같이 적는다 [Q3]
  2. **전제** 허가정보 조회에서 이 제품 줄의 품목 구분이 백신류가 아님 **결과** "백신류가 아니어서 국가출하승인 정보가 없습니다."만 보이고 승인 API를 부르지 않는다. 그 줄을 못 찾으면(넓은 품목명) 단정하지 않고 승인 API를 부른다 [Q5]
  3. **결과** 찾지 못하면 "조회한 N건(전체 M건) 안에는 승인 이력이 없습니다. 전체를 본 것은 아니라 이력이 없다는 뜻은 아닙니다."
  4. **결과** 모든 글자 앞에 "공개 정보이며 이 앱이 승인하거나 보증하지 않습니다"가 한 줄 보인다

### FR-003 업체명 맞춤 (P1)
시스템은 제품의 업체명과 GMP·승인 결과의 업체명을 비교해, 같은 회사인지 보여야 한다. [사용자 주의 사항: 업체명으로 맞추므로 같은 회사인지 확인 필요, 제조수입업자가 수입사일 수 있음]
- 수용 기준
  1. **결과** 공백·"(주)"·"주식회사"를 빼고 같으면 "같은 업체"
  2. **결과** 한쪽이 다른 쪽을 포함하면 "비슷한 이름: 같은 회사인지 확인 필요"
  3. **결과** 둘 다 아니면 그 줄을 쓰지 않는다 (잘못 이어 붙이지 않는다)
  4. **결과** 제조사가 수입사로 나올 수 있다는 한 줄 안내가 칸 아래에 있다

### FR-004 "QA 확인 필요" 표시 (P1)
시스템은 승인 이력이 있고 GMP 유효기간이 끝났거나 180일 안이면 "QA 확인 필요"를 보이고, 그 근거(남은 일수, 승인 로트 수)를 옆에 보여야 한다. [Q2]
- 수용 기준
  1. **결과** 남은 일수가 0 이하면 "GMP 유효기간 지남", 180일 이하면 "GMP 갱신 확인 필요 (N일 남음)", 그보다 많으면 배지 없음
  2. **결과** 승인 이력이 없거나 GMP를 못 찾으면 배지를 만들지 않고 이유를 글로 보인다 (자동 판정이 아니다)
  3. **결과** 글자 + 아이콘 + 색 배지를 모든 화면과 같은 모양으로 쓴다 (색만으로 구분하지 않음)

### FR-005 QA에게 확인 요청 (P2)
시스템은 "QA 확인 필요"가 떠 있을 때 버튼으로 QA 관리자에게 슬랙·앱 알림을 보내야 한다. [Q6]
- 수용 기준
  1. **결과** 알림 한 줄: "공개 규제 확인 요청 · 제품명 · GMP N일 남음", 누른 사람과 시각이 업무 이력에 남는다
  2. **결과** 같은 제품에 이미 보낸 요청이 열려 있으면 새로 만들지 않는다
  3. **결과** 이것은 로트·품질 이슈를 만들지 않는다 (가상 로트와 연결하지 않음)

### FR-006 시험 자료와 시험 모드 (P1)
시스템은 spec 019의 시험 모드가 GMP·국가출하승인 응답도 돌려주도록 `fixtures/`에 자료를 가져야 한다.
- 수용 기준
  1. **결과** GMP: 정상(여유), 임박, 만료, 0건, 다른 회사 이름, 제형군에 백신 없음. 국가출하승인: 정상, 0건. 오류·XML·깨짐·시간 초과는 기존 자료를 같이 쓴다
  2. **결과** 모든 자료에 "(시험 자료)"가 붙고, 실제 응답 모양이 아니라 공개 문서의 항목 이름을 따른 모양이다. 항목 이름은 공공데이터포털 문서(2026-10-28)로 확인했고, 응답 JSON 구조(header/body)는 첫 실제 호출 뒤 확정한다 [Q9]
  3. **결과** 시험 자료 결과는 "시험 자료" 표시가 붙고 마지막 정상 조회로 보관하지 않는다 (spec 019 FR-003)

### FR-007 기존 동작 유지 (P1)
- 수용 기준
  1. **결과** 허가정보·회수 칸, 제품 등록, 관리자 대시보드 회수 공지는 지금과 같다
  2. **결과** 가상 제품(허가정보로 등록하지 않은 제품)에는 새 칸이 없고 기존 안내만 보인다
  3. **결과** 전체 시험이 통과한다 (현재 225개 + 새 시험)

### FR-008 승인 로트와 회수 공지 대조 (P1)
시스템은 이 제품의 국가출하승인 로트 제조번호가 같은 제품의 회수 공지 제조번호에 있는지 대조해, 겹치면 그 로트를 보여야 한다. [사용자 요청: 두 API로 복합 인사이트, 회수 API는 기능 003]
- 수용 기준
  1. **전제** 승인 이력의 제조번호가 같은 품목기준코드 회수 공지의 제조번호 글자에 들어 있음 **결과** "승인된 로트 N건이 회수됨"과 제조번호·회수 명령일·회수 사유를 보인다
  2. **결과** 회수 공지가 있지만 겹치는 로트가 없으면 "회수 공지 N건 · 조회한 승인 이력의 제조번호와 겹치지 않음"만 보인다 (이상이 없다는 뜻이 아니라는 말을 함께)
  3. **결과** 회수 공지를 불러오지 못하면 대조하지 못했다고 한 줄 보이고 승인·GMP 칸은 그대로 보인다
  4. **결과** 제조번호 대조는 공백·쉼표·괄호로 나눈 낱말이 글자 그대로 같을 때만 맞다고 본다. "A1~A9" 같은 범위 표기는 풀지 않는다 [Q10]
  5. **결과** 승인 이력은 화면에 3건만 보여도 대조에는 찾은 전체(최근 끝 4쪽, 약 400건 안)를 쓴다

### FR-009 종합 한 줄 (P1)
시스템은 GMP, 승인, 회수 대조를 합쳐 칸 맨 위에 확인할 점을 한 목록으로 보여야 한다.
- 수용 기준
  1. **결과** 목록에는 심각한 것부터: 승인 로트 회수됨(위험), GMP 유효기간 지남(위험), GMP 갱신 확인 필요(주의), 회수 공지 참고(안내)
  2. **결과** 위험·주의가 하나라도 있으면 "QA 확인 필요"로 시작하고 "자동 판정이 아니라 확인하라는 표시입니다"를 붙인다
  3. **결과** 항목마다 글자 + 아이콘 + 색 배지와 근거 한 줄(날짜·제조번호)을 보인다 (색만으로 구분하지 않음)
  4. **결과** 위험·주의가 없으면 배지 없이 GMP 근거 한 줄과 안내만 보인다

### FR-010 세 곳 업체명 대조 (P1)
시스템은 허가정보(제품 업체), 국가출하승인, GMP 세 곳의 업체명이 서로 같은지 표로 보여야 한다. [사용자 요청: 두 API로 복합 인사이트]
- 수용 기준
  1. **결과** 표는 "허가정보 ↔ 국가출하승인", "허가정보 ↔ GMP", "국가출하승인 ↔ GMP" 세 줄이고, 줄마다 같음(✓)·비슷함(≈)·다름(✗)·확인 불가(–)를 글자와 기호와 색으로 보인다
  2. **결과** 비슷함이나 다름이 하나라도 있으면 맨 위 목록에 "업체명 확인 필요"(안내)를 더한다. 위험·주의가 아니라서 이것만으로 "QA 확인 필요"가 되지는 않는다
  3. **결과** 같은 제품명인데 업체가 다른 승인 이력은 승인 목록에서는 빼지만(FR-003), 표에서 그 건수와 업체명(최대 2곳)을 말한다. 같은 업체 승인이 하나도 없으면 "다름"
  4. **결과** 승인이나 GMP를 못 찾으면 해당 줄은 "확인 불가"이고 확인 필요로 세지 않는다
  5. **결과** "국가출하승인 ↔ GMP"는 가장 최근 승인의 업체와 GMP 업체를 비교한다. 같은 회사인지는 사람이 확인한다 (수입사·위탁 제조일 수 있음)

### FR-011 계획된 생산과 GMP 유효기간 대조 (P1)
시스템은 이 제품의 진행 전·진행 중 작업지시(초안·발행·진행 중)의 계획 기간을 GMP 유효기간과 비교해, 생산 중에 GMP가 끝나는 작업지시를 알려야 한다. [사용자 선택: 공개 규제 정보와 가상 생산일정을 제품 기준으로 엮음]
- 수용 기준
  1. **결과** 계획 시작일에 이미 GMP가 지났으면 "위험", 계획 기간 안에 끝나면 "위험", 계획 종료일 뒤 90일 이내에 끝나면 "주의", 그보다 길면 "GMP 유효기간 안"이다 [Q11]
  2. **결과** 위험·주의가 있으면 맨 위 목록에 "계획된 생산 N건이 GMP 유효기간과 맞지 않음"과 작업지시 번호·날짜 근거를 보인다
  3. **결과** GMP를 찾지 못하면 대조하지 못했다고 말하고, 대조할 작업지시가 없으면 그렇게 말한다 (이상이 없다는 뜻이 아님)
  4. **결과** 완료·취소된 작업지시는 대조하지 않는다. 작업지시는 이 앱의 가상(교육용) 자료이고 GMP만 실제 공개 정보라는 표시를 같이 보인다
  5. **결과** 작업지시를 읽지 못해도 승인·GMP·회수 칸은 그대로 보인다 (읽기만 하고 저장하지 않는다)

### FR-012 승인 추이와 승인 로트 유효기간 (P2)
시스템은 찾은 승인 이력으로 마지막 승인 이후 경과일, 평균 승인 간격, 유효기간이 지났거나 90일 안인 승인 로트 수를 보여야 한다.
- 수용 기준
  1. **결과** "승인 N건 · 마지막 승인 YYYY-MM-DD(N일 전) · 평균 간격 약 N일 · 유효기간 지남 N건 · 90일 이내 N건"을 조회한 범위 안의 값이라는 말과 함께 보인다
  2. **결과** 마지막 승인 이후 경과일이 평균 간격의 2배를 넘으면 맨 위 목록에 "승인 공백 가능성"(안내)을 더한다 [Q12]
  3. **결과** 승인이 2건 미만이면 평균 간격은 "-"이고 공백 판단을 하지 않는다

### FR-013 GMP 전체 보기 (P2)
시스템은 같은·비슷한 업체의 GMP 적합판정서를 한 줄(가장 늦은 유효기간)만이 아니라 전체 표로 보여야 한다.
- 수용 기준
  1. **결과** 표는 업체명·공장 소재지·완제/원료·제형군·유효기간·남은 기간이고 유효기간 늦은 순이다
  2. **결과** 다른 업체 줄은 넣지 않고, 비슷한 이름 줄에는 "같은 회사인지 확인 필요"를 붙인다

### 경계·예외 상황
- 업체명이 비었거나 제품에 업체명이 없으면 GMP를 부르지 않고 안내한다.
- GMP가 여러 줄이면 유효기간이 가장 늦은 줄을 쓴다. 날짜 형식이 아니면 그 줄은 뺀다.
- 승인 결과일시·유효기간이 날짜 형식이 아니면 그 칸은 "-"로 둔다.
- API 하나만 실패하면 그 칸만 실패 안내를 보이고 다른 칸은 정상으로 보인다. 둘 다 실패해도 제품 상세의 다른 탭은 정상이다.
- 하루 호출: 카드를 열 때 GMP 1회 + 승인 최대 3회(쪽 수) = 4회. 각 10,000건/일이라 한도는 문제없다고 가정한다 [Q7].

### 핵심 자료
- 저장하지 않는다. 화면을 열 때마다 서버 함수로 부르고, 마지막 정상 결과만 브라우저에 보관한다 (PRD "공공데이터 대량 복사 금지", spec 006).
- 사용 기록(`usage_log`)에는 호출 이름(`gmp`, `shipment`)·성공 여부·걸린 시간만 남는다 (spec 003 FR-008).

## 4. 성공 기준

### 완료 확인
- 시험 자료 모드에서 GMP 6가지·승인 2가지가 기대한 글자와 배지로 보인다.
- 업체명 같음·비슷함·다름 세 가지가 시험으로 가려진다.
- 실제 키로 첫 호출을 해서 `resultCode 00`과 실제 항목 이름이 문서와 같은지 확인한다 (유○○, Q9).

### 효과 지표
- 제품 하나에서 "승인 이력 + GMP 남은 일수"를 확인하는 데 식약처 사이트를 따로 열지 않아도 된다 (가설, 시연 2~3명 관찰).

## 5. 제외 범위
- 국가출하승인이나 GMP 적합 여부를 이 앱이 정하거나 보증하는 것
- 공급사 자동 부적격 처리 (PRD 하지 않을 것)
- 가상 로트·가상 제품과 이어 붙이기 (실제 등록 제품에만 표시)
- 해외 GMP(FDA 점검, EudraGMDP 등), Federal Register 규제 변경 공지
- 응답을 DB에 저장하거나 오래된 기록 쌓기
- 승인·GMP 변동 알림 자동 발송(주기 점검)
