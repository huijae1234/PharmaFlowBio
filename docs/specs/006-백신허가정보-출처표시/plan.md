## 0. 요약
spec 006의 FR-001~003을 3단계로 만든다. 데이터베이스는 바꾸지 않는다. 1단계에서 허가정보 함수(`api/permit.js`)가 품목 구분(PRDUCT_TYPE)을 돌려주고 "백신만" 조건이면 백신류만 걸러 보내게 하고, 순수 함수(백신 판별·출처 글자·보관 열쇠)와 시험을 만든다. 2단계에서 제품 등록 창에 "백신만"과 품목 구분 칸을, 3단계에서 공공데이터 칸 공통 조각(`public-panel.js`)에 출처·조회 시각과 마지막 정상 결과(브라우저에만, D10)를 붙인다. 새 라이브러리는 없다.

## 2. 구조와 파일

### 폴더 트리
```text
PharmaFlow/
├── api/
│   └── permit.js                  (수정) PRDUCT_TYPE 칸 더하기, vaccine=1이면 백신류만 (최대 10건)
├── src/
│   ├── domain/
│   │   └── public-data-rules.js   (수정) isVaccineItem, permitRow에 품목 구분, sourceText(조회 시각), publicCacheKey
│   ├── infrastructure/
│   │   └── public-cache.js        (신규) 마지막 정상 결과 읽기·쓰기 (localStorage, 실패해도 조용히 없음으로)
│   └── ui/
│       ├── public-panel.js        (수정) 성공하면 결과 + 출처·조회 시각(+ cacheKey가 있으면 보관), 실패하면 안내·다시 시도 + 마지막 정상 결과
│       ├── home-sections.js       (수정) 최근 회수 공지 칸에 cacheKey
│       └── pages/
│           ├── product-modals.js  (수정) "백신만"(처음 켬), 품목 구분 칸, 백신 결과 없음 문구, 출처 (보관 안 함, Q39)
│           └── product-public.js  (수정) 허가정보·회수 칸 cacheKey, "시험 규격·국가출하승인 정보로 쓰지 않습니다" 안내
├── styles/
│   └── public.css                 (수정) 출처 줄, 마지막 정상 결과 표시
└── tests/
    ├── public-data-rules.test.js  (수정) 백신 판별·품목 구분·출처 글자·보관 열쇠
    └── public-data-api.test.js    (수정) permit 함수 백신 거르기(가짜 응답)
```

## 5. 제약과 주의점

### 보안
- 인증키는 `api/` 함수와 `.env`·Vercel 환경변수에만. 브라우저 저장소에는 공공데이터 결과(items)와 시각만 넣는다. 로그인 토큰은 넣지 않는다.
- 공공데이터 글자도 사람 입력과 같이 textContent로만 그린다(지금과 같음).

### 성능
- vaccine=1 조회는 100건을 받아 거르므로 응답이 조금 커질 수 있다. 15초 제한은 그대로. 실제 호출 시간을 사용 기록으로 확인한다.

### 호환성
- localStorage가 막힌 브라우저(사생활 모드 등): 마지막 결과 없이 지금처럼 동작.

### 지금 돌아가는 기능 깨지 않기
- vaccine 조건이 없을 때 permit 함수 결과는 지금과 같다 (제품 상세 허가정보 탭은 vaccine 없이 부른다).
- 칸별 불러오는 중·실패·다시 시도, 사용 기록 남기기, 로그인한 사람만 호출.

### 경계
- 항상 할 것: 시험 먼저, 단계 끝마다 함수 시험과 qa.md 기록, 출처 주석, api 파일을 고치면 로컬 서버 다시 켜기.
- 먼저 물을 것: 실제 제품 등록(자료가 늘어남), 새 라이브러리, 데이터베이스 변경, 커밋·push·PR·배포.
- 절대 하지 말 것: spec 5절 제외 범위(공공데이터 DB 저장, 국가출하승인 조회, 허가정보로 시험 규격 채우기, 회수 공지 백신 거르기, 쪽 넘김, MSDS 앱 안 검색), 인증키를 화면·저장소·로그·응답에 넣기, 시험 지우기로 실패 숨기기.
