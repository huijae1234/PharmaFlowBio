## DN-01 알림 함이 대시보드 카드 밑으로 깔림
> 김희재도 병합 뒤 같은 증상을 직접 겪었다고 보고했다. 같은 사건인지는 미확인이며 [DN-09](#dn-09-알림창이-대시보드-뒤에-가려져-보이지-않음)에 코드 재확인을 적었다.
- **재현 방법**(커밋 메시지 기준): PR #22(UI 개편)가 병합된 `main`을 열고 로그인한 뒤 대시보드에서 위쪽 줄의 알림 함을 연다. 알림 함이 대시보드 카드 밑에 깔려 일부가 가려졌다.
- **원인**: 새 디자인(`styles/glass.css`)에서 위쪽 줄에 층 순서(`z-index`)가 없었고, 알림 함 바탕이 반투명이라 뒤 글자가 비쳤다. (카드의 흐림 효과가 각자 새 층을 만들어 위로 올라온 것은 코드를 보고 한 추정이다.)
- **고친 법**: `.topbar`에 `position: relative; z-index: 30;`, `.inbox-panel` 바탕을 불투명 흰색으로. 5줄. 커밋 `4f525e6`(PR #23).
- **확인**: 화면으로 확인했다고 커밋에 적혀 있지는 않다. 이 문서를 쓰며 다시 열어 보지는 못했다.
- **다음부터**: 화면 개편을 합칠 때 위쪽 줄·알림 함·모달처럼 겹쳐 뜨는 것을 한 번씩 열어 본다.

## DN-02 폐기 사유 검사가 잠긴 로트 검사보다 먼저 걸림
- **재현 방법**: 검토가 끝났거나 출하 완료로 잠긴 로트에 `decide_release`를 폐기 + 사유 없음으로 부르면, 잠긴 로트라는 이유 대신 "폐기 사유를 적어 주세요."가 먼저 나온다. (코드 순서에서 읽은 것이고, 커밋에는 "main 병합 때 순서 바꿈"이라고만 있다.)
- **원인**: UI 개편 브랜치의 폐기 사유 기능(0035)을 `main`에 합치며, 기존 잠긴 로트 검사(`lock_editable_batch`)와 새 사유 검사의 순서가 바뀌었다.
- **고친 법**: 잠금 확인을 사유 검사보다 앞으로 옮기고, `supabase/tests/002_rules.sql`에 폐기 사유 경우 3개를 더했다. 커밋 `30a8be4`.
- **확인**: 커밋 제목이 "main 병합 후 DB 시험"이라 DB 시험을 돌린 것으로 보이나, 통과 개수는 이 문서를 쓴 환경에서 확인하지 못했다.
- **다음부터**: 검사가 여러 개 있는 DB 함수를 합칠 때 검사 순서를 시험으로 고정한다(위 시험이 그 역할).

## DN-08 공정 탭 이름이 다르고 공정값을 입력할 수 없었음 (김희재 보고 · **원인·재현·수정 미확인**)
**사용자가 겪은 현상(김희재가 병합 뒤 직접 보고한 것):** 공정 관련 탭의 이름이 어떤 곳은 "공정 단계", 어떤 곳은 "공정 순서"로 달랐고, 공정값을 입력할 수 없었다. 어느 계정·로트·화면에서, 언제 겪었는지는 보고에 없다.

**2026-10-29에 코드·기록에서 확인한 것 (보고와 별개로 내가 확인한 사실)**
- **"공정 순서"라는 화면 글자는 `src/` 안에도 `git log -S` 이력에도 없다.** 문서에서만 나온다(`docs/MES-확장-설계.md`, `docs/data-structure.md`, `docs/specs/011-…`). 보고한 "공정 순서"가 어느 화면의 글자인지는 찾지 못했다(미확인).
- **같은 탭이 로트에 따라 두 이름으로 보인다.** 로트 상세의 탭 하나(`tab=process`)가 작업지시로 만든 단계 로트에는 "공정 단계", 아닌 로트에는 "공정 조건"으로 표시된다(`src/ui/pages/batch-detail.js` 34행과 110행). 다른 곳에는 "공정 단계 흐름"(공정 단계 화면 제목), "제조공정 홈", "최근 이탈 (공정)", 제품 상세의 "공정 단계"·"공정 조건" 칸이 있다. IA 문서(`docs/IA.md` 52행)에는 이 탭이 "공정 조건"으로만 적혀 있어 단계 로트의 "공정 단계" 이름이 문서에 없다.
- **단계 로트에서는 위쪽 "공정 조건 입력" 단추가 보이지 않는다**(`batch-detail.js` 139행, spec 011 FR-008 "단계 로트는 공정 단계 탭에서"). 단계 로트의 공정값은 공정 단계 탭에서 단계를 **착수**(라인 클리어런스 4가지 체크)한 뒤 **완료** 창에서 넣는다(`process-step-modals.js`). 그 단계에 이어진 공정 기준이 없으면 완료 창에는 값 칸 없이 설비 상태만 나온다(57행).

**원인:** **확정하지 못했다.** 위 세 가지(탭 이름이 두 개, 단계 로트의 단추 숨김, 기준이 이어지지 않은 단계는 값 칸 없음)는 "입력할 수 없다"고 느낄 수 있는 **후보**이지만 보고한 사례가 이 중 어느 것인지, 아니면 다른 문제인지는 모른다. 탭 이름 차이가 입력 불가의 직접 원인이라는 증거는 없다(이름은 표시일 뿐 입력 단추의 보이기는 단계 로트 여부로 정해진다).

**재현 절차:** 확인하지 못했다. 로그인이 필요한 화면이라 이 환경에서 재현하지 못했다. 같은 로트의 정상 흐름(공정 5/5 단계 완료)은 김희재가 올린 캡처 `1.png`·`4.png`(WO-2611-004, "공정 5/5 단계 완료")에 보이지만, 처음 보고한 실패를 재현한 것은 아니다([캡처 색인](../assets/captures/README.md)).

**수정 내용·관련 커밋:** 이 오류를 고친 커밋을 `git log`에서 찾지 못했다. 관련 있는 변경은 UI 개편 두 개(`07fd30c`·`4ab3d66`: 공정 단계 카드 정렬·"전체 N단계 중 M번째" 표기)와 AI 도우미 안내서에 생산 업무 절차를 더한 `56fd53c`(도우미가 "공정 조건은 어디서 입력해?"에 답함, `src/ui/assistant-views.js`)이며, 이 둘은 이름 문제나 입력 문제를 고친 것이 아니라 표기·안내를 바꾼 것이다. **코드는 이번에 고치지 않았다**(재현 없이 화면 규칙을 바꾸면 spec 011 FR-008과 어긋날 수 있음).

**수정 후 확인 결과:** 해당 없음(수정하지 않음).

**마감(2026-10-29, 김희재):** 재현 캡처는 찍지 못했고 이 기록으로 끝낸다. 원인은 위 후보 중 무엇인지 확정하지 않은 채 남긴다.

## DN-09 알림창이 대시보드 뒤에 가려져 보이지 않음 (김희재 보고 · DN-01과 같은 증상)
**사용자가 겪은 현상(김희재가 병합 뒤 직접 보고한 것):** 알림창이 대시보드 뒤쪽에 가려져 보이지 않았다. 언제·어느 계정·어느 화면인지는 보고에 없다.

**DN-01과의 관계:** 증상이 [DN-01](#dn-01-알림-함이-대시보드-카드-밑으로-깔림)과 같다. 김희재가 겪은 것이 DN-01로 기록된 그 사건(PR #22 병합 뒤)인지, 그 뒤에 다시 생긴 일인지는 **확인하지 못했다.** 이 항목은 "사용자가 직접 겪었다는 사실"과 "내가 코드에서 다시 확인한 것"을 DN-01에 더하는 것이다.

**원인 (2026-10-29에 코드와 실제 브라우저 CSS로 확인)**
- 위쪽 줄(`.topbar`)에 흐림 효과(`backdrop-filter`)가 걸려 있어 위쪽 줄이 **혼자 층 하나를 만든다**. 층 순서(`z-index`)가 없던 때는 그 층이 본문의 나머지 반투명 카드와 같은 순서로 그려져, 위쪽 줄 안의 알림 함(`position: fixed`, `z-index: 20`)이 뒤에 오는 카드 밑으로 깔렸다.
- 확인 방법: 로컬 서버(`localhost:5195`)에서 이 저장소의 실제 CSS(`tokens.css`~`glass.css`)를 불러온 페이지에 위쪽 줄·알림 함·반투명 카드 4장을 같은 클래스로 만들어 놓고, 알림 함 자리의 맨 위 요소를 `elementFromPoint`로 조회했다(1280×800).
  - 현재 CSS(`.topbar { position: relative; z-index: 30 }` 포함): 맨 위 요소 = **알림 함** (위·아래 두 지점 모두).
  - `.topbar`의 `position`·`z-index`만 뺀 상태: 맨 위 요소 = **`panel`(대시보드 카드)** → 알림 함이 카드 밑에 깔린 모습이 재현됨.
- 이 확인의 한계: 로그인한 실제 앱 화면이 아니라 **같은 CSS를 쓴 최소한의 모형 페이지**다. 실제 알림 함을 열어 본 화면 캡처는 아직 없다.

**수정 내용·관련 커밋:** 커밋 `4f525e6`(2026-10-28 17:49, PR #23 `fix-inbox-layer`)이 `styles/glass.css`에 `.topbar { position: relative; z-index: 30 }`와 `.inbox-panel { background: var(--color-surface) }`(불투명 바탕)를 더했다(5줄). 이 두 규칙은 2026-10-29 현재 `main`(`94ed746`)과 `checklist`의 `styles/glass.css`에 남아 있다. 이후 `glass.css`를 바꾼 커밋(`07fd30c`·`4ab3d66`, 윤○○ 계정)도 이 규칙을 지우지 않았다.

**수정 후 확인 결과:** 위 CSS 확인에서는 해결됨. **실제 화면에서 알림 함을 연 확인은 미확인**이다(김희재가 올린 캡처 9장에는 알림 함이 열린 화면이 없다). 김희재가 수정 뒤에도 같은 현상을 겪었는지는 보고에 없다.
