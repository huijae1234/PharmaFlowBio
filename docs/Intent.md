## 1. 문제 (Problem)
- 가상 백신 제조사에서 이탈 원인, 품질 영향 평가, 후속 조치, 승인 이력이 시험 기록·생산 기록·메일·엑셀에 흩어져, 한 로트의 이탈이 어디까지 처리됐고 누가 무엇을 근거로 승인했는지 한 번에 볼 수 없다. 내부 출하 검토 직전에 놓치기 쉽다(가설). [문제정의 v2 SCQA-C] [UJ CUJ-01 6단계]
- 이탈이 메일·전화로 전달되어 누락·지연이 생긴다. 반대로 관리기준 이탈까지 보류하면 출하가 불필요하게 막힌다. [UJ CUJ-01 2단계 MOT] [PRD §2]
- 영향 평가서를 워드에 옮겨 적고 메일로 주고받아, 평가 승인과 출하 승인이 섞여 "특채"로 오해될 위험이 있다. [UJ CUJ-01 3·4단계] [UJ 에러 E8]
- 근거(30분, 주 10건)는 모두 가설이다. [문제정의 v2 확인 필요] [PRD §8 가정] (2026-10-28 갱신: 인터뷰 5명으로 30분은 환경별 15분~3~4시간으로 바뀌었고 "주 10건"은 근거가 없다. 문제정의 v2.1, PRD v0.4)

## 2. 기대 결과 (Proposed outcome)
- 로트 상세 한 화면에서 열린 품질 이슈(종류별), 영향 평가 상태, 조치 상태, 판정 근거(적용 기준과 버전), 다음에 할 일, 업무 이력을 보고 1분 안에 내부 출하 검토를 한다(현재 약 30분, 가설). [문제정의 v2 확인할 것 하나] [PRD §3 KPI] [PRD FR-36] [IA BT_010200_PG]
- 시험값을 저장하면 시험 규격과 사내 관리기준으로 세 단계 판정(정상·관리기준 이탈·규격 이탈)을 하고, 이탈이면 품질 이슈가 열린다. 규격 이탈만 자동 보류한다. 판정에 쓴 기준과 버전이 측정값과 함께 남는다. [PRD FR-08, FR-27~29] [ERD measurement] [UJ CUJ-01 2단계]
- 품질 이슈는 품질 영향 평가 → QA 검토(승인·반려·보완 요청) → 후속 조치 → 이슈 종료 → 내부 출하 검토로 추적된다. 이슈 종류별 닫기 조건을 지킨다. [PRD FR-30~32] [ERD quality_issue 닫기 조건]
- 열린 이슈가 있으면 출하 가능을 고를 수 없고(DB도 거부), 영향 평가 승인만으로 출하되지 않으며, 화면에 "국가출하승인이 아님"을 밝힌다. [PRD FR-15, FR-33] [UJ 에러 E8]
- 백신 허가정보를 "백신만" 거르기로 찾고, 공공데이터에 출처·조회 시각과 마지막 정상 결과(이 기기에만)를 보인다. [PRD FR-35] [전환 D10]
- 기존 기능(로그인·역할, 조치 요청·승인, 업무 이력, 공공데이터, 사용 기록, 되돌리기)은 그대로 동작한다. [spec 001~003] [전환 D11]
- 발표 전 시연 2~3명이 CUJ-01을 도움 없이 완주한다. [PRD §3 KPI]
- 범위: Must FR-27~36(Bio 핵심) 먼저, Should FR-37(영향 평가 상세)·FR-38(품질 현황 조회), Could FR-39(공급사 반복 이탈)는 뒤에서부터 뺀다. [PRD §9] [문제정의 v2 우선순위]

## 3. 영향 범위 (Affected users and systems)
- **사용자:** QA 관리자(핵심), QC 시험 담당자, 생산 담당자, 열람자. 인허가·공급 담당자는 새 역할 없이 읽기 전용 화면으로. [문제정의 v2 네 칸-누가] [PRD §4] [전환 D4]
- **화면:** 44개(유지·변경·신규). 신규: 품질 영향 평가 작성·검토 `QI_010105_MD`·`QI_010106_MD`, 품질 현황 `RG_010000_PG`·`RG_010100_TB`(#/status), 공급사 `SP_*`(선택). 변경: 로트 화면(`BT_*`, 화면 이름 "로트"), 내부 출하 검토 `BT_010208_MD`, 제품 등록 `PD_010100_MD`(백신만). [IA v2 표·상태 라벨]
- **자료:** 기존 11개 표에 더해 specification.alert_min_value·alert_max_value·version, measurement.result `out_of_alert`·applied_alert_*·applied_spec_version, quality_issue.kind, 새 표 deviation_review. 선택: supplier, material_lot, batch_material, supplier_review_request. 표·필드 이름은 그대로(batch 등). [ERD v0.7] [전환 D3·D5·D7]
- **DB:** Supabase pharmaflow(서울). 바뀌는 것은 마이그레이션 0012~로 **더하기만** 하고 기존 자료를 지우지 않는다. 세 단계 판정·닫기 조건·출하 막기는 DB 함수에서 강제한다. [전환 D6·D8·D11] [ERD 권한 요약]
- **배포:** https://pharmaflow-iota.vercel.app (Vercel, GitHub dbdpfla98/PharmaFlow). Phase마다 브랜치 → PR → 병합. [CLAUDE.md 전역 규칙과 다른 점] [전환 D2]
- **외부 시스템:** Supabase, Google OAuth, Vercel 함수(`api/permit`·`api/recall`), 공공데이터 허가정보(백신 품목 구분 [06310]백신류)·회수·판매중지. MSDS는 공단 사이트 링크만. [ADR 0001·0002] [전환 D13]
- **코드:** 기능 001·002 완료, 003 개발 끝(MSDS 링크만). Bio 전환으로 바뀔 곳: `src/domain/batch-rules.js`·`action-rules.js`·`release-rules.js`(판정·닫기·출하 막는 이유), 로트 상세·품질 이슈 상세 화면, 화면 문구(배치→로트, 출하 판정→내부 출하 검토). [CLAUDE.md 현재 코드] [전환 영향분석 §2]

## 4. 제약 (Constraints)
- **기한:** 2026-10-27(화) 발표. 혼자서도 끝낼 수 있는 범위. [문제정의 v2 기한]
- **스택:** 빌드 없는 HTML/CSS/JS, Supabase 무료 + supabase-js CDN, Vercel 함수(icn1)로 공공데이터 대신 호출. 새 라이브러리 없음. [CLAUDE.md 스택] [ADR 0001·0002]
- **비밀 값:** 공공데이터 인증키·Supabase service 키는 `.env`와 Vercel 환경변수에만. 화면·GitHub에 노출하지 않는다. [CLAUDE.md 스택] [전환 요청 금지 사항]
- **자료 보존:** 개발·마이그레이션은 기존 자료를 지우거나 초기화하지 않는다. 되돌리기는 QA 관리자가 직접 누를 때만. [전환 D11]
- **권한:** 버튼 숨김만으로 끝내지 않고 DB 함수·RLS로 막는다. 영향 평가 승인·반려·보완 요청은 QA 관리자만. 업무 이력은 고치기·지우기 불가. [ADR 0002] [ERD 권한 요약] [PRD FR-31]
- **판정 규칙:** 경계값은 범위 안. 관리기준이 없으면 두 단계. 같은 입력에 둘이 섞이면 규격 이탈. 재시험이 또 이탈해도 같은 이슈(관리기준 → 규격 이탈이면 종류를 올림). 설비 상태 "이상"은 규격 이탈. [PRD FR-27~29] [ERD quality_issue.kind]
- **로트 상태:** 규격 이탈·직접 보류 → 보류. 관리기준 이탈은 보류 안 함. 열린 규격 이탈 이슈가 모두 닫히면 보류 → 시험 중. 출하 가능·폐기는 내부 출하 검토로만, 열린 이슈(종류 상관없이)가 있으면 출하 가능 불가. [ERD batch 로트 상태 규칙] [전환 D6]
- **하지 않을 것:** 실제 회사·로트 자료, 실제 법정 규격처럼 보이는 가상 규격, 규격 미달 로트를 버튼 하나로 특채·출하 승인, 국가출하승인 흉내, 공급사 자동 부적격 처리, 알림 발송, 결재 연동·전자서명, 아이디·비밀번호 가입, 공공데이터 대량 복사, 실험 조건별 결과 비교(FR-26). [PRD §9] [CLAUDE.md 하지 않을 것] [전환 요청 금지 사항]
- **공공데이터:** DB에 저장하지 않고 열 때마다 부른다. 마지막 정상 결과는 브라우저에만. 실패해도 핵심 흐름은 끝까지 된다. 허가정보를 로트 시험 규격으로 쓰지 않는다. [PRD FR-20, FR-35] [전환 D10]
- **개인정보:** 사용 기록에 이메일 대신 사용자 ID만. [PRD §8 개인정보]
- **디자인:** ant 스타일, Pretendard, 토큰은 `styles/tokens.css`, 상태는 색과 글자를 함께(정상·관리기준 이탈·규격 이탈). [CLAUDE.md 디자인] [rules/design.md 5]
