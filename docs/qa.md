| QA-1029-D | 계획 수량 1000 | U-11(역가 80·엔도톡신 10.01), U-13(조치 요청), U-19(출하 막힘) | 관리기준 이탈 + 규격 이탈, **보류** |

로트번호는 **작업지시 작성 때가 아니라 착수(U-06) 때** 넣는다(작성 창에는 로트번호 칸이 없다). 착수 창에 예정 로트번호(제품 약자 형식)가 미리 들어 있으니 지우고 `QA-1029-A~D`를 넣는다. 작업지시는 메모 칸에 같은 이름을 적어 구분한다.

## 6. Fail 기록 형식
이번 실행에서는 **Fail이 없다**. 앞으로 Fail이 나오면 시트 "이슈" 칸과 아래 형식으로 남긴다: QA 항목(번호·시나리오·현재 Fail) / As-Is(실제로 한 조작과 반응) / 오류 근거(콘솔·네트워크 오류, 캡처. 없으면 "없음") / To-Be(요구사항상 기대 동작) / 수정·재시험(내용·커밋·재시험 결과·사람이 다시 볼 단계). 404·홈 이동 같은 오류는 실제로 본 경우에만 적는다.

## 7. 이 QA로 알 수 없는 것
- 사람이 처음부터 끝까지 수행한 직접 QA는 아직 0건이다. 오늘 확인은 모두 **부분 확인**이다.
- 로그인 후 쓰기 흐름(작성·발행·착수·시험값·출하)의 새로고침 유지, DB 쪽 중복·동시 처리 막기, DB 시험 SQL.
- 이 세션은 실제 Claude·공공 API·슬랙을 부르지 않았다. 실제 호출 결과(CQ-26~28)는 다른 세션의 기록이다.
- "경계값 Pass"는 시험 자료 기대값과 JS 판정식이 맞았다는 뜻이다. DB 판정 결과는 2026-10-28 `019_rules.sql` 통과 기록에 의존한다.
