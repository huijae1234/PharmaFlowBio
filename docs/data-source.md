# 공공데이터 출처와 처리 기준

- 작성·공식 안내 확인일: 2026-10-28
- 목적: 프로젝트 2 안내문 15번의 출처 카드. API 이름·선택 이유·받는 항목·단위·기준 시각·빈 값·이용 조건과 확인 상태를 기록한다.
- 문서 기준: `main`(이 문서가 `checklist`에서 쓰인 뒤 2026-10-29 `docs-submission`으로 합쳐짐). 기능 구현 상태와 실제 응답 확인 상태는 구분한다.
- 회사·로트·시험값·규격·검체는 교육용 가상 업무 자료다. 아래 네 API는 식약처의 실제 공개 정보다. 가상 자료와 실제 공개 자료를 같은 로트의 사실로 연결하지 않는다.

**2026-10-29 갱신:** 두 API는 `main`에 들어갔다(PR #24~#26, `api/gmp.js`·`api/shipment.js`). 실제 키로 두 API 모두 `resultCode 00`을 받았고, 배포 화면에서 GMP 칸이 실제 자료(지씨플루주 GMP 2029-11-30까지 등)로 보였다. 국가출하승인은 배포에서 한 번 실패해 "마지막 정상 조회" 상자가 나온 기록이 있다(근거 [qa 021](specs/021-공개규제현황-국가출하승인-GMP/qa.md) H-02·실패와 조치). 아래 문단은 처음 쓸 때의 상태다.

신규 두 API는 공식 명세와 추가 중인 코드를 확인한 상태다. 환경변수 설정은 사용자에게 전달받았으며 키 값·Vercel 설정 화면은 열람하지 않았다. 설정 전달을 실제 호출 성공으로 기록하지 않는다.

## 3. API별 출처 카드

### D-01 의약품 제품 허가정보

- 공식 출처: [공공데이터포털 15095677](https://www.data.go.kr/data/15095677/openapi.do)
- 앱 요청 경로: [`api/permit.js`](../api/permit.js). 품목명으로 검색한다. 백신만 선택하면 응답의 품목 구분에서 백신류를 골라 보여 준다.
- 받는 항목·단위: 품목기준코드 `ITEM_SEQ`는 식별 문자열, 품목명 `ITEM_NAME`·업체명 `ENTP_NAME`·주성분 `ITEM_INGR_NAME`·전문/일반 `SPCLTY_PBLC`·상태 `CANCEL_NAME`·품목 구분 `PRDUCT_TYPE`은 글자다. 성분명만으로 함량 단위를 추정하지 않는다.
- 기준 날짜: 허가일 `ITEM_PERMIT_DATE`는 원문 `YYYYMMDD`를 화면에서 `YYYY-MM-DD`로 표시한다. 공공데이터를 받은 시각은 별도 표시한다.
- 현재 조회 범위: 일반 검색은 한 쪽 10건. 백신만 검색은 한 쪽 100건 안에서 골라 최대 10건을 표시한다. 넓은 검색어에서는 전체에 백신이 있어도 앞 100건에 없으면 검색 결과가 없을 수 있다.
- 빈 값: 결과 0건은 검색 결과 없음으로, 상세의 대응 품목이 없으면 허가정보를 찾을 수 없다는 안내로 표시한다. 비어 있는 개별 칸은 `-`이며 숫자 0으로 바꾸지 않는다.
- 사용 한계: 이 제품의 공개 허가정보이지, 사내 시험 규격이나 가상 로트의 국가출하승인 증거가 아니다. 코드로 재사용하는 항목 이름은 기존 실제 응답과 [기능 006 QA](specs/006-백신허가정보-출처표시/qa.md)를 근거로 한다.

### D-02 의약품 회수·판매중지 정보

- 공식 출처: [공공데이터포털 15059114](https://www.data.go.kr/data/15059114/openapi.do)
- 앱 요청 경로: [`api/recall.js`](../api/recall.js). 제품 상세에서는 품목명으로 받은 결과 중 품목기준코드가 같은 공지만 고른다. 홈에서는 최근 공지를 요청한다.
- 받는 항목·단위: 품목기준코드 `ITEM_SEQ`·제조번호 `MNFCTUR_NO`는 식별 문자열, 품목명 `PRDUCT`·업체명 `ENTRPS`·회수 사유 `RTRVL_RESN`은 글자, 목록 건수는 건이다.
- 기준 날짜: 회수명령일 `RECALL_COMMAND_DATE`를 화면에서 `YYYY-MM-DD`로 표시한다. 조회 시각과 회수명령일은 구분한다.
- 현재 조회 범위: 제품명 조회는 한 쪽 최대 100건. 요청한 범위 안에서 코드 일치·날짜순으로 정리하므로 전체 과거 이력을 빠짐없이 조회했다고 보증하지 않는다.
- 빈 값: 일치하는 공지가 없으면 회수·판매중지 공지가 없다는 문구를 표시한다. API 실패를 공지 없음으로 표시하지 않는다. 개별 값이 비면 미제공 상태로 취급한다.
- 사용 한계: 조회된 공개 공지는 참고 자료다. 공지가 없다는 결과만으로 해당 제품의 안전이나 내부 출하 가능 여부를 판단하지 않는다. 기존 정상·실패 확인은 [기능 003 QA](specs/003-공공데이터-MSDS-사용기록/qa.md), [기능 006 QA](specs/006-백신허가정보-출처표시/qa.md)에 있다.

### D-03 의약품 GMP 적합판정서 발급현황

- 공식 출처: [공공데이터포털 15097207](https://www.data.go.kr/data/15097207/openapi.do). GMP는 의약품 제조 및 품질관리기준을 뜻한다.
- 명세상 조회: 업체명 `BSSH_NM`으로 검색할 수 있다. 추가 중인 서버 함수 이름은 `api/gmp.js`다.
- 명세상 받는 항목·단위: 업체명 `BSSH_NM`, 공장소재지 `FCTR_ADDR`, 완제/원료 구분 `KGMP_BGMP_NAME`, 제형군/제조방법 `GMP_INGR_MM_GROUP_NAME`은 글자다. 유효기간 `VLD_PRD_YMD`는 날짜이며 공식 예시는 `YYYY-MM-DD`다. 남은 일수를 계산한다면 단위는 일이고 앱이 계산한 값임을 구분한다.
- 기준 시각: 유효기간과 앱의 조회 시각을 별도로 적는다. 실제 응답을 아직 받지 못했으므로 실제 날짜 표기·응답 구조는 확인 대기다.
- 빈 값 처리 기준: 결과 0건은 해당 업체명으로 찾지 못한 것으로 안내한다. 업체명 차이·누락 가능성이 있으므로 ‘GMP 부적합’으로 바꾸지 않는다. 날짜 누락·해석 실패 때는 만료 여부나 남은 일수를 계산하지 않는다.
- 사용 한계: 업체명이 비슷하다는 이유만으로 같은 제조소라고 확정할 수 없다. 업체·주소·제형군을 함께 확인해야 하며, 이 정보로 가상 로트의 품질이나 출하를 승인하지 않는다.
- 검증 상태: 공식 항목과 개발 코드 확인. 실제 키 승인·정상 응답·0건·실패·배포 화면은 미확인이다.

### D-04 감염병백신 국가출하승인정보

- 공식 출처: [공공데이터포털 15084883](https://www.data.go.kr/data/15084883/openapi.do)
- 명세상 조회: 접수번호 `RCPT_PRCS_NO`와 페이지 조건을 지원한다. 제품명 검색 변수는 공식 표에 없다. 인증키 변수 이름은 이 API에서 `ServiceKey`로 표기돼 있다. 추가 중인 서버 함수 이름은 `api/shipment.js`다.
- 명세상 받는 항목·단위: 접수번호·제조번호 `MNFT_NO`는 식별 문자열, 검체형식 `SPCM_FORM_LIMS_PRDLST_NM`·제품명 `PRDLST_NM`·제조수입업자 `MNFT_SALPS_NM`·검정규격코드명 `PROVT_UNIT`은 글자다. `PROVT_UNIT`을 임의의 수량이나 시험값으로 바꾸지 않는다.
- 기준 날짜: 결과일시 `RESULT_TIME`·유효기간 `VLD_PRD`의 공식 예시는 `YYYYMMDD`다. 실제 형식·시간대는 실제 응답 확인 대기이며, 앱의 조회 시각과 구분한다.
- 추가 코드의 조회 범위: 앞 3쪽·쪽당 100건을 받아 제품명으로 고르는 방식이다. 최대 300건 안에서 찾는 것이며, API 원문의 최신순 정렬 보장은 확인하지 못했다. 최종 반영 시 범위를 재확인한다.
- 빈 값 처리 기준: 조회 범위 안에 없다는 결과와 API 실패를 구분한다. 결과 없음은 ‘국가출하 미승인’이 아니며, 날짜가 비면 `-`로 표시하고 추정하지 않는다.
- 사용 한계: 제조수입업자가 실제 제조소와 다를 수 있다. GMP와 연결할 때 같은 업체인지 확인해야 한다. 앱의 내부 출하 검토 및 교육용 가상 로트와 구분한다.
- 검증 상태: 공식 항목과 개발 코드 확인. 실제 응답·배포 화면은 미확인이다.

## 4. 세 가지 결과와 기준 시각

로딩은 응답 전 상태다. 응답 뒤에는 아래 세 가지를 구분한다. 기존 D-01·02의 구현은 [`public-panel.js`](../src/ui/public-panel.js), [`public-data-rules.js`](../src/domain/public-data-rules.js)에 있다. 신규 D-03·04는 아래 기준을 적용할 예정이며 실제 화면 확인은 남아 있다.

| 경우 | 표시·처리 기준 | 확인 근거 |
|---|---|---|
| 읽음 | 받은 값, 식약처 출처, 이번 조회에서 응답을 받은 날짜·시각을 표시 | D-01·02 배포 화면 및 기능 006 QA |
| 내용 없음 | API 호출이 성공했지만 결과가 없으면 검색 결과/공지/해당 조회 범위에 자료가 없다고 표시. 0건을 API 실패나 규제 부적합으로 바꾸지 않음 | 기능 003·006 QA, 시험 모드의 0건 자료 |
| 못 읽음 | 실패 안내와 다시 시도. 이전 정상 결과가 이 기기에 있으면 과거 조회 시각과 ‘지금 결과가 아닐 수 있음’을 함께 표시. 없으면 과거 값을 만들지 않음 | 기능 006 QA C-06 |

- `조회 시각`은 브라우저가 응답을 받은 시각이다. 개별 자료의 기준 날짜는 위 카드의 허가일·회수명령일·결과일시·유효기간이며, 제공기관의 최종 수정 시각은 별도로 받지 못하면 알 수 없다.
- 공통 서버 함수는 로그인 확인 뒤 키를 붙여 요청하고 15초가 넘으면 실패 처리한다. 정상·오류·시간 초과를 구분하며 키나 외부 오류 원문을 사용자에게 노출하지 않는다. 설계 근거는 [ADR 0001](adr/0001-vercel-함수로-공공데이터-대신-호출.md)이다.
- 공개 응답은 DB에 대량 복사하지 않는다. 제품 등록 때 선택한 제품 정보만 업무 자료로 저장하고, 마지막 정상 조회는 브라우저에만 보관한다. 사용 기록에는 호출 종류·성공 여부·걸린 시간을 남긴다.
- `PUBLIC_DATA_MODE=fixtures`는 로컬 시험용이다. 시험 자료 표시와 출처를 붙이고, 실제 마지막 정상 결과를 덮어쓰지 않는다. 시험 자료 성공을 실제 API 성공으로 세지 않는다. 근거: [시험 자료·결과](test-data.md), [기능 019 QA](specs/019-시험자료-시험모드/qa.md).

## 5. 선택하지 않은 대안

| 후보 | 이번에 선택하지 않은 이유·상태 |
|---|---|
| MSDS API 직접 연결 | 현재 앱은 산업안전보건공단 MSDS 사이트 링크를 제공한다. API로 조회했다고 기록하지 않는다. 기존 범위 축소는 기능 003 기록 참조 |
| 의약품 행정처분 API | 이번 확인에서는 이 앱에 연결할 공식 의약품 API를 확인하지 못했다. 식품 분야 API를 의약품 처분 자료로 대체하지 않는다. GMP 적합판정서는 행정처분 기록과 구분한다 |
| 국가출하승인 API만으로 내부 출하 판단 | 공개된 실제 제품 기록과 교육용 가상 로트가 다르므로 내부 품질 판단을 대신할 근거로 선택하지 않았다. 공개 정보 참고 목적으로만 포함한다 |
