# 평가표용 PRD 요약 (01-prd)

확인일 2026-10-29. 기준: `origin/main` `94ed746`(PR #30)에 `checklist`·`qa-list` 문서를 합친 상태(브랜치 `docs-submission`). 처음 작성은 `7d06523` 기준이었고, AI 기능(PR #28·#29)·작업지시 로트 이름 정리(PR #30)·시험 개수를 이번에 맞췄다. 이 파일은 평가자가 한 번에 읽도록 [PRD.md](PRD.md)(v0.11)·[interview.md](interview.md)·[data-source.md](data-source.md)의 핵심만 모은 것이다. 원문과 근거는 링크로 연결하고, 숫자와 주장을 새로 만들지 않았다.

> **먼저 알아 둘 것:** 이 문서의 숫자(15분~3~4시간, 연 1~3회 등)는 **AI 페르소나 5명이 설정한 값**이다. 실제 현장 조사 결과가 아니라 **가정**이다. 실제 사람 한 명에게 같은 질문지로 물어 확인하는 일은 아직 하지 않았다([interview.md](interview.md) 10·11절).

## 1. 무엇을 만드나
가상 백신 제조사 "PharmaFlow Bio"의 **QA 관리자**가 시험·생산·평가서·메일·엑셀을 따로 뒤지지 않고, 로트 하나의 품질 이탈이 **이탈 근거 → 품질 영향 평가 → 후속 조치 → 이슈 종결**까지 어디까지 처리됐고 누가 무엇을 근거로 승인했는지를 한 화면에서 보고 내부 출하 검토를 하게 하는 웹 앱이다. 국가출하승인을 대신하지 않는다. 회사·로트·시험값·규격은 모두 교육용 가상 자료이고, 허가·회수·GMP·국가출하승인만 식약처 공개 자료다([PRD 1절](PRD.md)).

## 2. 문제 문장 (인터뷰 후, 최종)
> **QA 관리자(출하 판정 담당)**는 **로트 출하 서명 직전에 상태를 확인할 때**, 열린 일탈·변경 건과 시험·기록 상태가 시스템·엑셀·폴더에 나뉘어 있고 사람이 따로 입력·전달해야 최신이 되기 때문에 **로트당 15분~3~4시간을 들여 맞춰 보고, 서명 직전에야 열린 건을 알게 되는 일을 연 1~3회 겪는다.** 지금은 시스템별 개별 조회 + 개인 엑셀·대장 + 담당자 메신저·메일 문의로 버틴다.

- 근거: 인터뷰 패턴 P1(4명)·P2(3명)·P7(5명). 인터뷰 전 문장과의 차이: [interview.md 9절](interview.md), 문제 순위: 8절.
- 인터뷰 전에 세웠던 "확인에 약 30분" 가설은 인터뷰에서 맞지 않아 15분(MES·LIMS·eQMS를 갖춘 대형사)~3~4시간(종이·엑셀 중소사)으로 바꿨다([PRD 2절](PRD.md)).
- 손해는 시간과 지연뿐이다. 돈을 잃은 사람은 0명, 실제 오출하·사고는 0건이다.

## 3. 인터뷰 패턴과 문제 정의의 연결
인터뷰는 AI가 입은 페르소나 5명(문지아·서하은·한서윤·오태민·강동혁)에게 질문지(애시 모리아 방식) 21~22개를 물은 것이다. **질문한 사람은 파일에 이름이 없어 "8조"로만 기록**되어 있다([interview.md 3절](interview.md)). 두 명 이상이 말한 패턴만 문제 정의에 썼다.

| 패턴 | 요약 | 말한 사람 수 | 문제 문장·앱과의 연결 |
|---|---|---|---|
| P1 | 서명 직전 상태를 맞추려고 여러 곳을 오감 | 4 | 문제 문장의 "시스템·엑셀·폴더에 나뉘어 있음". 앱: 로트 상세 한 화면 |
| P2 | 열린 일탈·변경 건을 서명 직전에야 앎 | 3 | 문제 문장의 "서명 직전에야 앎". 앱: 열린 이슈가 있으면 출하 가능 선택이 막히고, 로트 상세에서 열린 이슈 수가 먼저 보임(FR-15) |
| P3 | 종결·진행 상태가 안 전달돼 기다리고 물으러 다님 | 5 | 앱: 슬랙·앱 알림(FR-41·42), 승인 대기 목록 |
| P4 | "언제 되나" 문의·독촉 응대 | 4 | 앱: 읽기 전용으로 로트 상태 열람(인허가·공급 역할) |
| P5 | 양식에 값을 옮겨 적다 반려·보완이 오감 | 2 | 앱: 시험값 입력 한 곳에서 판정·이슈·평가가 이어짐 |
| P6 | 점검·실사 때 승인 근거를 메일·폴더에서 뒤짐 | 2 | 앱: 업무 이력(누가·언제·무엇을·바뀌기 전후, 고칠 수 없음, FR-16) |
| P7 | 기록·대장·공유표를 바꿔 봤지만 실패(상대가 입력 안 함) | 5 | 문제 문장의 "사람이 따로 입력·전달해야 최신이 됨". 앱: 일하는 행동이 곧 기록이 되게 함 |

한 명만 말한 것은 패턴이 아니라서 따로 두었다([interview.md 5절](interview.md)). 패턴 표의 칸(반복된 행동·불편·지금의 대안·빈도·잃는 시간·근거가 된 말)은 원문을 그대로 두었으니 거기서 읽는다.

## 4. 5 Whys (세 방향, 각 5번)
`[인터뷰]`는 `docs/interviews/` 원문에서 확인한 것, `[가설]`은 팀의 추론이다. 전문은 [PRD 2-2절](PRD.md).

| 방향 | 마지막 "왜"의 답 | 확인 정도 |
|---|---|---|
| ① 시간이 왜 드나 | 시스템은 두고 한 로트의 상태만 한곳에 모아 보여 주는 중간 수단이 없다 | 1~4번 `[인터뷰]`, 5번 `[가설]` |
| ② 왜 서명 직전에야 아나 | 열린 건 확인이 서명 절차에 걸려 있지 않고 사람의 점검에 달려 있다 | 1~3번 `[인터뷰]`, 4·5번 `[가설]` |
| ③ 해 본 시도가 왜 실패했나 | 일을 끝내는 행동(시험 완료·서명)과 상태를 갱신하는 행동이 따로라 갱신이 빠진다 | 1~4번 `[인터뷰]`, 5번 `[가설]` |

세 줄을 합친 뿌리: 일을 하면 상태가 한곳에 저절로 쌓이는 구조가 아니라, 사람이 따로 입력·전달해야 최신이 된다. 앱은 일하는 행동이 곧 기록이 되게 한다. **`[가설]` 칸은 실제 사람에게 확인하지 않았다.**

## 5. 목표와 성공 지표
- **목표 하나:** QA 관리자가 한 로트의 열린 이슈·영향 평가·조치·승인 이력과 판정 근거를 한 화면에서 보고, 놓친 것 없이 1분 안에 내부 출하 검토를 한다.
- 지표: 로트 상세 진입 → 내부 출하 검토까지 시간(현재값 15분~3~4시간은 가정, 목표 1분), 이탈 → 이슈 생성까지 시간(메일 전달 → 저장과 동시에 자동), 시연 참가자 3명 중 3명 완주.
- **측정 상태:** 목표값 1분은 **실제로 측정하지 않았다.** 시연 참가자 3명의 완주 관찰 기록은 문서를 검색해도 찾지 못했다(목표 문장만 [PRD 3절](PRD.md)·Intent에 있음). 실제 시간 단축은 측정하지 않았다([03-data-or-automation.md 4절](03-data-or-automation.md)).

## 9. 하지 않을 것 (요약)
실제 회사 자료 사용, 규격 이탈 로트의 QA 버튼 하나 특채·출하 승인, 국가출하승인·법적 적합 결정, 메일·문자·푸시 알림(슬랙 개인 메시지만 허용), 전자서명, 아이디·비밀번호 가입, 공공데이터 대량 복사. 전체 목록은 [PRD 9절](PRD.md).
