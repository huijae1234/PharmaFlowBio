## Moment of Truth
- **2. 이탈 감지:** 자동으로 이슈를 열지 않으면 As-Is처럼 메일로 알리다 누락이 생긴다. 반대로 관리기준 이탈까지 보류하면 출하가 불필요하게 막혀 앱을 우회하게 된다. 규격 이탈만 자동 보류하고, 판정에 쓴 기준과 버전을 남겨야 나중에 근거를 설명할 수 있다.
- **6. 내부 출하 검토:** 문제정의의 "확인할 것 하나"다. 열린 품질 이슈, 영향 평가 상태, 조치 상태, 판정 근거, 업무 이력이 로트 상세 한 화면에 없으면 1분 목표를 이룰 수 없다. 열린 이슈가 있는데도 출하 가능을 누를 수 있거나, 영향 평가 승인만으로 출하가 풀리면 앱을 믿을 수 없다.

## As-Is → To-Be
| 구간 | As-Is (가정) | To-Be |
|---|---|---|
| 이탈 전달 | 메일·전화로 QA에 알림, 빠뜨리기 쉬움 | 저장 즉시 세 단계 판정, 품질 이슈 자동 생성, 규격 이탈은 자동 보류 |
| 영향 평가 | 워드 양식에 근거를 옮겨 적고 메일 첨부 | 이슈 상세에서 작성, 근거 자료 자동 표시, QA가 승인·반려·보완 요청 |
| 승인 | 메일함에서 요청 찾고 회신 | 승인 대기 목록에서 영향 평가와 조치 요청을 함께 처리 |
| 출하 전 확인 | 시험·생산 기록, 평가서, 메일, 엑셀을 따로 확인 (15분~3~4시간, 인터뷰 가정, 감정 최저점) | 로트 상세 한 화면 (1분 안) |

## 여정 명세 (개발·테스트 기준)

### 전제 조건
- 가상 백신 제품에 시험 항목(예: 역가)의 시험 규격과 사내 관리기준이 등록돼 있다 (교육용 가상 값, spec 004에서 정함).
- 로트는 시험 중이고 열린 품질 이슈가 없다.
- QC 시험 담당자, QA 관리자 역할을 가진 구글 계정이 로그인할 수 있다 (한 계정만 있으면 QA 관리자가 모든 단계를 할 수 있다).
- 데스크톱과 휴대폰 폭(375px) 모두에서 된다.

### 1단계: 시험값 입력 (BT_010206_MD)
- **사용자 행동:** 품질시험 홈 → 시험값을 기다리는 로트 → 로트 상세 → 시험값 입력 → 저장
- **시스템 반응:** 시험 규격과 사내 관리기준(있으면)을 입력 칸 옆에 보여 준다.
- **성공 기준:**
  - [ ] 시험 규격·사내 관리기준과 "교육용 가상 기준" 표시가 입력 칸 옆에 보인다
  - [ ] 숫자가 아니거나 비어 있으면 저장하지 않고 이유를 보여 준다
  - [ ] 저장이 끝나기 전에 같은 값이 두 번 저장되지 않는다

### 2단계: 이탈 감지 (BT_010202_TB) ★MOT
- **시스템 반응:** 판정을 글자와 색으로 표시한다(정상·관리기준 이탈·규격 이탈). 관리기준 이탈이면 품질 이슈(종류: 관리기준 이탈)만 연다. 규격 이탈이면 품질 이슈(종류: 규격 이탈)를 열고 로트를 보류한다. 판정에 쓴 규격·관리기준·기준 버전을 측정값과 함께 남긴다.
- **성공 기준:**
  - [ ] 경계값은 범위 안(정상 또는 관리기준 이탈)으로 판정한다
  - [ ] 관리기준이 없는 항목은 정상/규격 이탈 두 가지로만 판정한다
  - [ ] 이탈이면 품질 이슈가 정확히 1개 생긴다
  - [ ] 규격 이탈일 때만 로트 상태 배지가 "보류"로 바뀐다

### 3단계: 품질 영향 평가 (QI_010105_MD)
- **사용자 행동:** 품질 이슈 상세 → 품질 영향 평가 작성 → 이탈 내용·추정 원인·품질 영향·제안 후속 조치·근거 입력 → 검토 요청
- **성공 기준:**
  - [ ] 로트, 발생 일시, 시험 항목, 측정값, 적용 기준과 버전이 자동으로 보인다
  - [ ] 필수 칸이 비면 검토 요청을 보내지 않는다
  - [ ] 상태가 "검토 요청"으로 보이고 업무 이력에 남는다

### 4단계: QA 검토 (QI_010106_MD, QI_010102_MD)
- **사용자 행동:** QA 관리자가 승인 대기에서 영향 평가를 승인(또는 반려·보완 요청 + 사유), 재시험 조치 요청을 승인 + 담당자 배정
- **성공 기준:**
  - [ ] QA 관리자가 아닌 사람에게는 검토·승인 버튼이 없고, 데이터베이스도 거부한다
  - [ ] 반려·보완 요청 사유가 비면 저장되지 않는다
  - [ ] 승인 모달에 "사용·출하 승인이 아닙니다"가 보인다
  - [ ] 보완 요청이면 요청자가 같은 평가를 고쳐 다시 제출할 수 있다

### 5단계: 조치 결과와 이슈 종료 (QI_010104_MD)
- **사용자 행동:** 배정된 담당자가 재시험 측정값 입력 → 정상이면 이슈 닫기
- **성공 기준:**
  - [ ] 재이탈이어도 새 품질 이슈가 생기지 않는다
  - [ ] 규격 이탈 이슈는 승인된 영향 평가와 완료된 조치가 있어야 닫힌다. 아니면 이유를 글로 보여 준다
  - [ ] 마지막 규격 이탈 이슈를 닫으면 로트가 보류 → 시험 중

### 6단계: 내부 출하 검토 (BT_010208_MD) ★MOT
- **사용자 행동:** QA 관리자가 로트 상세 위쪽 요약을 확인 → 내부 출하 검토 → "출하 가능"
- **성공 기준:**
  - [ ] 열린 품질 이슈(종류별), 영향 평가 상태, 조치 요청 상태, 다음에 할 일, 최근 업무 이력이 탭을 누르지 않아도 위쪽에 보인다
  - [ ] 열린 이슈가 1건이라도 있으면 "출하 가능"을 고를 수 없고 이유를 글로 보여 준다
  - [ ] 영향 평가 승인만으로는 출하 가능이 풀리지 않는다
  - [ ] 창에 "회사 내부 검토이며 국가출하승인이 아닙니다"가 보인다
  - [ ] 검토 후 로트 상태가 "출하 가능"으로 바뀌고 업무 이력에 남는다

## 에러 시나리오
- E1~E8은 `../edge-cases/에러-복구.md`에 있다 (저장 실패, 권한 없음, 반려 후 재제출, 공공데이터 호출 실패, 동시 수정, 관리기준 이탈, 영향 평가 보완 요청, 특채 시도).

## 추적 지표
- 로트 상세 진입 → 내부 출하 검토까지 시간 (목표 1분 안)
- 이탈 → 품질 이슈 생성까지 시간 (목표 0초, 자동)
- 이슈 생성 → 영향 평가 검토 요청 → QA 결정까지 시간
- 위 시간은 업무 이력의 시각으로 계산할 수 있다. 화면 이동 시각은 사용 기록에 남는다.

## E2E 테스트
- qa.md의 사람 QA 항목(H-번호)과 Claude의 브라우저 확인(C-번호)으로 대신한다. 판정 규칙(경계값, 세 단계, 관리기준 없음, 재이탈, 닫기 조건, 출하 잠금)은 `node:test` 함수 시험과 DB 시험으로 확인한다.
