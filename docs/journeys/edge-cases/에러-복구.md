# 에러 복구 경로

- 근거: CUJ-01~03 (v2), docs/adr/0001, docs/adr/0002, `~/.claude/rules/code.md` 오류 처리
- 화면에 보이는 오류 문구는 "무엇이 안 됐는지 + 사용자가 할 일"로 쓴다.

### E1: 저장 실패 (인터넷 끊김, Supabase 응답 없음)
- **발생 조건:** 시험값·공정 조건·조치 요청 등을 저장하는 중에 연결이 끊긴다.
- **사용자가 보는 것:** 모달이 닫히지 않고 입력값이 그대로 남는다. "저장하지 못했습니다. 인터넷 연결을 확인한 뒤 다시 저장해 주세요."
- **복구 경로:** 같은 모달에서 다시 저장한다. 성공 전에는 품질 이슈나 업무 이력이 반쯤만 생기지 않는다.
- **검증 방법:** 브라우저 개발 도구로 오프라인 상태를 만든 뒤 저장 (C-번호로 qa.md에 등록)

### E2: 권한 없음
- **발생 조건:** 역할에 없는 동작을 하려 한다 (예: 생산 담당자가 주소를 직접 바꿔 승인 요청을 보냄). 또는 열람자가 입력 화면에 들어온다.
- **사용자가 보는 것:** "이 작업은 QA 관리자만 할 수 있습니다." 자료는 바뀌지 않는다.
- **복구 경로:** 자기 첫 화면으로 돌아가는 버튼을 누른다.
- **검증 방법:** 역할별 계정으로 데이터베이스에 직접 쓰기를 시도해 거부되는지 확인한다.

### E3: 반려 후 재제출
- **발생 조건:** QA 관리자가 조치 요청을 반려한다.
- **사용자가 보는 것:** 요청자의 첫 화면과 품질 이슈 상세에 "반려됨 — 사유: …"가 보인다.
- **복구 경로:** 요청자가 내용을 고쳐 다시 제출한다. 반려와 재제출이 모두 업무 이력에 남는다.
- **검증 방법:** CUJ-01 4단계를 반려로 진행 (H-번호)

### E4: 공공데이터 호출 실패
- **발생 조건:** 공공데이터 API가 느리거나, 해외 요청을 막거나, 트래픽 한도를 넘는다.
- **사용자가 보는 것:** 그 칸에만 "허가정보를 불러오지 못했습니다. 잠시 뒤 다시 시도해 주세요." 이 기기에서 전에 정상 조회한 결과가 있으면 "마지막 정상 조회 {시각}"과 함께 보여 준다(전환 D10). 화면의 다른 부분(기준, 품질 이슈)은 정상으로 보인다.
- **복구 경로:** 다시 시도 버튼을 누른다. 핵심 흐름(CUJ-01)은 공공데이터 없이도 끝까지 된다.
- **검증 방법:** 함수의 인증키를 비운 상태로 호출해 본다. 실패는 사용 기록에 남는다.

### E5: 같은 자료를 두 사람이 동시에 바꿈
- **발생 조건:** QA 관리자 두 명이 같은 조치 요청을 거의 동시에 승인·반려한다.
- **사용자가 보는 것:** 나중에 누른 사람에게 "다른 사람이 먼저 처리했습니다. 화면을 새로 고칩니다."를 보여 주고 최신 상태를 띄운다.
- **복구 경로:** 새로 고친 화면에서 다시 판단한다.
- **검증 방법:** 브라우저 두 개로 같은 요청을 처리해 본다. (가정 — 발표 범위에서 꼭 필요한지 PRD에서 정함)

### E6: 관리기준 이탈 (v2)
- **발생 조건:** 측정값이 시험 규격 안이지만 사내 관리기준을 벗어난다.
- **사용자가 보는 것:** 판정 "관리기준 이탈"(글자 + 색). 품질 이슈(종류: 관리기준 이탈)가 열리지만 로트는 보류되지 않는다. 이슈 상세의 다음에 할 일은 "품질 영향 평가 작성".
- **복구 경로:** 영향 평가를 작성하고 QA가 승인하면 이슈를 닫을 수 있다. 열려 있는 동안은 내부 출하 검토에서 출하 가능을 고를 수 없다(전환 D6·D8).
- **검증 방법:** 관리기준 경계 바로 밖 값을 넣어 본다 (DB 시험 004, C-번호)

### E7: 품질 영향 평가 보완 요청 (v2)
- **발생 조건:** QA 관리자가 영향 평가의 근거가 부족하다고 본다.
- **사용자가 보는 것:** 요청자의 첫 화면과 품질 이슈 상세에 "보완 요청 — 사유: …"가 보인다.
- **복구 경로:** 요청자가 같은 평가를 고쳐 다시 검토 요청한다. 보완 요청과 재요청이 모두 업무 이력에 남는다.
- **검증 방법:** CUJ-01 4단계를 보완 요청으로 진행

### E8: 영향 평가 승인만으로 출하하려 함 (특채 시도, v2)
- **발생 조건:** 규격 이탈 이슈의 영향 평가가 승인됐지만 조치가 끝나지 않았거나 마지막 측정값이 규격 이탈인 상태에서 출하 가능을 고르려 한다.
- **사용자가 보는 것:** 출하 가능이 잠겨 있고 이유가 글로 보인다("열린 품질 이슈가 1건 있어 출하할 수 없습니다." 등). 데이터베이스에 직접 시도해도 거부된다.
- **복구 경로:** 조치(재시험 등)를 끝내고 이슈를 닫거나, 폐기로 정한다.
- **검증 방법:** DB 시험 004에서 영향 평가 승인 뒤 출하 가능 시도
