# 판단 규칙과 데이터 세 경우 (03-data-or-automation)

확인일 2026-10-29, 기준 `origin/main` `94ed746`(PR #30). **판정과 출하 막기는 규칙이고, Claude API는 그 위에 "읽기 쉬운 정리"를 얹는 별도 칸으로 `main`에 들어와 있다**(PR #28, spec 022~026). 1~5절은 규칙표(안내문의 "규칙만 쓰면 규칙표" 형식), 6절은 AI 칸이다. 어느 쪽도 판정·승인·출하를 AI가 정하지 않는다. 규칙마다 화면에 보이는 근거와, 알 수 없는 것(한계)을 함께 적는다.

## 2. 이 규칙의 한계 (판단이 알지 못하는 것)
- **기준값이 맞는지는 모른다.** 규칙은 사람이 입력한 규격·관리기준을 그대로 믿는다. 기준 자체가 틀렸으면 판정도 틀린다.
- **시험값이 맞는지는 모른다.** 입력한 값이 숫자인지, 칸이 비지 않았는지만 검사한다. 측정 오류나 거짓 입력은 못 잡는다.
- **"정상"은 출하해도 안전하다는 뜻이 아니다.** 정상은 입력한 기준 안이라는 뜻일 뿐이고, 출하 판단은 사람(QA 관리자)이 한다. 평가 승인과 출하 승인도 별개다.
- **가상 자료다.** 로트·제품·기준·검체는 교육용 가상 자료이고 실제 회사·배치 자료가 아니다.
- **여러 항목의 조합은 보지 않는다.** 항목마다 따로 판정하고, 항목들이 함께 변하는 추세는 계산하지 않는다.
- **공공데이터(허가·회수)는 판정에 쓰지 않는다.** 참고로 보여 줄 뿐이고, 로트의 판정·출하 규칙과 연결하지 않았다.

## 3. 바깥 데이터를 보여 주는 세 경우
허가정보·회수 정보를 서버 함수(`api/permit.js`, `api/recall.js`)로 받아 보여 줄 때 세 경우를 화면에서 구분한다. 자세한 출처와 항목은 [data-source.md](data-source.md).

| 경우 | 화면 표시 | 0이나 거짓 값으로 바꾸지 않는 것 | 시험 자료 |
|---|---|---|---|
| 읽음 | 받은 값과 출처 줄("출처: 식약처 공공데이터 · 조회 시각") | — | `fixtures/public/permit-normal.json`, `recall-normal.json` (test-data.md F-01) |
| 내용 없음 | "검색 결과가 없습니다" 같은 안내. 0건을 실패나 규제 부적합으로 보이지 않음 | 결과 0건 | `fixtures/public/permit-empty.json`, `recall-empty.json` (F-03) |
| 못 읽음 | "허가정보를 불러오지 못했습니다" + 다시 시도. 이 기기에 지난 정상 결과가 있으면 "마지막 정상 조회" 상자로 지난 시각과 함께 표시. 없으면 과거 값을 만들지 않음 | 지난 값을 지금 값처럼 보이기 | `fixtures/broken/public/` (오류 코드·깨진 응답·XML 오류·시간 초과, F-04~F-07) |

시험 모드(`PUBLIC_DATA_MODE=fixtures`)로 키 없이 세 경우를 재현할 수 있다(test-data.md 6절). 제품 등록 검색은 지난 값을 보관하지 않는다.

## 4. 이 데이터로는 알 수 없는 것
- 실제 현장에서 이 규칙이 판정 시간을 몇 분에서 몇 분으로 줄이는지는 **측정하지 않았다.** PRD의 시간 지표는 인터뷰 설정값(가정)이다.
- 공공데이터에 없는 품목이나 아직 반영되지 않은 회수는 알 수 없다. "자료가 없다"는 "문제가 없다"가 아니다.
- 규격·관리기준이 실제 규제 기준과 같은지는 모른다(가상 자료).
- 쌓인 데이터 양(측정값·이슈·요청 건수)의 관리자 화면 캡처는 아직 없다. 팀 DB를 읽을 수 없어 확인하지 못했다.

- **아침 브리핑의 AI 줄(026):** 김희재가 실제 Claude 호출이라고 확인(2026-10-29). 호출 횟수·토큰·비용 기록은 문서에 없다.
- **합계(qa 문서에 적힌 것만):** Claude 실제 호출은 10 + 6 + 3번과 재확인 몇 번이다. 재확인 횟수는 문서에 없다.
- **spec 022~024는 실제 호출 기록이 없다.** 문서에 "키가 없어 미확인"으로 적혀 있다. 키가 생긴 시점과 022~024도 호출해 봤는지는 알 수 없다.
- **못 한 것:** 실제 호출 결과의 문장 품질을 사람이 평가한 기록, 총 호출 횟수·비용 합계, SC-009(숫자 어긋남 비율)를 큰 표본으로 센 것.

### AI 칸의 알 수 없는 것
- 실제 현장에서 AI 정리가 확인 시간을 줄이는지는 **측정하지 않았다.**
- 문장의 숫자는 검사하지만 **해석이 맞는지**는 알 수 없다. 모든 문장은 사람이 근거 줄을 열어 확인해야 한다.
- 가상 자료만 읽는다. 공공데이터의 회수 사유 같은 자유 글에는 개인정보가 없다고 보지만 모든 경우를 검사하지는 않았다.
- 하루 한도는 서버 메모리라 비용의 확실한 상한이 아니다(spec 022 7절 한계).

## 7. 빈칸
- 쌓인 데이터 양 캡처(받은 값·회원 입력·요청 건수): 관리자 화면 캡처 필요(팀원). 대시보드 캡처 1장은 있으나 건수 비교는 아님.
- AI 칸 실제 호출 결과는 위 6절 표로 모았다. spec 022~024는 실제 호출 기록이 없다.
- AI 칸이 판정·출하 규칙에 영향을 주지 않는다는 점은 spec 문서의 주장이며, 이번에 코드를 읽어 따로 확인하지는 못했다.
