## 네비게이션 모델
- **주 메뉴(왼쪽 사이드바, 휴대폰에서는 위쪽 메뉴 버튼):** 홈(역할별 첫 화면), 로트, 품질 이슈, 제품, 품질 현황(선택), 공급사(선택), 관리. MSDS는 각 홈 아래 링크 (spec 007 FR-002·003·007). 관리는 QA 관리자에게만 보인다.
- **첫 화면 바꾸기:** QA 관리자는 품질시험 홈과 제조공정 홈도 열 수 있다. 다른 역할은 자기 첫 화면만 메뉴에 보인다.
- **유틸리티(오른쪽 위):** 내 이름과 역할 표시, 로그아웃.
- **열람자:** 모든 화면 위에 "역할을 받기 전에는 읽기만 할 수 있습니다. QA 관리자에게 역할을 요청해 주세요." 안내를 띄운다.
- **교육용 가상 표시:** 기준·로트·공급사를 보여 주는 화면에는 "교육용 가상 자료" 표시를, 공공데이터 칸에는 "출처: 식약처 공공데이터 · 조회 시각"을 둔다.

## 화면별 콘텐츠 우선순위
### 로트 상세 (BT_010200_PG)
1. 로트번호, 제품, 로트 상태 배지(글자 + 색)
2. 한 줄 요약: 열린 품질 이슈(규격 이탈 N·관리기준 이탈 N), 품질 영향 평가 상태, 조치 요청 상태, **다음에 할 일**, 최근 업무 이력 3줄
3. 내부 출하 검토 버튼 (QA 관리자만, 막히면 이유를 글로)
4. 탭: 공정 조건 / 시험 결과 / 품질 이슈 / 업무 이력

### 품질 이슈 상세 (QI_010100_PG)
1. 단계 표시줄: 이탈 발생 → 품질 영향 평가 → 후속 조치 → 이슈 종결 → 내부 출하 검토 (지금 단계 강조, 다음에 할 일과 담당)
2. 기준 이탈 내용: 측정값, 판정, 적용한 시험 규격·사내 관리기준·기준 버전
3. 품질 영향 평가: 내용, 상태(검토 요청·승인·반려·보완 요청. 작성 중(임시 저장)은 없음, ERD v0.7·spec 005 Q36), 요청자·검토자·사유
4. 조치 요청과 재시험 결과
5. 업무 이력

### 관리자 대시보드 (HM_010000_PG)
1. 승인 대기(조치 요청 + 품질 영향 평가) 수와 목록
2. 내부 출하 검토 대기 로트(시험 중인데 열린 품질 이슈 없음)
3. 보류 로트
4. KPI 숫자(열린 품질 이슈 수: 규격·관리기준 구분, 이번 주 기준 이탈 수, 평균 처리 일수)
5. 최근 회수 공지 (출처·조회 시각)

### 품질시험 홈 (HM_020000_PG) / 제조공정 홈 (HM_030000_PG)
1. 시험값을 기다리는 로트 / 생산 중 로트
2. 나에게 배정된 조치 (Q23)
3. 보완 요청·반려된 내 요청 (영향 평가 포함)
4. 최근 기준 이탈

### 품질 현황 조회 (RG_010000_PG, 선택)
1. 로트별 내부 품질 상태(보류·검토 중 먼저)
2. 조치 지연(승인 대기·승인됨이 오래된 것)
3. 공급 일정에 영향을 줄 수 있는 열린 규격 이탈
4. 인허가 체크리스트 탭(계산값)

## 유저 플로우
### 시험 이탈부터 내부 출하 검토까지 (지금의 답)
1. QC 시험 담당자가 로그인 → 품질시험 홈 → 시험값을 기다리는 로트 → 로트 상세
2. 시험값 입력 모달에서 측정값 저장 (입력 전에 시험 규격·사내 관리기준이 보임)
   - 두 기준 안이면 → "정상"
   - 관리기준만 벗어나면 → 품질 이슈(종류: 관리기준 이탈)가 열림, 로트는 보류되지 않음
   - 규격을 벗어나면 → 품질 이슈(종류: 규격 이탈)가 열리고 로트가 보류됨
3. 담당자가 품질 이슈 상세 → 품질 영향 평가 작성 → 검토 요청
4. QA 관리자가 승인 대기 → 품질 영향 평가 검토: 승인 / 반려 / 보완 요청(담당자가 고쳐 다시 제출)
5. 담당자가 조치 요청 등록(재시험 등) → QA 관리자 승인(담당자 배정) 또는 반려
6. 배정된 담당자가 조치 결과 입력
   - 정상이면 → 품질 이슈 닫기 (규격 이탈: 승인된 영향 평가 + 완료된 조치 / 관리기준 이탈: 승인된 영향 평가, 전환 D8)
   - 또 이탈이면 → 같은 품질 이슈에 결과가 붙고 이슈는 열린 채 다른 조치
7. 마지막 규격 이탈 이슈가 닫히면 로트가 보류 → 시험 중
8. QA 관리자가 로트 상세에서 내부 출하 검토(출하 가능 / 폐기). 영향 평가 승인만으로는 출하 가능이 풀리지 않는다
9. 모든 단계가 업무 이력에 남는다

### 공정 이탈
1. 생산 담당자가 로그인 → 제조공정 홈 → 로트 상세 → 공정 조건 입력
2. 판정은 시험과 같은 세 단계. 이후는 위 3~9와 같다(조치 종류: 설비 점검 등)

### 처음 로그인한 사람
1. 구글 로그인 → 열람자로 로트 목록에 들어옴, 읽기 전용 안내
2. QA 관리자가 사용자·역할에서 역할을 지정
3. 다음 화면 이동부터 그 역할의 첫 화면과 권한이 적용됨

## 콘텐츠 증가 대응
- 로트·품질 이슈·업무 이력·사용 기록·원료 로트는 계속 늘어난다. 목록은 최근순으로 보여 주고 상태·기간으로 거른다. 한 번에 50개씩 보여 준다.
- 공공데이터 검색 결과는 API의 페이지 나누기(pageNo)를 그대로 쓴다.

## URL 전략
- 빌드 없는 정적 앱이라 주소는 `#/`로 시작하는 해시 주소를 쓴다.
- 상세 화면은 `#/batches/:batchId`처럼 ID를 붙인다(화면 이름이 "로트"로 바뀌어도 주소는 그대로). 탭은 `?tab=` 쿼리.
- 공공데이터를 대신 부르는 함수는 `/api/...` 경로에 둔다(ADR 0001).

## AI 칸 (spec 022·023·024, v2.17)
화면을 새로 만들지 않고 기존 화면에 접힌 칸만 더한다. 보일지는 역할·대상·상태 권한표(`ai-policy-rules.js`)가 정하고 서버가 같은 표를 다시 적용한다.
- HM_010000_PG·HM_020000_PG·HM_030000_PG 각 홈: "지금 할 일" 아래 "업무 찾아보기"(4종 질문, 예시 버튼). QA 홈에는 "오늘 먼저 볼 것"(spec 022)도 있다.
- QI_010100_PG 품질 이슈 상세: 조치 요청 칸의 "AI로 조사 준비"·"조치 이후 확인", 평가서 칸의 "AI로 보완할 점 확인"(작성 창은 작성 지원, 저장된 평가서는 QA 검토 지원).
- PD_010200_PG 제품 상세(QA): 기준 표 아래 "AI로 기준 변경 영향 설명".
- WO_010000_PG 작업지시(생산·QA): 목록 위 "AI로 일정에 영향을 주는 미완료 업무 확인".
- IA.xlsx·ia-screens.json은 갱신하지 않았다(화면 ID·경로 변화 없음).
