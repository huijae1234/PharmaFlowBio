# 기능 파일: UI 개편 (홈·목록·로트 상세·도식)

- 담당: 윤○○
- 상태: 구현·배포됨 (PR #22, 이후 main에 직접 반영). 사람 QA는 아래 6절에 빈칸으로 남겼다
- 관련 문서: [DESIGN.md](../DESIGN.md)(디자인 결정과 이유), [references.md](../references.md)(레퍼런스), `CLAUDE.md`의 "UI 개편" 항목, [spec 020](../specs/020-디자인-클리니컬글라스/spec.md)(팀이 정한 "클리니컬 글라스" 톤)
- 이 파일이 따로 있는 이유: 이 개편은 기능·권한·데이터를 바꾸지 않고 **화면이 일을 알려 주는 방식**을 바꾼 것이라 별도 spec 없이 사용자 피드백으로 진행했다. 그 내용을 여기에 모은다

## 1. 해결하려는 문제

**지금 방식(개편 전):** 홈 화면은 역할마다 카드가 길게 쌓였고, 사용자가 로그인 후 "무엇을 해야 하는지" 알려면 여러 카드를 읽어야 했다.

**막히는 지점 (사용자 말, 2026-10-27):**
- "홈화면이 가장 답답하다. 뭘 해야 하는지 모르겠다. 파악하는 데 시간이 너무 많이 걸린다."
- 홈이 길어 스크롤이 많고, 할 일이 종류별로 흩어져 있고, 지표가 작다.
- 로트 상태 한눈 보기가 어렵고, 처리 중과 종결된 이슈가 섞여 있고, 공정 단계가 도식으로 안 보인다.
- 비교(범위 막대, 같은 제품 로트)를 하려면 화면을 오가야 한다.

## 2. 대상 사용자

모든 역할(열람자, QC 시험 담당자, 생산 담당자, QA 관리자). 홈은 역할마다 다르게 보인다.

## 3. 만든 것과 수용 기준

각 줄은 "이렇게 보이면 된다"이다.

### 3-1. 홈 (`ui/home-widgets.js`, `ui/pages/homes.js`, `domain/home-task-rules.js`)
- [ ] "지금 할 일"이 한 카드에 종류와 상관없이 한 목록으로 나오고, 6건까지만 펼쳐 보이며 나머지는 접힌다.
- [ ] 위쪽에 지표 3개(처리 중 품질 이슈, 이번 주 규격 이탈, 평균 처리 기간)가 카드로 나오고, 숫자를 누르면 해당 목록으로 간다.
- [ ] 사이드바 "홈" 옆에 지금 할 일 건수가 배지로 나온다.
- [ ] 보류 로트가 오래된 순으로 나오고, 정렬(오래된 순·최신 순)과 제품 거르기가 된다. 각 줄에 "지금 누가 풀어야 하는지"(담당)가 나온다.
- [ ] 도식 세 개: 로트 상태 도넛(범례를 누르면 그 상태의 로트 목록), 주별 품질 이슈 막대(누르면 품질 이슈 목록), 이탈이 많은 항목 순위. 모두 **이미 있는 자료로만** 그린다.
- [ ] 회수 공지는 칸 안에서 스크롤되고, 아래에 의약품안전나라 조회 링크가 있다.
- [ ] 넓은 화면에서 윗줄 큰 칸 2개, 아랫줄 칸 4개로 빈칸 없이 채워진다. 좁은 화면은 한 칸씩 쌓인다.

### 3-2. 목록 (`ui/master-detail.js`, `ui/filter-chips.js`)
- [ ] 로트·품질 이슈 목록이 "상태 칩 + 목록 + 미리보기" 구조다.
- [ ] 로트 목록은 로트번호 앞 글자가 아니라 **실제 제품**으로 거른다. 제품 화면에 "로트 이니셜" 패널이 있어 WO(작업지시 번호로 붙인 로트)·QA(시험용) 같은 이니셜의 뜻을 보여 준다.
- [ ] 사용 기록 화면은 맨 위에서 전환할 수 있다. 작업지시 목록은 제품으로 거를 수 있다.

### 3-3. 판단에 필요한 비교를 한 화면에 (`ui/range-bar.js`, `ui/compare-panel.js`, `pages/release-panel.js`)
- [ ] 시험값 범위 막대에서 점에 올리면(휴대폰은 누르면) 로트번호와 값이 보인다.
- [ ] 같은 제품 로트를 한 화면에서 비교한다(전환 단위는 로트번호 앞 글자).
- [ ] 출하 판단 근거 패널이 시험 결과, 열린 이슈, 공정, 보존 검체, 기준 버전을 한 곳에 보여 준다.

### 3-4. 로트 상세 공정 단계 (`pages/process-steps.js`)
- [ ] 넓은 화면에서 각 단계 동그라미 **바로 아래**에 그 단계 내용이 온다. 좁은 화면에서는 세로로 쌓이고 옅은 선으로 이어진다.
- [ ] 단계 번호는 "1/5"가 아니라 "전체 5단계 중 **1번째**"로 쓴다(날짜나 "5단계 중 4단계만 했다"로 읽히지 않게).

### 3-5. 모양 (`styles/tokens.css`, `styles/glass.css`, `styles/charts.css`)
- [ ] 밝고 투명한 톤, 청록 주색 + 라임 포인트(지금 해야 할 것에만).
- [ ] 모서리는 카드 8px, 버튼·입력 6px, 배지 4px.
- [ ] 옆 메뉴 묶음 이름(업무·기준정보·관리)은 눌리는 메뉴와 구분되게 작은 글씨와 들여쓰기로 보인다.
- [ ] 375px 폭에서 가로로 넘치지 않는다.

## 4. 하지 않는 것

- 권한, 데이터베이스, 판정 규칙은 바꾸지 않는다. 판정과 막기는 여전히 DB 함수가 한다.
- 합성 데이터를 새로 만들지 않는다(도식은 있는 자료만 쓴다).
- 문구 통일 15건(용어 7, 설명 보강 8)은 이번에 하지 않았다.
- 폐기 사유 저장은 이 개편의 범위가 아니다(별도 마이그레이션).

## 5. 만드는 과정에서 정한 것 (이유는 DESIGN.md)

| 정한 것 | 이유 |
|---|---|
| 팔레트 A안(백신 청록)을 후보 4개를 같은 화면에 그려 보고 선택 | 사용자가 직접 비교해 고르게 하려고 |
| 배경 빛 번짐을 한 번 진하게 했다가 옅게 되돌림 | 사용자 피드백 |
| 모서리를 16/12px에서 8/6px로 줄임 | "너무 동그랗다" 피드백 |
| 그래프 카드를 옆으로 늘리지 않고 4칸 격자로 | "옆으로 늘려놓은 게 티난다" 피드백 |

## 6. 확인 방법

- 자동 시험: `tests/home-task-rules`, `home-chart-rules`, `hold-sort-rules`, `compare-rules`, `issue-stage-rules`(로트 이니셜·제품 목록 포함), `process-step-rules` 등. main 기준 278개 통과(2026-10-29).
- 화면 확인(작성자 직접): 홈·로트 목록·로트 상세·공정 단계·제품 화면을 1500px와 375px 폭에서 열어 가로 넘침과 "null/undefined" 글자가 없는지 확인했다.
- **사람 QA(작성자가 아닌 사람): 빈칸.** 이 개편을 다른 팀원이 열어 보고 "지금 할 일이 먼저 보이는가"를 확인한 기록이 아직 없다.

## 7. 알려진 한계

- 배포는 Vercel 개인(Hobby) 플랜이라 소유자가 아닌 사람의 커밋은 배포가 막힌다. 소유자가 빈 커밋 하나를 올려야 반영된다.
- 로컬에서는 회수 공지 요청이 실패해 회수 공지 스크롤을 실제 자료로 확인하지 못했다(가짜 자료 12건으로 스크롤 동작만 확인).
