# 문제 인터뷰 가이드 (작성 틀)

- 상태: **빈 틀**. 질문은 팀원이 직접 쓴다. Claude는 질문을 채우지 않았다.
- 방법: Ash Maurya의 Problem Interview. 목적은 해결책 검증이 아니라 **문제가 실제로 있는지, 누가 어떤 상황에서 겪는지, 지금은 어떻게 버티는지** 확인하는 것이다.
- 근거 자료: `docs/research.md` 8절(문제 후보), 9절(인터뷰 대상과 미확인 내용)
- 질문을 다 쓰면 Claude에게 "Ash Maurya 기준으로 검수해줘"라고 따로 요청한다.

## 쓸 때 지킬 것 (작성 원칙)

- 우리 서비스나 해결책을 말하지 않는다.
- "~하면 쓰시겠어요?"처럼 미래를 묻지 않고, **이미 겪은 일**을 묻는다.
- 문제가 있다고 미리 정하고 묻지 않는다. ("불편하시죠?" 대신 그때 무슨 일이 있었는지 묻는다)
- 실제 회사 자료·배치 기록·기밀 문서는 받지 않는다. 경험을 말로 듣는다.
- 답을 들은 뒤 조사자의 가설을 먼저 말하지 않는다.
