# 슬랙 알림은 데이터베이스가 만들고 Vercel 함수가 보낸다

처음에는 메일·메신저·푸시 알림을 모두 "하지 않을 것"으로 두었다(PRD §9). 2026-10-26 사용자 결정으로 슬랙 개인 메시지 알림만 허용한다(spec 009). 메일·문자·푸시는 그대로 하지 않는다.

보내는 구조는 이렇게 정했다.

- 검체 전달, 조치 승인 같은 업무가 저장되면 데이터베이스 트리거가 같은 처리 안에서 `notification` 표에 받는 사람마다 한 줄을 "대기"로 남긴다.
- 화면은 저장에 성공한 뒤 `/api/notify`(Vercel 함수)를 부르고, 결과는 기다리지 않는다.
- 함수는 로그인을 확인한 뒤 그 사람이 일으킨 대기 알림만 가져와 슬랙 Web API로 보낸다. 이메일로 슬랙 사용자를 찾아 개인 메시지를 보내고, 못 찾으면 알림 채널로 보낸다. 결과는 기록에 남긴다.
- 슬랙 봇 토큰은 Vercel 환경변수와 로컬 `.env`에만 둔다(ADR 0001과 같은 방식).

## 검토한 다른 방법
- **화면이 받는 사람을 정해 함수에 넘기기:** 위조나 누락이 생길 수 있고, 업무 함수마다 코드를 붙여야 한다.
- **데이터베이스에서 바로 슬랙 부르기(pg_net):** 토큰을 데이터베이스에 둬야 하고, 시험하기 어렵다.
- **정해진 시각마다 보내기:** 무료 플랜에는 몇 분 간격으로 돌리는 장치가 없다.
- **Incoming Webhook:** 채널 하나에만 보낼 수 있어 개인 메시지가 안 된다.

## 주의할 점
- 화면을 바로 닫아 보내지 못한 알림은 그 사람이 다음에 저장할 때 함께 나간다(spec 009 Q51).
- 알림이 실패해도 업무 저장은 막지 않는다. 트리거는 받는 사람을 찾고 글을 만드는 일만 한다.
- 슬랙 앱 권한은 `chat:write`, `users:read`, `users:read.email` 세 가지만 쓴다.
