# 모든 자료를 Supabase에 두고 구글 로그인과 역할별 권한으로 지킨다

업무 이력과 사용 기록을 관리 페이지에서 모아 보려면 모두가 같은 자료를 봐야 한다. 그래서 배치·시험값·품질 이슈·조치 요청·취급점검 기록·업무 이력·사용 기록을 모두 Supabase에 두고, 처음에 정했던 브라우저 저장(localStorage)은 쓰지 않는다. 사용자는 구글 계정으로 로그인한다. 처음 로그인한 사람은 열람자로 시작하고, QA 관리자가 역할을 지정한다. 권한은 화면에서 버튼을 숨기는 데서 끝내지 않고 Supabase 데이터베이스 규칙(RLS)으로 막는다.

## 검토한 다른 방법
- 이력만 Supabase, 업무 자료는 브라우저: 이력에 나온 배치가 다른 사람 브라우저에만 있어 열어 볼 수 없다.
- 로그인 없이 역할·이름을 고르기: 빠르지만 "누가 승인했나"를 믿을 수 없고, 사용자가 진짜 로그인을 원했다.

## 주의할 점
- 첫 QA 관리자는 개발 중 한 번 직접 지정한다.
- 사용 기록에는 이메일 대신 사용자 ID만 남긴다.
- 구글 로그인용 OAuth 클라이언트는 사용자가 Google Cloud Console에서 직접 만든다.
