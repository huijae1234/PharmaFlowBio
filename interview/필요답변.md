# 인터뷰에서 나와야 할 답변 (PharmaFlow Bio 역산)

프로젝트 방향(PharmaFlow Bio)이 정해져 있어, 제품의 각 판단이 어떤 현장 사실 위에 서야 하는지 거꾸로 뽑은 목록이다. 질문으로 답을 유도하지 않고, 필요한 답이 나오도록 **페르소나의 상황 설정**을 조정했다.

## 1. 완성돼야 하는 문제 문장
> **QA 출하 담당자**는 **로트 출하 판정 직전**, 시험·일탈·평가·조치 기록이 여러 시스템·파일·메일에 흩어져 있어 **열린 이슈를 확인하는 데 [N분·N곳]이 들고, 놓칠 위험**을 진다. 지금은 **시스템별 개별 조회 + 개인 엑셀 + 메일 문의**로 버틴다.

## 2. 나와야 할 답변 13개

| # | 나와야 할 현장 사실 | 받쳐 주는 제품 판단 | 얻어야 하는 형태 |
|---|---|---|---|
| A | 출하 판정 전 상태 확인의 시간·조회 곳 수·인원 | 목표 30분→1분, 로트 상세 요약 | 숫자 + 구체적 장면 |
| B | 이탈을 발견해 QA에 전하는 경로, 전달이 늦거나 빠진 경험 | 값 입력 즉시 자동 판정·이슈 생성 | 지난 한 건의 시간순 서술 |
| C | 열린 이슈를 판정 직전에 알게 된 경험과 빈도 | 열린 이슈가 있으면 출하 가능 잠금 | 사례 1건 + 연간 횟수 |
| D | 규격 이탈과 사내 경보 범위 이탈을 구분하는 방식, 불필요하게 로트가 묶인 경험 | 세 단계 판정, 규격 이탈만 자동 보류 | 현재 방식과 실제 사례 |
| E | 영향 평가를 옮겨 적는 수작업, 반려·보완 왕복 | 평가 화면 자동 채움, 보완 요청 | 오간 횟수와 경로 |
| F | 승인 이력이 흩어져 실사·감사 때 되짚기 힘든 경험 | 수정 불가 업무 이력 | 되짚는 데 든 시간 |
| G | 기준이 바뀐 뒤 예전 판정의 근거를 설명해야 했던 경험 | 기준 버전 | 사례 1건 |
| H | 평가 승인과 출하 승인, 내부 검토와 국가출하승인을 혼동한 상황 | 승인 창 문구, 국가출하승인 미구현 | 혼동 사례 |
| I | 상태를 묻는 연락의 빈도와 응대 시간 | 열람자 역할, "문의 메일 주 10건" 가설 | 주당 횟수, 묻는 사람 |
| J | 도구를 바꾸지 않는 이유 (밸리데이션, 비용, 기존 방식으로 충분) | 이 앱이 선택받을 조건 | 반대 근거 |
| K | 다른 해결책을 써 봤지만 안 된 경험 | 기존 시도가 실패한 이유, 이 앱이 달라야 할 점 | 시도 내용, 결과, 그 이유 |
| L | 끝났는데 끝났다는 처리가 안 돼서 기다리는 상황, 다음 담당·상태를 모르는 상황 | 단계 표시줄, "다음에 할 일과 담당" | 대기한 기간과 영향 |
| M | 부서 간 핑퐁: 샘플 미리 안 뜸, 반납했는데 "너희에게 있다", 위치 불명 | **현재 기능 밖. 범위 확인용** | 빈도와 영향 |

> M은 PharmaFlow Bio에 없는 기능(샘플 위치·반납 추적)이다. M이 크게 나오면 PRD의 "하지 않을 것" 후보나 후속 과제로 적는다. L은 단계 표시줄·다음에 할 일 표시로 일부 받을 수 있다.

## 3. 돌고도는 부서 간 갈등 구조 (페르소나 설정의 공통 틀)
```
생산 ──(샘플 늦게·안 뜸, 서명 누락, 기록 늦게 넘김)──▶ QC
 ▲                                                    │ (결과 늦음, 종결 처리 누락)
 │                                                    ▼
영업·위탁사 ◀──(종료·승인 지연, 열린 건 미공유)── QA
 └──(출하 일정 독촉)──▶ 생산·QA·QC
```
- 각 페르소나는 자기 쪽 잘못도 하나씩 인정한다 (남 탓만 하지 않도록).
- 숫자는 의도적으로 흩어 놓았다 (15분~반나절). 모두 [가상 가정]이다.

## 4. 페르소나별 담당 답변

| 페르소나 | A | B | C | D | E | F | G | H | I | J | K | L | M |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 강동혁 (QC 팀장, 회의적) | | | | | | | | | | ● | ● | ● | ● |
| 한서윤 (대형, 백신 완제 라인) | ● | ● | ● | ● | ● | | | | | ● | ● | ● | |
| 오태민 (중소, 종이·엑셀) | ● | ● | ● | | ● | | | | ● | | ● | | |
| 문지아 (백신 제조사) | ● | | ● | | | ● | ● | ● | | | ● | | |
| 서하은 (수탁, 경력 2년) | | | | | | ● | | | ● | | ● | | |

- 두 명 이상이 말해야 패턴이 되므로 B, E, F는 두 명으로 나눴다. 아직 한 명뿐인 항목: D(한서윤), G·H(문지아), J 일부(강동혁·한서윤은 두 명), L·M(강동혁 중심, L은 한서윤도). G·H·D는 "한 명만 말한 것"으로 분류될 가능성이 크니 필요하면 설정을 한 명 더 추가한다.
- 강동혁의 QC 시점은 L·M을 맡고, 제품 범위 밖 문제(M)를 근거로 도입에 회의적인 역할이다.

## 5. 주의
AI가 연기한 답은 제품 가설의 증거가 아니라 **연습용 시나리오**다. `docs/interview.md` 끝의 "확인할 가정"에 A, C, I의 숫자와 K의 시도 사례를 적고, 가능하면 실제 QA·QC 담당자 한 명에게 같은 질문지로 확인한다.
